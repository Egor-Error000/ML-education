# Сборка и проверка курса

## Локальные примеры проектов

Положите Markdown-файлы в корневую папку `Примеры проектов/`. При сборке они появятся отдельным разделом в HTML-читателе; текст и изображения будут встроены в HTML, а ссылки между Markdown-файлами станут внутренними переходами. Папка исключена из Git, поэтому сборка в чистом клоне просто пропускает этот раздел и не оставляет на странице ссылок на отсутствующие файлы. Добавляйте кодовые фрагменты в Markdown как fenced code blocks.

Учебный текст редактируется в Markdown пяти модулей. `course.json` задаёт главы и маршруты. Авторские сценарии хранятся в `editorial/chapter-scenarios.json`; сборщик не извлекает их из первых абзацев. Для автономной сборки нужен Node.js 20+; marked и KaTeX уже находятся в `vendor/` с лицензиями.

```text
node tools/build_course.cjs
node tools/build_course.cjs --html-only
node tools/build_course.cjs --check
python -X utf8 tools/audit_course.py --output-dir .qa-results
python -X utf8 tools/test_portability.py
python -X utf8 tools/test_worked_examples.py
python -X utf8 tools/test_cv_expansion.py
python -X utf8 tools/check_portable_checkout.py
node tools/check_reader.cjs --output-dir .qa-results/browser
node tools/check_cv_reader.cjs
```

`--check` ничего не записывает и сравнивает содержимое с нормализованными окончаниями строк. Генерация всегда записывает LF; SVG нормализуются также перед встраиванием в HTML. Бинарные изображения встраиваются без изменения.

`--html-only` обновляет только `Читать конспекты.html`, не перезаписывая Markdown-оглавления и планы.

## Расширенный модуль CV

`editorial/cv-expansion.json` описывает 60 глав, девять подразделов, предпосылки, авторские схемы и первичные источники. Тринадцать прежних ID и путей сохранены. Новые главы не объявлены перенесёнными архивными единицами: исходный `coverage.json` продолжает проверять прежний материал отдельно от добавлений.

`draw_cv_expansion_figures.py` воспроизводит 60 поясняющих SVG из этого реестра. Иллюстрации статей хранятся отдельно в `оформление/course/papers/`: для каждого рисунка указаны авторский источник, номер, страница PDF, область обрезки и контрольные суммы. `extract_cv_paper_figures.py --pdf-dir ПАПКА_PDF --output-dir ПАПКА_РИСУНКОВ` повторяет извлечение из тех же байтов PDF; версия renderer может влиять на растеризацию. Схема YOLOv8 от RangeKing сохранена исходным JPEG, с разрешением автора в публикации.

`test_cv_expansion.py` независимо пересчитывает учебные примеры и проверяет состав, маршруты, хэши глав и исходные иллюстрации. `check_cv_reader.cjs` проверяет все CV-маршруты, локальные картинки, увеличение, поиск, автономную перезагрузку и мобильную ширину. Обе проверки дополняют общий аудит; они не закрывают независимую предметную приёмку текста.

Аудит без `--output-dir` печатает результат, не меняя отчёты в репозитории. Он отдельно проверяет сохранность источников, явные целевые диапазоны, ссылки, маршруты и SVG. Статус `passed` относится к техническим проверкам; число незакрытых содержательных проверок возвращается отдельно.

## Карта происхождения

`editorial/coverage.json`, версия 3, содержит исходные единицы и `spans`: путь, строки (с единицы, включительно), SHA-256 и обоснование редакторского изменения. `targets` допускает несколько целей для исходной единицы и общую цель для нескольких исходников. Строки считаются после замены CRLF на LF; внутренние пробелы и пустые строки значимы.

Якоря `u-*` добавляются из сайдкара только в HTML. Служебные обёртки не нужны в учебном Markdown. Карта переноса ведёт к HTML-якорю, а JSON хранит точное место в исходном файле. При несовпадении диапазона сборка останавливается с ID и координатами. Изменение текста требует пересмотра записи, а не массовой перезаписи хэшей.

`edit_chapter.py` помогает применить явную правку с обновлением диапазонов либо заменить главу по указанной редактором карте разделов. Он не объявляет смысловую проверку выполненной.

Архивные манифесты версии 2 сохраняют `original_sha256` и первоначальное число байтов отдельно от проверяемого канонического хэша. Только CRLF заменяется на LF; BOM, пробелы и остальные байты сохраняются. Для бинарных файлов проверяются точные байты.

## Браузер и переносимость

Пакет адаптации/инференса: `test_batch02_examples.py` пересчитывает 34 группы примеров и входит в общий `test_worked_examples.py` (73 проверки). Авторский генератор `draw_batch02_figures.py` использует Pillow и локальный Segoe UI только при перерисовке; обычная автономная сборка использует сохранённые SVG. Проверка подписей: `node tools/check_batch_figures.cjs --production tools/draw_batch02_figures.py --output .qa-results/batch02/figure-bounds.json`. Она не заменяет предметное чтение рисунков.

Браузерная проверка требует Playwright 1.62.1 и Chromium либо установленного Edge. Можно использовать `npm install --no-save --package-lock=false playwright@1.62.1`, затем `npx playwright install chromium`. Эти зависимости нужны для QA, а не для сборки или чтения. `COURSE_NODE_MODULES` позволяет указать отдельное окружение пакетов.

Проверка блокирует HTTP, пишет результаты в `--output-dir` либо временный каталог. Workflow CI настроен для Windows и Linux; факт успешного запуска каждой ОС фиксируется отдельно в приёмке. `check_portable_checkout.py` создаёт локальный временный Git-репозиторий из текущих файлов и отдельный чистый клон, проверяет LF/CRLF, две сборки и отсутствие изменений. Индекс и ветка проекта не меняются; другой ОС эта команда не эмулирует. Сборщик, браузерный отчёт и проверка клона считают SHA-256 одних и тех же байтов HTML с завершающим LF.

Если локальный читатель включает игнорируемые `Примеры проектов/`, проверка сначала выполняет `--check` рабочей редакции, затем пересобирает только читатель временного fixture без этих приватных входов. Проверки LF/CRLF относятся к этому составу клона. Отчёт хранит отдельно `workingHtmlSha256` локального читателя и `htmlSha256` читателя чистого клона, а также число исключённых примеров; рабочие файлы примеров не меняются.

Исторические скрипты — в [`archive/rebuild-tooling/`](../archive/rebuild-tooling/README.md). Их повторный запуск не является способом редактирования текущей редакции. `draw_revision_figures.py` строит авторские SVG по слоям BERT и числовым примерам; `draw_encoder_figures.py` — схемы целей предобучения и вариантов кодировщиков. Оба запускаются отдельно при редактуре рисунков; обычная сборка встраивает сохранённые локальные изображения.
