## ViT: изображение становится последовательностью

ViT делит изображение на patches, проецирует каждый в D-мерный vector, добавляет position information и обрабатывает Transformer encoder (кодировщик входа). Для обычного classification attention (механизм внимания) bidirectional по доступным image tokens (токены). В отличие от decoder-only LLM, causal mask здесь обычно не нужна.

Пусть B — batch (пакет примеров), C — channels, H/W — размеры, P — сторона неперекрывающегося patch (фрагмент изображения). Если размеры делятся на P:

$$
\begin{gathered}N_h=\frac HP,\quad N_w=\frac WP,\quad N=N_hN_w,\quad K_{\mathrm{patch}}=CP^2,\\X\in\mathbb{R}^{B\times C\times H\times W},\quad X_{\mathrm{patches}}\in\mathbb{R}^{B\times N\times K_{\mathrm{patch}}},\\E\in\mathbb{R}^{K_{\mathrm{patch}}\times D},\quad b\in\mathbb{R}^{D},\qquad Z=X_{\mathrm{patches}}E+b\in\mathbb{R}^{B\times N\times D}.\end{gathered}
$$

Embedding (векторное представление) width D задаётся архитектурой и не обязана равняться CP². Совпадение 768 для RGB patches $16\times 16$ и ViT-Base $D=768$ — частный выбор.

Для H=W=224,$P=16$,$C=3$ получаем сетку $14\times 14$, $N=196$, K_patch=768. Матрица проекции содержит $768\cdot 768+768=590 592$ параметра с bias. Добавление одного learned CLS token (токен) даёт длину 197; его итоговое state (состояние системы) используют для head. Другой вариант — pooling (агрегирование состояний) patch states, так что CLS не обязательная математическая часть всех ViT.

Далее, для одного encoder head при row tokens:

$$
Q=ZW_Q,\quad K=ZW_K,\quad V=ZW_V,\qquad S=\operatorname{softmax}_{\mathrm{rows}}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right),\quad O=SV.
$$

Multi-head outputs объединяются, проецируются, добавляются residual/norm и tokenwise MLP. Векторы patches получают глобальный контекст через attention. Подробный backward (обратный проход вычисления производных) этого механизма уже разобран в [основах LLM](<../05-language-models/01-foundations/lm-attention.md>): смена modality не меняет chain rule.

### Почему в ViT нужен отдельный CLS и что он получает

CLS — обучаемый начальный вектор длины D, который добавляется как ещё одна позиция. В начале forward (прямой проход вычисления) он общий для разных изображений, но после attention его состояние зависит от patches данного изображения. Он может использовать их K/V и в последующих блоках снова уточнять representation. Таким образом, общий параметр CLS и выходной state CLS — разные объекты, как token embedding (входное векторное представление токена) и contextual state в текстовой модели.

Потеря классификации на итоговом CLS возвращает градиент к использованным patch states, далее к patch projection и пикселям вычислительного графа. Не требуется отдельная целевая метка для каждого patch, чтобы они участвовали в обучении. Альтернатива — mean-pooling patch states; выбор агрегатора должен соответствовать обучению checkpoint (сохранённое состояние модели), а не произвольно меняться только при оценке.

MLP внутри ViT применяется к каждому токену, включая CLS, одной и той же функцией данного блока. Attention смешивает позиции, MLP преобразует признаки каждой уже контекстной строки. В обычной классификации картинки все patches известны заранее, поэтому разрешить им двусторонний обмен нормально. Causal маска LLM нужна для другой постановки — предсказания неизвестного продолжения, — и не переносится сюда только из-за общего слова Transformer.

![Четыре patches превращаются в четыре вектора общей проекцией](<../оформление/transformer/patch-to-tokens.svg>)

На иллюстрации E общая для всех четырёх областей, а позиционные векторы различны. Цвет обозначает исходное место, а не класс объекта. Проекция не сокращает четыре patches до одного: она меняет число признаков каждой строки.

## Полная индексация patch embedding

Зафиксируем порядок flattened patch: сначала c, затем локальные p,q. Для $i\in\{0,\ldots,N_h-1\}$, $j\in\{0,\ldots,N_w-1\}$, $p,q\in\{0,\ldots,P-1\}$:

$$
\begin{aligned}n&=iN_w+j,\qquad k=cP^2+pP+q,\\(X_{\mathrm{patches}})_{b,n,k}&=X_{b,c,iP+p,jP+q},\\Z_{b,n,d}&=\sum_k(X_{\mathrm{patches}})_{b,n,k}E_{k,d}+b_d.\end{aligned}
$$

В original export сначала объявлялся HWC, а flatten объяснялся как для CHW. Само отображение может быть задано как угодно, но соответствие memory axes надо фиксировать. Здесь всё согласовано с NCHW.

Линейная проекция всех patches эквивалентна Conv2d с `in_channels=C, out_channels=D, kernel_size=P, stride=P, padding=0`, если:

$$
(W_{\mathrm{conv}})_{d,c,p,q}=E_{cP^2+pP+q,\,d}.
$$

Действительно:

$$
\begin{aligned}Y_{b,d,i,j}&=\sum_{c,p,q}(W_{\mathrm{conv}})_{d,c,p,q}X_{b,c,iP+p,jP+q}+b_d\\&=Z_{b,\,iN_w+j,\,d}.\end{aligned}
$$

После conv output $B\times D\times N_{h}\times N_{w}$ нужно flatten spatial и transpose в $B\times N\times D$. В PyTorch `Linear.weight` имеет $D\times K_{\mathrm{patch}}$, то есть хранит Eᵀ нашей формулы. Переставить веса без этого transpose/reshape — ошибка, которая не обязательно обнаружится только по конечным shapes.

### Четыре индекса в вычислении внимания

Проследим адрес конкретного элемента patch и все промежуточные индексы. Пусть $C=3$, $H=W=32$, $P=8$. Тогда $N_w=4$. Для patch с i=1,j=2 получаем n=6. Внутри него возьмём c=2,p=3,q=5; flattened индекс k=$2\cdot64+3\cdot8+5=157$. Этому числу соответствует пиксель $X_{b,2,11,21}$, поскольку глобальные координаты равны $(1\cdot8+3,2\cdot8+5)$.

Одна координата embedding d умножает этот пиксель на $E_{157,d}$ и складывает с аналогичными вкладами остальных 191 элементов patch. Один и тот же E используется у patch n=0, n=6 и всех остальных. Отдельной матрицы «для верхнего левого patch» нет; различие мест сообщит позиционная информация на следующем шаге.

Для всех patches одной картинки $Z=X_{patches}E+\mathbf1_N b^\top$. Запись с единичным столбцом показывает bias без неявного broadcasting: одна и та же строка $b^\top$ прибавляется N раз. Для batch повторяется та же операция независимо по B; веса не умножаются на размер batch при подсчёте параметров.

### Почему эквивалентности Conv2d недостаточно объявить на словах

Возьмём канал d выходной свёртки. Его filter содержит $CP^2$ коэффициентов, каждый для конкретных c,p,q. При stride (шаг пространственного перемещения операции)=P и без padding (дополнение до общей длины) filter на location i,j видит ровно patch i,j. Каждое слагаемое произведения совпадает с соответствующим членом линейной проекции, если kernel присвоен по приведённому выше индексу k. Bias совпадает тоже. Так устанавливается поэлементное равенство, а не только похожесть форм.

После conv ось d стоит второй: $B\times D\times N_h\times N_w$. Для Transformer tokens должны стоять перед каналами: spatial оси объединяются в N, после чего происходит transpose в $B\times N\times D$. Операция `reshape` без нужной перестановки может сохранить число элементов и дать желаемую форму, но перемешать содержимое токенов. Проверять нужно реальные значения на нумерованном входе, а не только shape.

В источнике заявлялся HWC, а формула flatten соответствовала CHW. Оба порядка допустимы отдельно. Если выбрать HWC, коэффициент должен следовать индексу $(pP+q)C+c$; тогда и строки E переставляются соответственно. Одинаковая E при разных flatten-порядках задаёт другую функцию. Эта поправка сохраняет все шаги исходного объяснения и устраняет его неоднозначность.

### Формы реализации без зависимого от версии training API

Для NCHW входа путь через patches можно описать последовательностью операций:

```python
# X: B, C, H, W; H и W делятся на P
patches = X.unfold(2, P, P).unfold(3, P, P)
# B, C, N_h, N_w, P, P
patches = patches.permute(0, 2, 3, 1, 4, 5)
# B, N_h, N_w, C, P, P
patches = patches.reshape(B, N_h * N_w, C * P * P)
Z = linear(patches)  # Linear.weight имеет D, C*P*P

# Эквивалентный путь при согласованных весах
Y = conv(X)          # B, D, N_h, N_w; kernel=P, stride=P
Z_conv = Y.flatten(2).transpose(1, 2)
```

Это учебное сопоставление forward, а не код полного обучения. Чтобы скопировать веса, в нашей записи нужно $W_{conv}=E^\top$, reshaped в D×C×P×P. Сравнение `Z` и `Z_conv` при одинаковом bias проверяет и соглашение об осях, и корректность извлечения patches.

### Минимальный ручной пример

Одноканальное $4\times 4$ изображение содержит числа 1…16 по строкам. При $P=2$ первый patch $\left(1,\,2,\,5,\,6\right)$, второй $\left(3,\,4,\,7,\,8\right)$, третий $\left(9,\,10,\,13,\,14\right)$, четвёртый $\left(11,\,12,\,15,\,16\right)$. Возьмём $D=2$, bias=0 и columns E:

$$
E_{:,1}=\begin{bmatrix}1\\1\\1\\1\end{bmatrix},\qquad E_{:,2}=\begin{bmatrix}1\\0\\0\\-1\end{bmatrix}.
$$

Получим $Z=\begin{bmatrix}14 & -5\\22 & -5\\46 & -5\\54 & -5\end{bmatrix}$. Два conv filters $\begin{bmatrix}1 & 1\\1 & 1\end{bmatrix}$ и $\begin{bmatrix}1 & 0\\0 & -1\end{bmatrix}$ со stride2 дадут те же четыре vectors. Первая координата суммирует patch; вторая сравнивает диагональные pixels. Это пример learned linear filters, а не обязательное значение реальных trained columns.

Gradient (градиент) также прозрачен. При $G=\frac{\partial\mathcal{L}}{\partial Z}$ матрично $\frac{\partial\mathcal{L}}{\partial E}=X_{\mathrm{patches}}^\top G$, $\frac{\partial\mathcal{L}}{\partial X_{\mathrm{patches}}}=GE^\top$, а bias gradient суммирует B/N. Входной gradient раскладывается обратно по местам patches. При overlap вклады в одни pixels складываются.

### Что именно обучается в E и как читать её строки и столбцы

В соглашении E размера $CP^2\times D$ столбец $E_{:,d}$ — полный linear filter для координаты d. Строка $E_{k,:}$ описывает, как один входной элемент patch влияет на все D координат. В разбираемом примере оба объекта назывались «шаблоном»; различие полезно для проверки shapes: у фильтра одного output должно быть столько коэффициентов, сколько входных элементов, то есть CP².

Проекция с D<CP² не может быть обратимой на всём пространстве pixels: её rank не больше D, часть направлений теряется. При D≥CP² и полном столбцовом/строчном ранге в согласованной ориентации сама линейная часть может сохранять достаточно информации для восстановления, но objective (оптимизируемая целевая функция) классификации не требует этого. Даже квадратная E не обязана быть невырожденной. Поэтому равенство D=768 и CP²=768 не означает «без потерь» автоматически.

Backward по E суммирует вклады всех patches всех B объектов. Для одного output $Z_{b,n,d}$ производная по $E_{k,d}$ равна значению соответствующего pixel-компонента $X_{patches,b,n,k}$. Через loss (функция потерь) этот вклад умножается на downstream gradient $G_{b,n,d}$. Поэтому один filter может обучаться на разных местах картинки одновременно. При overlap один пиксель участвует в нескольких patches, и его входные градиенты суммируются; простое присваивание последнего вклада потеряло бы часть производной.

Числа исходного примера для больших ширин также сохраняются: при P=16,C=3,D=1024 projection имеет $768\cdot1024+1024=787456$ параметров. При P=14,C=3,D=1280 — $588\cdot1280+1280=753920$ с bias. Число 752640 из рассматриваемого примера учитывает только матрицу. Нельзя сравнивать его с бюджетом другого варианта, где bias уже включён, без пояснения.

## Зачем patches, positions и какие ограничения

Если сделать token из каждого pixel $224\times 224$, $N=50$ 176, матрица attention имеет около 2.52 млрд элементов на head. Для $N=196$ — 38 416. Отношение **числа pairwise entries** равно $256^2=65 536$ без CLS. Это не 65 536-кратный выигрыш полного training: остаются projections/MLP, другая ширина и kernels.

Уменьшение P увеличивает N и сохраняет более мелкую spatial структуру, но повышает attention cost. При doubling обеих сторон изображения N растёт вчетверо, pairwise entries — в 16 раз. Поэтому resolution влияет иначе, чем только число parameters (параметры).

Одинаковая linear projection применяется к каждому patch. Если переставить patches, выходные vectors переставятся так же: это **equivariance**, не invariance. Последовательность сама помнит порядок индексов в массиве, но без position information стандартный Transformer encoder не получает привилегированной геометрии этой сетки. Learned absolute/relative position schemes добавляют spatial relations; при новом resolution может требоваться корректная interpolation/иная схема.

Из linear embedding не следует, что semantic patches автоматически близки. Это свойство зависит от обучения всех последующих layers/objective. CNN имеет сильные locality/weight sharing priors; ViT получает часть locality через patches, но глобальное смешивание attention устроено иначе. Больше данных/pretraining (предобучение) часто помогает ViT, однако «ViT всегда требует гигантский dataset» слишком категорично: data-efficient training и transfer меняют условия. [ViT](https://arxiv.org/abs/2010.11929).

### Перестановка patches: точное свойство и предел интуиции

Пусть Π переставляет N строк $X_{patches}$. Тогда shared linear projection даёт

$$
(\Pi X_{patches})E+\mathbf1 b^\top=\Pi(X_{patches}E+\mathbf1 b^\top).
$$

Output меняется той же перестановкой. Это equivariance. Если затем усреднить строки без позиционной информации, получится одинаковое среднее — уже инвариантность конкретного агрегированного результата. Эти два утверждения нельзя смешивать.

Представим два изображения из одинаковых patches: небо сверху и трава снизу, затем наоборот. При отсутствии position information encoder с глобальным permutation-equivariant attention не получает привилегированной привязки patch к ячейке исходной сетки; pooling/CLS может не различить такую перестановку в идеализированных условиях. Фиксированная позиционная сетка, прибавленная к embeddings (векторные представления), нарушает эту симметрию: один patch получает другое сочетание content и location.

Если вместе переставить и patches, и их позиционные векторы, соответствие снова будет сохранено. Поэтому важен именно способ закрепления positional information за местами. При смене resolution число grid-позиций меняется. Для learned absolute embeddings иногда интерполируют spatial grid, обрабатывая CLS отдельно; это техника согласования формы, а не гарантия сохранения качества на любом размере.

### Когда менять patch size, а когда архитектуру

При 224×224 переход P=16→P=8 увеличивает N с 196 до 784, то есть вчетверо, а число pairwise entries с 38416 до 614656, то есть в шестнадцать раз. При P=14 N=256 и 65536 entries, примерно в 1.706 раза больше, чем при P=16. Это нагляднее формулировки «патч немного меньше»: небольшое изменение стороны может заметно увеличить attention.

При этом размер матрицы projection при фиксированном D уменьшается вместе с P². Значит, «меньше параметров patch embedding» может сочетаться с «намного больше вычислений attention». Общие FLOPs включают и Q/K/V projections, и MLP по всем N, поэтому ни parameter count, ни N² отдельно не описывают полную скорость.

Перекрывающиеся patches используют stride S<P; без padding число позиций по высоте равно $\lfloor(H-P)/S\rfloor+1$. Не следует продолжать формулу N=HW/P² для этого случая. Overlap даёт более плотное покрытие и новые связи на входе, одновременно увеличивая N. Conv stem добавляет несколько локальных нелинейных преобразований до token sequence. Иерархическая схема может уменьшать spatial grid по стадиям, а оконное внимание ограничивает взаимодействия; это разные способы контролировать стоимость и локальность.

CNN и ViT поэтому нельзя ранжировать только по словам «маленький» и «большой dataset». Pretraining, аугментации, разрешение, teacher (модель-учитель) signals и compute меняют условия. Содержательный вывод из разбираемого примера сохраняется: CNN даёт более сильную встроенную локальную структуру, ViT с глобальным attention позволяет прямой обмен между удалёнными patches. Выбор проверяется в сопоставимом протоколе. Архитектурная основа patch sequence — [оригинальный ViT](https://arxiv.org/abs/2010.11929).

## Полное обучение ViT: от метки картинки до patch projection

![Путь изображения через Vision Transformer и обратное распространение ошибки](<../оформление/transformer/vit-pipeline.svg>)

На схеме специально показаны обе оси: число токенов 197 и ширина признаков 768. Attention смешивает токены вдоль первой оси, а MLP преобразует координаты вдоль второй. Равные численные размеры patch vector и hidden state (скрытое состояние позиции) в этом примере не делают две операции одинаковыми. Схема и следующий разбор — разбор механизмов; учебные числа не являются отчётом о тренировке модели.

### Почему одной метки достаточно для всех patches

Пусть изображение принадлежит классу «кошка», а head выдаёт три logits (логиты, оценки альтернатив до нормировки) для классов «кошка», «собака», «автомобиль». Из выходного CLS получаем $z=h_{\rm CLS}W+b$. При вероятностях $(0.6,0.3,0.1)$ loss равна $-\log0.6\approx0.510826$, градиент по logits — $(-0.4,0.3,0.1)$. Этот вектор проходит через head к итоговому CLS, затем через все encoder-блоки.

В attention CLS содержит взвешенную смесь V других позиций. Поэтому градиент приходит к patch values, к keys, повлиявшим на веса, и к query (запрос) CLS. Через ранние слои он достигает самой patch projection. Если один и тот же параметр E использовался для всех 196 patches, его итоговый градиент суммирует вклады всех этих применений, всех изображений batch и всех путей в графе. Не нужно назначать каждому patch класс «кошка»; такая искусственная разметка вообще неверна для patches, содержащих только фон.

Для проекции $Z=PE+b$, где строки P — распрямлённые patches, при градиенте $G=\partial\mathcal L/\partial Z$ имеем

$$
\frac{\partial\mathcal L}{\partial E}=P^\top G,\qquad
\frac{\partial\mathcal L}{\partial P}=GE^\top,\qquad
\frac{\partial\mathcal L}{\partial b}=\sum_n G_n.
$$

Сумма дополнительно охватывает batch. Первое равенство показывает обучение patch projection; второе — как сигнал можно вернуть к пикселям, например для анализа чувствительности. Обычное supervised обучение обновляет E и другие параметры, а не заменяет исходные пиксели train dataset шагом optimizer (оптимизатор обновления параметров). Наличие производной по входу не означает, что вход — обучаемый параметр.

### Чему учатся CLS и position embeddings

Начальный CLS — один параметр модели, повторённый для изображений batch. Его начальный вектор одинаков, но после первого attention результаты уже зависят от конкретных patches. Производные к исходному CLS суммируются по примерам. Этот параметр учится формировать полезный запрос и участвовать в накоплении информации, но он не содержит заранее готового класса текущей картинки.

Если $Z_0=[c;PE+b]+E_{\rm pos}$, то сложение даёт прямой градиент к position embeddings. Позиция может менять дальнейшие Q/K/V и тем самым влиять на маршруты внимания. В стандартном ViT позиционные векторы не являются неподвижными координатами пикселей: это обучаемые признаки индексов сетки. При изменении разрешения число patches меняется, поэтому таблицу нельзя просто прибавить без согласования размеров. Для learned absolute embeddings часто отдельно интерполируют пространственную сетку, сохраняя специальный CLS-вектор. Изменение порядка обхода сетки без перестановки соответствующих positions меняет смысл входа.

Внутри одного слоя все токены используют общие WQ/WK/WV и MLP. Это не набор отдельных весов для левого верхнего и правого нижнего patches. Различия возникают из содержимого токенов и position information. Между слоями параметры обычно разные. После глобального attention токен исходного patch уже может содержать сведения о всей картинке; его пространственный индекс сохраняется, но receptive field (область входа, влияющая на элемент карты) не ограничен исходным квадратом 16×16.

### Предобучение, linear probe и полный fine-tuning (дообучение модели)

При supervised pretraining обновляют backbone (основная сеть извлечения признаков) и classifier на большом размеченном наборе. Затем при переносе на другой набор классов обычно заменяют head, потому что размер и смысл выходов изменились. Это не требует уничтожать ранее выученную patch projection: она уже преобразует локальное изображение в полезные признаки. Но пригодность представления проверяют на новых данных, а не выводят из самого наличия checkpoint. Роль масштабного предобучения в исходном ViT описана в [оригинальной работе](https://arxiv.org/abs/2010.11929).

Linear probe замораживает backbone и обучает линейную голову. Градиенты для головы нужны, для весов backbone — нет. Полный fine-tuning позволяет менять также attention, MLP, positions и patch projection. Частичное размораживание занимает промежуточное положение. Сравнение этих режимов показывает, достаточно ли уже готовых признаков или задаче полезна адаптация самого представления. Оно не доказывает, что один режим всегда лучше при любом размере данных.

В отличие от текстового next-token обучения, обычная классификация ViT имеет одну целевую метку на изображение и не сдвигает последовательность patches на один шаг. Все patches уже наблюдаемы. Применить causal mask только потому, что используется Transformer, означало бы изменить граф обмена информацией без требования задачи. Авторегрессионные модели изображений и masked image modeling существуют, но их цели и маски задаются отдельно.

### Что особенно важно в тренировочном режиме

Сначала изображение приводят к формату и нормировке выбранного backbone. Случайные crop и flip меняют train input, сохраняя метку только при допустимости такой инвариантности для задачи. Например, зеркальное отражение может менять смысл символа или медицинского снимка; увеличение числа аугментаций само по себе не гарантирует полезных данных. Train и validation (проверочная часть для выбора решения) не должны случайно содержать почти одинаковые кадры одного объекта или видео, если нужна оценка переноса на новые объекты.

Mixup смешивает два изображения и их целевые распределения: $\tilde x=\lambda x_a+(1-\lambda)x_b$, $\tilde y=\lambda y_a+(1-\lambda)y_b$. При $\lambda=0.7$ и разных классах цель содержит массы 0.7 и 0.3, а cross-entropy использует оба класса. CutMix вставляет область другого изображения; коэффициент метки связывают с фактически вставленной площадью, которая может отличаться от предварительно выбранной после обрезания прямоугольника границами. Эти процедуры изменяют обучающую задачу и требуют поддержки мягких целей.

Оптимизация проходит через тот же chain rule, что в NLP. На каждом шаге получают logits, вычисляют loss, возвращают производные и обновляют выбранные параметры. Learning rate, weight decay (затухание весов при обновлении), warmup, dropout и stochastic depth управляют разными аспектами обучения; они не заменяют друг друга. Stochastic depth случайно отключает residual-ветви при обучении с выбранной схемой масштабирования, а не удаляет patches из входа. При validation случайные обучающие преобразования выключают или используют явно оговорённую процедуру оценки.

### Как читать вычислительную цену картинки

Для сетки 14×14 с CLS длина равна 197; одна голова имеет 38 809 attention scores (оценки). При 448×448 и том же patch 16 сетка становится 28×28, длина — 785, scores — 616 225. Отношение приблизительно 15.88: удвоение обеих сторон увеличило число patches вчетверо, а число пар почти в шестнадцать раз. При этом линейные проекции и tokenwise MLP по числу токенов выросли примерно в четыре раза. Поэтому нельзя назначать всей модели один квадратичный коэффициент без учёта составляющих.

Уменьшение patch size даёт более мелкую пространственную сетку, но также увеличивает длину. Полезность мелких деталей зависит от задачи, качества предобучения и вычислительного бюджета. Для segmentation или depth нужен выход по пространственным позициям: можно взять patch states, вернуть им форму сетки и применить decoder (декодер) для восстановления разрешения. Один CLS для всей картинки сам по себе не является картой маски. Иерархические и оконные Transformers меняют этот компромисс; их механизмы следует рассматривать отдельно от простой глобальной схемы ViT.

## Самопроверка и практика

1. Почему D не обязательно CP²? **Ответ:** E — произвольная обучаемая rectangular projection.
2. Сколько tokens с CLS у изображения $224\times224$ при размере patch $16\times16$? **Ответ:** 197.
3. Почему patch embedding не permutation-invariant? **Ответ:** перестановка входных patches переставляет outputs, а не оставляет всю последовательность прежней.
4. Что оптимизировать при замороженном backbone? **Ответ:** только выбранную head и прочие явно разрешённые параметры. Веса backbone не обновляются; сами features (признаки) могут различаться при изменении входа, аугментаций или активного dropout.

**Практика:** пересчитать $4\times 4$ пример и conv correspondence. Затем при $B=2$,H=W=32,$C=3$,$P=8$,$D=24$ выписать $patches:2\times 16\times 192$, $E:192\times 24$, $Z:2\times 16\times 24$, budget $192\cdot 24+24=4632$. Для реальных данных сравнить frozen+kNN, frozen+linear и одну partial-tuning конфигурацию; анализировать false positives/negatives по источникам, масштабу и backgrounds.

## Как читать углубления этой ветки


Для самостоятельного CV-маршрута attention не требует предварительного изучения LLM. Из token states $X\in\mathbb R^{N\times D}$ линейные projections дают $Q=XW_Q,K=XW_K,V=XW_V$. В одной head $A=\operatorname{softmax}(QK^T/\sqrt{d_k})$ нормируется по keys каждой query; output $AV$ смешивает value vectors. Все projection weights обучаются через task loss. Attention scores сами не являются метками объектов.

[Swin](<cv-hierarchy.md>) изменяет spatial organization внимания, [MAE/DeiT](<cv-pretraining.md>) — training signal, [DINO](<cv-dino.md>) — согласование views, [DETR](<cv-detr.md>) — способ выдачи множества объектов.

## Разобранный пример для проверки контракта


Пусть для одной query после scale logits равны $(\ln3,0)$, values $v_1=(2,0)$ и $v_2=(0,4)$. Softmax weights $(3/4,1/4)$, output $(1.5,1)$. Это weighted sum, а не выбор только первого token. Если добавить третью key с logit 0, прежние weights станут $(3/5,1/5,1/5)$: denominator меняет весь ряд.

## Ограничения переноса

При изменении patch size меняются token count и смысл projection weights. Interpolation position embeddings может помочь смене сетки, но не заменяет evaluation fine details.

## Самопроверка с ответами

**Практика:** переставьте keys и соответствующие values одновременно. При неизменном query result сохранится, если positional information уже не меняется отдельно.

**Почему attention делят на $\sqrt{d_k}$?** При стандартных assumptions variance dot products растёт с dimension; scaling помогает контролировать насыщение softmax.

**Можно ли считать high attention pixel explanation доказательством причинности?** Нет, feature mixing и последующие blocks тоже влияют на output.

## Схема вычислений

![Vision Transformer: patches, attention и обучение: вычислительные этапы](<../оформление/course/expanded-cv-vit.svg>)

Self-attention: Tokens X: N×D + positions → Q,K,V: обучаемые projections → Softmax rows of QKᵀ / √dk → Weighted values → residual block.

Обучаемые преобразования и фиксированные операции разделены в последующем объяснении; стрелки показывают передачу данных, а направление градиента обсуждается вместе с loss.
