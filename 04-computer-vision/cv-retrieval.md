# Visual retrieval: metric learning и поиск изображений

**Уровень:** основа ветки.

**Предпосылки:** [Обучение и перенос: frozen features, fine-tuning и аугментации](<cv-transfer.md>)

**Используют:** Самостоятельное применение выбранной ветки.

**Учебный вопрос:** Как обучить и оценить поиск похожих изображений?

## Схема вычислений

![Visual retrieval: metric learning и поиск изображений: вычислительные этапы](<../оформление/course/expanded-cv-retrieval.svg>)

Metric learning: Anchor / positive / negative → Общий обучаемый encoder → Embeddings → distances → Triplet loss → gradient. Поиск: Query → encoder v1 → Gallery → тот же encoder v1 → Index → top-K → reranking → Ранжирование → AP / recall.

Обучаемые преобразования и фиксированные операции разделены в последующем объяснении; стрелки показывают передачу данных, а направление градиента обсуждается вместе с loss.

## Сначала определить релевантность

Visual retrieval возвращает ранжированный список изображений по query. Релевантность может означать тот же товар, тот же физический объект или похожий стиль. Эти отношения не совпадают: две красные кружки похожи по цвету, но могут быть разными SKU. Split должен исключать утечку экземпляров, если требуется перенос на новые товары. Baseline — frozen embeddings с cosine search.

## Siamese и metric learning

Siamese-схема применяет один encoder с общими весами к разным изображениям. Получаем $z=f(x)$, часто с L2-normalization. Для normalized vectors $\|z_i-z_j\|_2^2=2-2z_i^Tz_j$, поэтому cosine и Euclidean дают одинаковый порядок при одинаковой нормировке.

Triplet loss использует anchor $a$, positive $p$, negative $n$:

$$
L=\max(0,\|z_a-z_p\|_2^2-\|z_a-z_n\|_2^2+m).
$$

Margin $m>0$ задаёт желаемый зазор squared distances. Если он выполнен, эта тройка не даёт gradient. Random negatives часто слишком просты, hard mining выбирает близкие нерелевантные примеры, но ошибки меток делают самые hard negatives опасными. [FaceNet](https://arxiv.org/abs/1503.03832) — конкретный пример обучения triplet embeddings; для другой семантики нужны свои пары.

## Индекс, reranking и обновление

Gallery embeddings вычисляют заранее. Exact search сравнивает query со всеми $M$ vectors за $O(MD)$; approximate index снижает стоимость с возможной потерей нужных соседей. Reranking уточняет порядок небольшой выборки кандидатов, но не возвращает объект, который не попал в кандидаты. Версия encoder и preprocessing должна совпадать у query и gallery; переобучение encoder обычно требует пересчёта индекса.

## Разобранный пример: loss и ranking

Пусть $a=(0,0)$, $p=(0.3,0.4)$, $n=(0.6,0.8)$ — учебные ненормированные vectors. Squared distances равны 0.25 и 1. При $m=0.5$ loss $\max(0,0.25-1+0.5)=0$. Для negative $(0.4,0.3)$ его squared distance 0.25, и loss станет 0.5. Получение нуля для одной тройки не гарантирует хорошей геометрии всех объектов.

В gallery есть три релевантных объекта; они стоят на местах 1,3,5. Precision в этих местах: $1$, $2/3$, $3/5$. Average Precision $=(1+2/3+3/5)/3\approx0.75556$. Recall@3 $=2/3$. Показатель «есть хотя бы один relevant в top-3» равен 1 и отвечает другому вопросу; в некоторых retrieval benchmarks именно его называют Recall@K, поэтому convention фиксируют явно.

## Ограничения

Дубликаты и разные фотографии одного объекта могут завысить метрики. Background shortcut приводит к соседям из одной фотостудии. Для оценки нужны срезы по новым объектам, ракурсам, камерам и тяжёлым negatives. Отдельно измеряют качество embeddings, потерю approximate index и latency end-to-end.

## Самопроверка с ответами

**Практика:** исключите релевантный объект на месте 5 из выдачи, но не из знаменателя AP. Качество упадёт; ограничение списка не делает пропущенный relevant несуществующим.

**Достаточно ли уменьшать triplet loss?** Нет: выбранные тройки могут не представлять трудные случаи применения.

**Почему нельзя незаметно сменить encoder только для query?** Пространства старой gallery и нового query не обязаны быть согласованы.
