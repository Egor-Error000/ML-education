## U-Net и nnU-Net: пространственный decoder и настройка pipeline

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как U-Net восстанавливает детали и что автоматизирует nnU-Net?

**Уровень:** основа ветки. **Предпосылки:** cv-semantic

**Потребители:** cv-domains

**Порядок объяснения:**

1. От класса изображения к маске.
2. U-Net: две ветви одной сети.
3. nnU-Net — больше, чем название блока.
4. Разобранный пример: каналы и ошибка.
5. Нюансы выбора.
6. Самопроверка с ответами.

**Разобранный пример:** В учебном same-padding decoder карта $[B,128,32,32]$ увеличивается до $[B,64,64,64]$. Skip имеет $[B,64,64,64]$. Concatenation даёт $[B,128,64,64]$, затем свёртка $3\times3$, $128\to64$ содержит $9\cdot128\cdot64=73728$ весов без bias. Сложение вместо concatenation изменило бы вход следующей свёртки и всю архитектуру.

Для мягкого binary prediction $(0.8,0.3,0.1,0.9)$ и target $(1,0,0,1)$ пересечение $\sum py=1.7$, сумма predictions 2.1, сумма targets 2. Soft Dice без smoothing $2\cdot1.7/(2.1+2)=0.82927$, loss 0.17073. Hard mask при пороге 0.5 совпадёт с GT и имеет Dice 1. Значит, soft training loss и thresholded metric не обязаны совпадать.


**Схемы и разбор:** U-Net: Image → encoder levels → Bottleneck → upsampling → Concat с encoder skip → Convolutions → pixel logits; nnU-Net pipeline: Данные + spacing + labels → Планирование patch / model → 2D / 3D training + validation → Sliding-window → original grid.

## DeepLabv3+ и SegFormer: контекст и декодирование

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как DeepLabv3+ и SegFormer объединяют контекст с пространственными деталями?

**Уровень:** основа ветки. **Предпосылки:** cv-semantic, cv-vit

**Потребители:** Самостоятельное применение.

**Порядок объяснения:**

1. Два способа получить multiscale context.
2. DeepLabv3+: dilation, ASPP и decoder.
3. SegFormer: encoder MiT и MLP decoder.
4. Разобранный пример: охват и память.
5. Диагностика.
6. Самопроверка с ответами.

**Разобранный пример:** Kernel $3\times3$ с dilation 6 имеет эффективный размер $3+2\cdot5=13$ cells. На stride 16 расстояние крайних центров sampled positions составляет $12\cdot16=192$ pixels; это не полный receptive field всей сети, который включает ранние операции.

Для изображения $512^2$ SegFormer-карты могут иметь сетки $128^2,64^2,32^2,16^2$. После projection к 256 каналам и upsampling на $128^2$ concatenated tensor имеет $4\cdot256\cdot128^2=16777216$ чисел, 64 MiB float32 на один пример. Лёгкий по параметрам decoder всё ещё может требовать заметную память активаций.


**Схемы и разбор:** DeepLabv3+: CNN с atrous features → ASPP: rates + global pooling → Up + low-level skip → Decoder → semantic logits; SegFormer: Overlapping patch stages → MiT: 4 scales of features → MLP project → up → concat → Fusion → K pixel logits.

## YOLACT: prototype masks, коэффициенты и crop

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как получить маску экземпляра без отдельного пространственного decoder на каждый объект?

**Уровень:** основа ветки. **Предпосылки:** cv-instance

**Потребители:** Самостоятельное применение.

**Порядок объяснения:**

1. Две параллельные ветви.
2. Линейная сборка маски.
3. Targets, loss и выбор candidates.
4. Разобранный пример: смешивание и стоимость.
5. Ограничения и диагностика.
6. Самопроверка с ответами.

**Разобранный пример:** В одной позиции prototypes равны $(2,-1,0.5)$, coefficients экземпляра $(0.5,1,-2)$. Logit $2\cdot0.5-1\cdot1+0.5\cdot(-2)=-1$, вероятность $\sigma(-1)\approx0.26894$. Для другого экземпляра coefficients $(1,0,0)$ дают logit 2 и вероятность 0.88080 в том же пикселе. Shared prototypes не вынуждают все объекты иметь одинаковую маску.

При $H_p=W_p=138$, $K=32$, $n=100$ выбранных экземплярах хранится 609408 prototype values и 3200 coefficients. Сборка всех masks требует около $138^2\cdot32\cdot100=60940800$ MAC и создаёт 1904400 mask values. Экономия shared features не отменяет стоимость матричного произведения и resize большого числа masks.


**Схемы и разбор:** YOLACT shared branch: Image → backbone / FPN → Protonet → Hp×Wp×K → Общие prototypes P → P используется всеми objects; Instance branch: FPN → classes / boxes / c → Candidate filtering + NMS → P × coefficients → sigmoid → Crop / resize → instance masks.

## Mask2Former: mask queries и panoptic segmentation

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как один набор mask queries решает разные виды segmentation?

**Уровень:** углубление. **Предпосылки:** cv-instance, cv-detr

**Потребители:** Самостоятельное применение.

**Порядок объяснения:**

1. Mask classification вместо отдельного класса каждого пикселя.
2. Pixel decoder и Transformer decoder.
3. Training и три вида результата.
4. Разобранный пример: semantic aggregation и PQ.
5. Ограничения.
6. Самопроверка с ответами.

**Разобранный пример:** Два queries имеют вероятности класса «дорога» 0.8 и 0.1, а mask probabilities в pixel — 0.6 и 0.9. Ненормированный semantic score дороги: $0.8\cdot0.6+0.1\cdot0.9=0.57$. Это сумма contributions, а не готовая откалиброванная вероятность события.

Для panoptic evaluation пусть два matched segments имеют IoU 0.8 и 0.6, ещё есть один FP и один FN. Тогда $PQ=(0.8+0.6)/(2+0.5+0.5)=0.46667$. Segmentation Quality $SQ=1.4/2=0.7$, Recognition Quality $RQ=2/3$, произведение $0.46667$. Matching и правила допустимости классов задаются протоколом, обычно с IoU больше 0.5 для panoptic segments.


**Схемы и разбор:** Mask2Former: Backbone → pixel decoder → Mask features D×Hm×Wm → Queries → class + embedding → Dot product → Q masks; Masked decoding: Предыдущие query masks → Resize / threshold → support → Masked cross + self-attention → Новые queries → новые masks.
