## Faster R-CNN: RPN, RoI и обучение двух стадий

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как RPN и RoI-head совместно превращают карту признаков в объекты?

**Уровень:** основа ветки. **Предпосылки:** cv-detection, cv-pyramids

**Потребители:** Самостоятельное применение.

**Порядок объяснения:**

1. Две стадии с общей картой.
2. Targets и RPN.
3. RoI-признаки, loss и inference.
4. Разобранный пример: обратное преобразование.
5. Самопроверка с ответами.

**Разобранный пример:** Anchor имеет центр $(50,40)$ и размеры $(20,10)$, GT — центр $(54,38)$ и размеры $(30,10)$. Targets: $t_x=0.2$, $t_y=-0.2$, $t_w=\ln1.5\approx0.40547$, $t_h=0$. Декодирование: $x=50+0.2\cdot20=54$, $y=40-0.2\cdot10=38$, $w=20e^{0.40547}=30$, $h=10$. Итоговый xyxy — $(39,33,69,43)$.

Для 1000 proposals, $C=256$ и RoI-сетки $7\times7$ получаем $12544000$ активаций, примерно 47.85 MiB float32 до дальнейших слоёв. Уменьшение proposals сокращает стоимость, но может снизить recall мелких и перекрытых объектов.


**Схемы и разбор:** RPN: Image → backbone / FPN → Anchors → objectness + 4Δ → Decode → proposal NMS → R выбранных областей; RoI-head: Области + общие features → RoIAlign → R×C×7×7 → Class head + box head → Scores → final NMS.

**Уровень:** основа ветки. **Предпосылки:** cv-detection, cv-pyramids

**Потребители:** Самостоятельное применение.

**Разобранный пример:** GT box $(10,20,50,60)$, позиция $(20,40)$. Расстояния $(10,20,30,20)$, centerness $\sqrt{(10/30)(20/20)}=1/\sqrt3\approx0.57735$. В центре $(30,40)$ расстояния $(20,20,20,20)$ и centerness 1. Для точки вне рамки обычные positive targets не определяются этим правилом.

Пирамида имеет 8400 positions. При девяти anchors RetinaNet и $K=80$ classification выдаёт $8400\cdot9\cdot80=6048000$ scores. FCOS с одним предсказанием на позицию — $8400\cdot80=672000$, плюс regression и centerness. Это сравнение выходных массивов; реальные FLOPs зависят также от ширины и глубины head.


**Схемы и разбор:** RetinaNet: FPN: H×W×C → A anchors на cell → AK classes + 4A offsets → Focal / box loss → NMS; FCOS: FPN: H×W×C → Позиция внутри assigned GT → K classes + l,t,r,b + c → Decode distances → NMS.

**Разобранный пример:** На входе $640\times640$ сетки 80,40,20 дают 8400 positions. YOLOv3 с 80 классами выдаёт $3(4+1+80)=255$ channels каждого уровня. Всего $8400\cdot255=2142000$ raw numbers.

## DETR: queries, matching и set prediction

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как обучение множества предсказаний устраняет необходимость обычной NMS?

**Уровень:** основа ветки. **Предпосылки:** cv-detection, cv-vit

**Потребители:** cv-deformable, cv-mask2former

**Порядок объяснения:**

1. Выход как множество.
2. Queries, heads и matching.
3. Почему нельзя смешивать training и inference.
4. Разобранный пример: две перестановки.
5. Обучение и ограничения.
6. Самопроверка с ответами.

**Разобранный пример:** Пусть два GT, A и B, и два predictions, 1 и 2. Матрица pair costs по строкам predictions: $(1,2)$ и $(1.1,100)$. Greedy берёт пару 1→A с cost 1 и оставляет 2→B с cost 100, всего 101. Глобальный assignment выбирает 1→B и 2→A, всего $2+1.1=3.1$. Именно взаимодействие назначений требует оптимизации всего сопоставления.

При $Q=100$, $K=20$ один кадр имеет $100\cdot21=2100$ class logits и 400 box values. Карта $25\times40$ даёт 1000 encoder tokens; одна полная attention matrix содержит миллион scores на head. Удвоение обеих spatial сторон создаёт 4000 tokens и 16 миллионов scores. Это одна причина стоимости плотного attention.


**Схемы и разбор:** DETR forward: Image → CNN map + positions → Flatten → encoder memory → Q learned queries → decoder → Q classes + Q boxes; Training only: GT set + predictions → Class / L1 / GIoU costs → Hungarian one-to-one pairs → Matched loss; no-object rest.

## Deformable DETR и RT-DETR: внимание и скорость

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как сократить внимание к изображению и ускорить set prediction?

**Уровень:** углубление. **Предпосылки:** cv-detr, cv-pyramids

**Потребители:** Самостоятельное применение.

**Порядок объяснения:**

1. Ограничения полного attention.
2. Deformable DETR.
3. RT-DETR.
4. Разобранный пример: sampling и interpolation.
5. Диагностика и выбор.
6. Самопроверка с ответами.

**Разобранный пример:** Пусть $Q=100$, $M=8$, $L=4$, $K=4$. Всего $100\cdot8\cdot4\cdot4=12800$ выборок features. Dense cross-attention при $N=20000$ использует $100\cdot8\cdot20000=16000000$ scores. Разница иллюстрирует структурную экономию, но sampling часто менее эффективно использует память, чем большие матричные умножения.

В одной scalar-карте значения углов cell равны 0,2,4,6. Для координат с долями $u=0.25$, $v=0.5$ weights: 0.375,0.125,0.375,0.125. Результат $0+0.25+1.5+0.75=2.5$. Если перепутать нормированные координаты и pixel indices, sampled signal будет другим даже при правильных tensor shapes.


**Схемы и разбор:** Deformable attention: Query + reference point → Offsets / weights: M×L×K → Bilinear sample multi-scale → Weighted sum → refinement; RT-DETR: Backbone: multi-scale maps → Hybrid encoder: intra / cross → Выбор начальных queries → Decoder → classes / boxes.
