## CRAFT и DBNet: поиск текста на изображении

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как обнаруживать текст разной ориентации и формы?

**Уровень:** основа ветки. **Предпосылки:** cv-detection, cv-semantic

**Потребители:** cv-documents

**Порядок объяснения:**

1. Text detection до распознавания.
2. CRAFT: character regions и affinity.
3. DBNet: differentiable binarization.
4. Разобранный пример: soft threshold и resize.
5. Оценка и ошибки.
6. Самопроверка с ответами.

**Разобранный пример:** Для $P=0.6$, $T=0.5$, $k=10$ получаем $\hat B=\sigma(1)\approx0.73106$. При том же $P$ и $T=0.7$ результат $\sigma(-1)=0.26894$. Если $P=T$, ответ 0.5. Поэтому вероятность text и приблизительная binary map — разные выходы.

Исходный кадр $1200\times800$ уменьшен до $600\times400$. Polygon prediction имеет углы $(50,30),(150,20),(160,50),(60,60)$. При простом равномерном resize обратные координаты умножаются на 2. Если затем добавлялся padding, сначала его вычитают. Perspective rectification crop требует четырёхугольника в согласованном порядке; перестановка углов может перевернуть строку.


**Схемы и разбор:** CRAFT: Image → encoder / decoder → Character region scores → Affinity scores → grouping → Components → text polygons; DBNet: Image → multiscale features → Probability P + threshold T → Soft binarization при training → Contours → unclip polygons.

## CRNN, CTC и TrOCR: распознавание текста

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как читать строку без отдельной рамки каждого символа?

**Уровень:** основа ветки. **Предпосылки:** cv-classification, cv-vit

**Потребители:** cv-documents

**Порядок объяснения:**

1. Последовательность из изображения.
2. CRNN и CTC.
3. TrOCR: image encoder и autoregressive decoder.
4. Разобранный пример: repeated letters и CER.
5. Ошибки и стоимость.
6. Самопроверка с ответами.

**Разобранный пример:** CTC path `l l blank l blank` после слияния соседних повторов даёт `l blank l blank`, после удаления blank — `ll`. Path `l l l blank` даёт только `l`. Для target `ll` нужно минимум три timesteps: две буквы и разделяющий blank. В общем минимальная длина $T\ge U+r$, где $U$ — длина target, $r$ — число соседних одинаковых пар.

GT `кот`, prediction `кит`: одна substitution, CER $1/3\approx0.33333$. Для GT `кот`, prediction `котт`: одна insertion, тоже $1/3$. CER $(S+D+I)/N$ может превышать 1 при большом числе insertions; это не обычная accuracy. Case folding или удаление punctuation меняют задачу и должны быть одинаковы для всех моделей.


**Схемы и разбор:** CRNN + CTC: Rectified text crop → CNN → width sequence → BiRNN → T×(alphabet + blank) → CTC alignments → string; TrOCR: Crop → image Transformer → Image states → cross-attention → Causal decoder: BOS → tokens → EOS → decoded text.

## Document vision: layout, reading order и таблицы

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как связать геометрию страницы, OCR и структуру документа?

**Уровень:** основа ветки. **Предпосылки:** cv-text-detection, cv-text-recognition

**Потребители:** cv-cases

**Порядок объяснения:**

1. Страница как структурированный объект.
2. Layout и reading order.
3. Таблицы и поля.
4. Разобранный пример: две колонки и сквозная ошибка.
5. Диагностика и split.
6. Самопроверка с ответами.

**Разобранный пример:** Страница шириной 1000 pixels имеет левую колонку с boxes A $(50,100,450,140)$ и B $(50,160,450,200)$, правую — C $(550,110,950,150)$ и D $(550,170,950,210)$. Сортировка только по верхнему y даёт A,C,B,D. Если документ читается колонками, верный порядок A,B,C,D. Сначала определяют колонки, затем порядок внутри каждой.

Пусть из 100 GT fields detector/crop stage сохраняет 90; recognizer верно читает 81 из этих 90; relation assignment правильно связывает 72 из 81. Conditional accuracies: 0.9,0.9, $72/81\approx0.88889$. End-to-end exact match $72/100=0.72$. Усреднение трёх процентов дало бы завышенное представление о результате; ошибки стадий последовательно ограничивают pipeline.


**Схемы и разбор:** Document pipeline: Page image / PDF + page ID → Layout regions + OCR strings → Order graph / table structure → Fields + evidence coordinates; Table understanding: Table region → Rows / columns / spans → Cell assignment + OCR → Structured table → evaluation.

## Anomaly detection: reconstruction, PaDiM и PatchCore

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как искать дефекты, если при обучении есть преимущественно нормальные изделия?

**Уровень:** основа ветки. **Предпосылки:** cv-transfer

**Потребители:** cv-cases

**Порядок объяснения:**

1. Норма и anomaly score.
2. Reconstruction и PaDiM.
3. PatchCore.
4. Разобранный пример: covariance и порог.
5. Самопроверка с ответами.

**Разобранный пример:** Mean normal feature $(1,2)$, diagonal covariance $\operatorname{diag}(4,1)$, test feature $(3,3)$. Difference $(2,1)$, squared Mahalanobis distance $2^2/4+1^2/1=2$, score $\sqrt2\approx1.41421$. Euclidean distance $\sqrt5$ не учитывает, что первая координата в норме более изменчива.

Normal memory vectors $(0,0),(1,0),(0,1)$, test patch $(2,0)$. Nearest distance равна 1 до $(1,0)$. После удаления этого vector coreset distance станет 2. Score вырос без изменения test image: compression bank является изменением модели и требует validation.

На normal validation из 1000 независимых изделий порог оставляет 10 false alarms: FPR 1%. При потоке 100000 normal изделий в день это около 1000 alarm/day при сохранении distribution. Высокий AUROC не показывает приемлемость этой нагрузки.


**Схемы и разбор:** PaDiM: Normal images → frozen features → По позиции: mean / covariance → Test features → Mahalanobis → Anomaly map → image decision; PatchCore: Normal patches → memory bank → Representative coreset → Test patch → nearest neighbours → Distances → map / image score.

## Восстановление изображений: denoising, deblurring и super-resolution

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как восстанавливать изображение, не принимая правдоподобные детали за измеренные?

**Уровень:** основа ветки. **Предпосылки:** cv-input, cv-classification

**Потребители:** Самостоятельное применение.

**Порядок объяснения:**

1. Обратная задача.
2. Архитектуры и targets.
3. Loss и конфликт качества.
4. Разобранный пример: PSNR и неоднозначность.
5. Диагностика.
6. Самопроверка с ответами.

**Разобранный пример:** Для pixels в $[0,1]$ $PSNR=10\log_{10}(1/MSE)$. При MSE 0.01 получаем 20 dB; при 0.0025 — $10\log_{10}400\approx26.02060$ dB. Уменьшение MSE вчетверо добавило около 6.02 dB. Для диапазона 0..255 numerator должен быть $255^2$, а не 1; иначе comparison бессмысленно.

Два допустимых high-resolution patches равны $(0,1)$ и $(1,0)$ с одинаковой вероятностью, а degradation усредняет их до $y=0.5$. L2-optimal prediction $(0.5,0.5)$ имеет error 0.5 по сумме squared differences для любого варианта. Выбор $(0,1)$ иногда точен, иногда даёт error 2, ожидаемое значение 1. Усреднение улучшает L2, но теряет резкий рисунок — это следствие ambiguity.

Для scale factor 2 и RGB pixel shuffle требует 12 channels на low-resolution grid. Например, $[1,12,32,32]\to[1,3,64,64]$; операция сама не увеличивает количество предсказанных scalar values.


**Схемы и разбор:** Super-resolution: Low-resolution observation → Feature extraction / residual blocks → Subpixel features r²C → Pixel shuffle → high-res image; Restoration training: Clean image x → Degradation D + noise → y → Restorer → estimate x → Pixel / feature loss → gradient.

## Медицинские и спутниковые изображения: данные, объём и масштаб

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Какие свойства медицинских и спутниковых данных меняют обычный CV pipeline?

**Уровень:** углубление. **Предпосылки:** cv-unet, cv-obb, cv-camera

**Потребители:** Самостоятельное применение.

**Порядок объяснения:**

1. Единица независимости и физический масштаб.
2. Medical volumes.
3. Remote sensing.
4. Разобранный пример: spacing и tiling.
5. Самопроверка с ответами.

**Разобранный пример:** Medical volume $256\times256\times128$ при spacing $(0.7,0.7,3)$ mm, в порядке x,y,z, покрывает по соглашению voxel extent приблизительно $(179.2,179.2,384)$ mm. Кубический kernel $3^3$ samples имеет разные расстояния между centers по осям. Два voxels по z — 6 mm, два по x — 1.4 mm: одинаковая index error физически различна.

Satellite tile $512\times512$ при GSD 0.5 m/pixel покрывает 256 m на сторону. Объект длиной 10 m занимает 20 pixels, а после downsampling вчетверо — пять. Для изображения $2048^2$, tiles 512 и stride 384 требуется по $\lceil(2048-512)/384\rceil+1=5$ tiles на ось, всего 25. Граница в этом примере совпадает точно; для других размеров нужен explicit last-tile/padding policy.


**Схемы и разбор:** Medical pipeline: Volume + spacing / orientation → Resample / normalize / patches → 2D / 3D U-Net → logits → Original grid → physical metrics; Satellite pipeline: Scene + bands + GSD → Tiles с overlap + offsets → Detector / segmenter → local → Scene merge → geographic split.
