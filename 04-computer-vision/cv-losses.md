# Loss, дисбаланс, пороги и калибровка в CV

**Уровень:** основа ветки.

**Предпосылки:** [Классификация, CNN и residual learning](<cv-classification.md>)

**Учебный вопрос:** Как связать функцию потерь, дисбаланс и порог принятия решения?

## Схема вычислений

![Loss, дисбаланс, пороги и калибровка в CV: вычислительные этапы](<../оформление/course/expanded-cv-losses.svg>)

Обучение: Разметка: single / multi → Logits → softmax / sigmoid → CE / focal / smoothing → Gradient → параметры. Принятие решения: Validation logits → Calibration: выбрать T → Вероятность + цена FP/FN → Порог → ответ / проверка.

Обучаемые преобразования и фиксированные операции разделены в последующем объяснении; стрелки показывают передачу данных, а направление градиента обсуждается вместе с loss.

## Loss и метрика отвечают на разные вопросы

Loss — дифференцируемая цель оптимизации, метрика — способ оценки решения. Для single-label classification logits $z\in\mathbb R^K$ преобразуются softmax; CE равна $-\log p_y$. Для независимых меток нужны sigmoid по каждому классу и binary cross-entropy. Нельзя подавать независимые бинарные цели в mutually exclusive softmax и считать постановку неизменной.

При label smoothing зададим $q_k=(1-\epsilon)\mathbf1[k=y]+\epsilon/K$. Тогда $L=-\sum_kq_k\log p_k$. Это выбранная convention: распределение массы только по неверным классам даёт другие числа. Сглаживание уменьшает стимул делать уверенность бесконечной, но не гарантирует калибровку на новой камере.

## Дисбаланс и focal loss

Вес класса меняет вклад примера в objective, sampling — частоту его предъявления. Их совместное применение может избыточно усилить редкий класс. Для binary focal loss $L=-\alpha_t(1-p_t)^\gamma\log p_t$, где $p_t$ — вероятность истинного исхода. При $\gamma=0$ остаётся взвешенная CE. [Lin et al.](https://arxiv.org/abs/1708.02002) вводят этот механизм для большого числа простых фоновых кандидатов; полезность для другого режима проверяют отдельно.

## Порог и калибровка

Classification score не обязательно является вероятностью события. Для temperature scaling подбирают $T>0$ на calibration-части, используя $\operatorname{softmax}(z/T)$. При одном положительном $T$ порядок logits и argmax сохраняются, распределение меняется. Для выбора нескольких порогов по классам нужны отдельные критерии и данные достаточного объёма. [Guo et al.](https://arxiv.org/abs/1706.04599) исследуют калибровку сетей; хорошие результаты одного протокола не обещают устойчивость к domain shift.

Для откалиброванной вероятности $p$ и цен FP и FN ожидаемая цена положительного решения $C_{FP}(1-p)$, отрицательного $C_{FN}p$. Выбираем positive, когда $p>C_{FP}/(C_{FP}+C_{FN})$. Формула предполагает только эти две стоимости, одинаковую единицу решения и отсутствие дополнительной цены отказа.

## Разобранный пример: одна метка, три решения

Пусть $K=3$, правильный класс первый, $p=(0.8,0.1,0.1)$ и $\epsilon=0.1$. Цель $q=(0.93333,0.03333,0.03333)$. CE без smoothing равна $-\ln0.8=0.22314$. С smoothing: $-0.93333\ln0.8-0.06667\ln0.1\approx0.36177$.

Для binary focal с $p_t=0.9$, $\gamma=2$, $\alpha_t=1$ получаем $0.01\cdot0.10536=0.0010536$. Для трудного примера $p_t=0.2$ — $0.64\cdot1.60944=1.03004$. Простые примеры подавлены сильнее.

Если пропуск дефекта стоит 9 условных единиц, а ложная тревога 1, порог по откалиброванной вероятности равен $1/(1+9)=0.1$. При $p=0.2$ ожидаемые цены 0.8 и 1.8: выбираем проверку дефекта. При изменении prevalence прежняя калибровка требует пересмотра.

## Самопроверка с ответами

**Практика:** при равных ценах порог станет 0.5. Это следствие заданной модели стоимости, а не универсальный default любой системы.

**Изменит ли temperature scaling top-1 accuracy?** При одном положительном $T$ и неизменных правилах tie-breaking — нет.

**Почему высокая AUROC не выбирает порог?** Она агрегирует ранжирование по множеству порогов и не задаёт допустимое число пропусков или ложных тревог.
