## Обучение и перенос: frozen features, fine-tuning и аугментации

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как выбрать между frozen features и полным fine-tuning?

**Уровень:** основа ветки. **Предпосылки:** cv-classification

**Потребители:** cv-contrastive, cv-dino, cv-retrieval, cv-anomaly, cv-robustness, cv-deployment

**Порядок объяснения:**

1. Что переносится.
2. Три режима и состояние модели.
3. Нормировка и аугментации.
4. Разобранный пример: память и сигнал обучения.
5. Ошибки и критерий выбора.
6. Самопроверка с ответами.

**Разобранный пример:** Для 10000 изображений и $D=768$ кеш float32 занимает $10000\cdot768\cdot4=30720000$ байт, примерно 29.30 MiB. Голова на пять классов содержит $768\cdot5+5=3845$ параметров. Это число не включает backbone и optimizer state, если backbone разморожен.

При frozen encoder логиты $z=Wf(x)+b$ дают градиенты $\partial L/\partial W$, но веса $f$ не обновляются. При fine-tuning цепное правило передаёт сигнал через $W$ в $f$. Если linear probe ошибается преимущественно на новой камере, сравнивают контролируемо: тот же split, та же head, размороженная поздняя стадия. Изменение одновременно split и архитектуры не позволяет приписать улучшение fine-tuning.


**Схемы и разбор:** Linear probe: Изображение + preprocessing → Frozen backbone: eval → Кеш N×D, без gradient → Обучаемый linear → K; Fine-tuning: Изображение + аугментации → Обновляемые стадии → Head → task loss → Gradient → head и backbone.

## Loss, дисбаланс, пороги и калибровка в CV

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как связать функцию потерь, дисбаланс и порог принятия решения?

**Уровень:** основа ветки. **Предпосылки:** cv-classification

**Потребители:** cv-diagnosis, cv-robustness, cv-deployment

**Порядок объяснения:**

1. Loss и метрика отвечают на разные вопросы.
2. Дисбаланс и focal loss.
3. Порог и калибровка.
4. Разобранный пример: одна метка, три решения.
5. Самопроверка с ответами.

**Разобранный пример:** Пусть $K=3$, правильный класс первый, $p=(0.8,0.1,0.1)$ и $\epsilon=0.1$. Цель $q=(0.93333,0.03333,0.03333)$. CE без smoothing равна $-\ln0.8=0.22314$. С smoothing: $-0.93333\ln0.8-0.06667\ln0.1\approx0.36177$.

Для binary focal с $p_t=0.9$, $\gamma=2$, $\alpha_t=1$ получаем $0.01\cdot0.10536=0.0010536$. Для трудного примера $p_t=0.2$ — $0.64\cdot1.60944=1.03004$. Простые примеры подавлены сильнее.

Если пропуск дефекта стоит 9 условных единиц, а ложная тревога 1, порог по откалиброванной вероятности равен $1/(1+9)=0.1$. При $p=0.2$ ожидаемые цены 0.8 и 1.8: выбираем проверку дефекта. При изменении prevalence прежняя калибровка требует пересмотра.


**Схемы и разбор:** Обучение: Разметка: single / multi → Logits → softmax / sigmoid → CE / focal / smoothing → Gradient → параметры; Принятие решения: Validation logits → Calibration: выбрать T → Вероятность + цена FP/FN → Порог → ответ / проверка.

## FPN и PAN: многомасштабные представления

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как передать голове одновременно детали и контекст разных масштабов?

**Уровень:** основа ветки. **Предпосылки:** cv-input, cv-classification

**Потребители:** cv-faster-rcnn, cv-dense-detectors, cv-yolo, cv-deformable

**Порядок объяснения:**

1. Почему одной последней карты мало.
2. FPN: lateral и top-down.
3. PAN и варианты слияния.
4. Разобранный пример: согласование карт.
5. Самопроверка с ответами.

**Разобранный пример:** Вход $640\times640$ даёт карты $80\times80$, $40\times40$, $20\times20$. Пусть каналы $256,512,1024$, а lateral width 256. Приведение $C_5$ стоит $1024\cdot256=262144$ весов без bias. После upsampling $20\to40$ обе слагаемые имеют $[B,256,40,40]$; их сумма корректна. При concatenation получится $[B,512,40,40]$.

Число spatial positions: $6400+1600+400=8400$. По 80 class logits на позицию дают 672000 чисел без regression. Добавление уровня stride 4 даёт ещё $160^2=25600$ positions — в три раза больше прежней суммы. Поэтому поддержка маленьких объектов заметно увеличивает память головы.

Если размеры входа нечётные, удвоение ширины верхней карты может не совпасть с lateral. Надёжное правило — интерполировать к точному target size и проверить координатное выравнивание. Half-pixel convention и padding могут сдвинуть привязку головы к исходным пикселям.


**Схемы и разбор:** FPN top-down: C5: 20×20×1024 → 1×1 → M5: 256 → Up + lateral C4 → M4 → Up + lateral C3 → M3; PAN bottom-up: P3: 80×80×256 → Down 2 + merge P4 → Down 2 + merge P5 → Heads на трёх масштабах.

## SimCLR и MoCo: контрастивное обучение изображений

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как обучить encoder на разных видах одного изображения без class labels?

**Уровень:** углубление. **Предпосылки:** cv-transfer

**Потребители:** Самостоятельное применение.

**Порядок объяснения:**

1. Как возникает обучающий сигнал.
2. Objective и смысл temperature.
3. MoCo: очередь и momentum encoder.
4. Разобранный пример: положительная пара и очередь.
5. Проверка представления.
6. Самопроверка с ответами.

**Разобранный пример:** Возьмём одну положительную similarity 0.8 и две отрицательные 0.2 и 0.0 при $\tau=0.2$. Logits: 4,1,0. Вероятность positive $e^4/(e^4+e+1)\approx0.93624$; loss $\approx0.06588$. Если трудный negative имеет similarity 0.7, его logit 3.5: вероятность positive $\approx0.61544$, loss $\approx0.48541$. Даже при прежнем positive ошибка растёт из-за близкого конкурента.

Для скалярного параметра key encoder 2, query encoder 4 и $m=0.9$ новое значение key равно $0.9\cdot2+0.1\cdot4=2.2$. Очередь из 65536 float32 vectors длины 128 занимает $65536\cdot128\cdot4=33554432$ байт, 32 MiB без служебных данных.


**Схемы и разбор:** SimCLR: B изображений → 2B views → Общий f → h; g → z → Normalize → similarities → NT-Xent → gradient f,g; MoCo: Query view → encoder q → Key view → EMA encoder k → Positive + queue negatives → Loss; enqueue / dequeue.

## DINO, DINOv2 и DINOv3: self-distillation и dense features

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как self-distillation учит глобальные и пространственные признаки?

**Уровень:** углубление. **Предпосылки:** cv-vit, cv-transfer

**Потребители:** Самостоятельное применение.

**Порядок объяснения:**

1. Teacher без ручных классов.
2. Почему требуется предотвращать collapse.
3. От DINO к DINOv2 и DINOv3.
4. Разобранный пример: CE и карта признаков.
5. Самопроверка с ответами.

**Разобранный пример:** Teacher выдаёт $(0.8,0.2)$, student $(0.6,0.4)$. Cross-entropy равна $-0.8\ln0.6-0.2\ln0.4\approx0.59192$. При student $(0.8,0.2)$ значение $\approx0.50040$, а не ноль: это энтропия мягкой цели. Для сравнения совпадения распределений можно рассматривать KL, вычитая постоянную энтропию teacher.

Изображение $224\times224$ с patch size 14 даёт $16\cdot16=256$ patch vectors. При $D=768$ spatial representation имеет 196608 чисел. Upsampling logits с $16\times16$ до исходной сетки возвращает размер ответа, но не гарантирует точные контуры объектов меньше patch.


**Схемы и разбор:** Self-distillation: Изображение → разные crops → Student → logits; teacher EMA → Center / sharpen teacher → Cross-entropy → student; Dense readout: Изображение → patch encoder → B×N×D; global / patches → Frozen features → task head → Classes / masks + evaluation.

## Visual retrieval: metric learning и поиск изображений

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как обучить и оценить поиск похожих изображений?

**Уровень:** основа ветки. **Предпосылки:** cv-transfer

**Потребители:** Самостоятельное применение.

**Порядок объяснения:**

1. Сначала определить релевантность.
2. Siamese и metric learning.
3. Индекс, reranking и обновление.
4. Разобранный пример: loss и ranking.
5. Ограничения.
6. Самопроверка с ответами.

**Разобранный пример:** Пусть $a=(0,0)$, $p=(0.3,0.4)$, $n=(0.6,0.8)$ — учебные ненормированные vectors. Squared distances равны 0.25 и 1. При $m=0.5$ loss $\max(0,0.25-1+0.5)=0$. Для negative $(0.4,0.3)$ его squared distance 0.25, и loss станет 0.5. Получение нуля для одной тройки не гарантирует хорошей геометрии всех объектов.

В gallery есть три релевантных объекта; они стоят на местах 1,3,5. Precision в этих местах: $1$, $2/3$, $3/5$. Average Precision $=(1+2/3+3/5)/3\approx0.75556$. Recall@3 $=2/3$. Показатель «есть хотя бы один relevant в top-3» равен 1 и отвечает другому вопросу; в некоторых retrieval benchmarks именно его называют Recall@K, поэтому convention фиксируют явно.


**Схемы и разбор:** Metric learning: Anchor / positive / negative → Общий обучаемый encoder → Embeddings → distances → Triplet loss → gradient; Поиск: Query → encoder v1 → Gallery → тот же encoder v1 → Index → top-K → reranking → Ранжирование → AP / recall.
