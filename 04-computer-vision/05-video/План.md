## HRNet, ViTPose и RTMPose: архитектуры pose estimation

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Чем различаются HRNet, ViTPose и координатная классификация RTMPose?

**Уровень:** углубление. **Предпосылки:** cv-pose, cv-vit

**Потребители:** Самостоятельное применение.

**Порядок объяснения:**

1. Единый контракт, разные представления.
2. HRNet: сохранять высокое разрешение.
3. ViTPose и RTMPose.
4. Разобранный пример: размер выхода и обратная геометрия.
5. Ошибки и выбор.
6. Самопроверка с ответами.

**Разобранный пример:** Crop $192\times256$ pixels, heatmap stride 4: выходные сетки $48\times64$. Для 17 joints нужно $17\cdot48\cdot64=52224$ logits. При SimCC split ratio 2 получаем $L_x=384,L_y=512$, всего $17\cdot896=15232$. Это сравнение output arrays, без backbone и head operations.

Пусть crop начинается в $(100,50)$ исходного кадра и имеет размер $96\times128$, затем увеличен до $192\times256$ без rotation. Predicted point $(60,80)$ соответствует $(100+60/2,50+80/2)=(130,90)$. При rotation нельзя отдельно делить координаты на scale: требуется обратная affine matrix. Для heatmap argmax сначала возвращают точку в координаты model crop согласно принятой convention центров cells.


**Схемы и разбор:** HRNet: Person crop → high-res stem → Параллельные low/high branches → Повторное multi-scale fusion → K heatmaps → inverse affine; ViTPose: Person crop → patches → Plain ViT → patch features → Лёгкий upsampling decoder → K heatmaps → keypoints; RTMPose: Person crop → backbone → Features → SimCC head → K×Lx и K×Ly logits → 1D decoding → keypoints.

## SORT, DeepSORT, ByteTrack и BoT-SORT: разбор последовательности

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как сохранить ID при падении confidence и пересечении траекторий?

**Уровень:** углубление. **Предпосылки:** cv-tracking

**Потребители:** cv-cases

**Порядок объяснения:**

1. Общий detector, разные правила association.
2. DeepSORT, ByteTrack и BoT-SORT.
3. Разобранный пример: три кадра.
4. Состояние и оценка.
5. Самопроверка с ответами.

**Разобранный пример:** Рассмотрим ByteTrack-подобную учебную схему с high threshold 0.6, low threshold 0.1 и IoU gate 0.3. В кадре 1 объект A имеет box $(10,10,30,30)$, score 0.9; создаётся ID 7. Кадр 2: Kalman предсказывает $(12,10,32,30)$, detection $(13,10,33,30)$ имеет score 0.3. Она не участвует в high-score стадии, но её IoU с prediction $380/420\approx0.90476$; low-score association сохраняет ID 7. При отбрасывании всех scores ниже 0.6 track остался бы без observation.

Кадр 3: prediction $(15,10,35,30)$, detection A $(16,10,36,30)$ со score 0.85 и detection B $(60,10,80,30)$ со score 0.9. A имеет высокий IoU и обновляет ID 7; B не проходит motion/overlap для этого track и может создать новый ID. Confidence B выше, но score сам по себе не определяет identity.

Если после долгой окклюзии A и B встречаются близко, motion может стать неоднозначным. Appearance помогает, только если embeddings различают объекты; одинаковая форма, uniform и плохой crop создают риск ID switch. После истечения max age удалённый track не обязан получать прежний ID.


**Схемы и разбор:** SORT / DeepSORT: Detector → boxes / crops → Kalman predict + motion gate → IoU; appearance + cascade → Update ID / lifecycle; ByteTrack / BoT-SORT: Tracks → motion prediction → High-score association → Low-score recovery; camera motion → Matched update / lost / new.

## Optical flow и RAFT: плотное движение

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как RAFT находит перемещение каждого пикселя между двумя кадрами?

**Уровень:** углубление. **Предпосылки:** cv-input, cv-classification

**Потребители:** Самостоятельное применение.

**Порядок объяснения:**

1. Correspondence как поле смещений.
2. RAFT: correlation и recurrent refinement.
3. Loss и допустимые pixels.
4. Разобранный пример: endpoint error и память.
5. Диагностика.
6. Самопроверка с ответами.

**Разобранный пример:** Истинное flow в pixel $(3,4)$, prediction $(1,5)$. Endpoint error, EPE, равна $\sqrt{(1-3)^2+(5-4)^2}=\sqrt5\approx2.23607$ pixels. Для трёх valid pixels с EPE 1,2,3 mean EPE равна 2. Если четвёртый pixel invalid, он не должен добавлять нулевую ошибку и уменьшать среднее до 1.5.

На входе $512\times512$ с feature stride 8 получаем $64\times64=4096$ positions. All-pairs volume содержит $4096^2=16777216$ scalars, 64 MiB float32 до pyramid и gradient buffers. При удвоении обеих сторон входа positions вырастут вчетверо, correlation — в 16 раз. Это важный предел даже при малом recurrent block.

Для prediction low-resolution flow $(2,-1)$ в units feature cells stride 8 full-image displacement соответствует $(16,-8)$ pixels. Resize grid без корректного масштабирования vectors даёт геометрически неверный ответ.


**Схемы и разбор:** RAFT features: Два кадра I1, I2 → Feature encoders → F1,F2 → All-pairs correlation + pyramid → Context encoder → hidden state; Iterative update: Flow estimate f → Lookup around correspondences → Recurrent block → Δf → f + Δf → learned upsampling.

## Video understanding: 3D CNN, SlowFast, TimeSformer и VideoMAE

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как модель использует время и почему выбор кадров входит в постановку?

**Уровень:** углубление. **Предпосылки:** cv-vit, cv-pretraining

**Потребители:** Самостоятельное применение.

**Порядок объяснения:**

1. Вход — временное наблюдение.
2. 3D CNN и SlowFast.
3. TimeSformer и VideoMAE.
4. Обучение, применение и утечки.
5. Разобранный пример: цена attention и длительность.
6. Самопроверка с ответами.

**Разобранный пример:** Для $T=8$, $H=W=224$, patch size 16 имеем $N=14^2=196$, всего 1568 tokens без CLS. Joint attention содержит $1568^2=2458624$ scores на head. Divided attention приблизительно использует $N T^2+T N^2=12544+307328=319872$ scores. Это оценка attention matrices без projections, CLS и конкретного implementation overhead.

При 30 FPS и 16 samples с шагом 4 расстояние между первым и последним кадром $(16-1)\cdot4/30=2$ seconds. Сам clip не равен 16/30 seconds. Если действие занимает 0.1 seconds, такой sparse sampling способен полностью его пропустить.


**Схемы и разбор:** SlowFast: Одно видео → два sampling → Slow: редкие; Fast: частые → 3D blocks + lateral fusion → Pooling → action logits; TimeSformer: T кадров → spatial patches → Temporal attention по позиции → Spatial attention по кадру → Aggregation → action logits; VideoMAE: Видео → tubelet tokens → Tube mask → visible encoder → Decoder + masked positions → Reconstruction loss → transfer.
