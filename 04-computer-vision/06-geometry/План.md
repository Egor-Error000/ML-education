## Камера и геометрия: проекция, координаты и калибровка

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как связать пиксели, координаты камеры и точки сцены?

**Уровень:** основа ветки. **Предпосылки:** cv-input

**Потребители:** cv-stereo, cv-depth, cv-sfm, cv-pointnet, cv-nerf, cv-domains

**Порядок объяснения:**

1. Три системы координат.
2. Матрица и обратное преобразование.
3. Resize, crop и глубина.
4. Разобранный пример: projection и backprojection.
5. Ошибки применения.
6. Самопроверка с ответами.

**Разобранный пример:** Пусть $f_x=f_y=800$, $(c_x,c_y)=(320,240)$, point в camera coordinates $(1,0.5,4)$ metres. Тогда $u=800/4+320=520$, $v=800\cdot0.5/4+240=340$. Обратный путь: $X=(520-320)\cdot4/800=1$, $Y=(340-240)\cdot4/800=0.5$.

Range равен $\sqrt{1^2+0.5^2+4^2}=\sqrt{17.25}\approx4.15331$ m, хотя depth $Z=4$ m. После resize вдвое intrinsics становятся $(400,400,160,120)$, point проецируется в $(260,170)$. Если сохранить прежнюю $K$, восстановленная геометрия будет неверной.


**Схемы и разбор:** Projection: World point Xw: metres → Extrinsics: Xc = R Xw + t → Perspective divide X/Z,Y/Z → Intrinsics K → pixel u,v; Backprojection: Pixel + axial depth Z → K inverse → camera ray → Умножение на depth Z → Inverse extrinsics → world.

## Стереозрение: disparity, cost volume и погрешность глубины

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как disparity превращается в глубину и почему дальние точки менее точны?

**Уровень:** основа ветки. **Предпосылки:** cv-camera

**Потребители:** Самостоятельное применение.

**Порядок объяснения:**

1. Геометрия rectified пары.
2. От matching cost к cost volume.
3. Разобранный пример: глубина и неопределённость.
4. Сложные случаи.
5. Самопроверка с ответами.

**Разобранный пример:** Пусть $f=800$ pixels, $B=0.12$ m. При $d=40$ pixels глубина $96/40=2.4$ m. Ошибка $\Delta d=1$ pixel даёт локальную оценку $|\Delta Z|\approx fB\,|\Delta d|/d^2=96/1600=0.06$ m. При $d=4$ получаем $Z=24$ m и линейную оценку 6 m. Точное значение при $d=5$ равно 19.2 m: для большой относительной ошибки linear approximation уже неточна.

Distribution по disparities 2,3,4 имеет probabilities 0.2,0.5,0.3. Soft argmin даёт $0.4+1.5+1.2=3.1$ pixels. При $fB=96$ глубина 30.96774 m. Среднее depth по трём hypotheses было бы $0.2\cdot48+0.5\cdot32+0.3\cdot24=32.8$ m. Из-за нелинейности inverse disparity эти усреднения различаются.

Для volume $D=192,H=128,W=256$ нужно 6291456 scalar costs, 24 MiB float32. Feature concatenation с дополнительным channel dimension увеличивает память ещё сильнее; 3D CNN добавляет activations и gradient buffers.


**Схемы и разбор:** Stereo geometry: Calibrated left / right → Rectification → common rows → Match → disparity d pixels → Z = f B / d metres; PSMNet: Shared image features + SPP → Disparity cost volume → 3D CNN regularization → Soft argmin → disparity.

## Feature matching, SfM и SLAM: восстановление сцены и движения

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как из нескольких изображений восстановить камеры и разреженную сцену?

**Уровень:** углубление. **Предпосылки:** cv-camera, cv-classical

**Потребители:** Самостоятельное применение.

**Порядок объяснения:**

1. Matching не равен reconstruction.
2. От двух видов к общей сцене.
3. SfM и SLAM.
4. Разобранный пример: reprojection и scale.
5. Диагностика.
6. Самопроверка с ответами.

**Разобранный пример:** В camera frame point $(1,0,5)$ при $f_x=500,c_x=320$ проецируется в $u=420$. Observation равна 422, residual prediction-minus-observation $-2$ pixels, squared contribution 4. Для второй observation residual 3 даёт суммарно 13 до robust weighting. Это ошибка изображения; она не задаёт однозначную ошибку в metres.

Если все camera translations и scene points увеличить вдвое, projected ratios $X/Z$ и $Y/Z$ сохраняются. Поэтому обычные monocular images не отличают модель комнаты в metres от модели в удвоенных единицах. Известная baseline, размер объекта или calibrated inertial constraints могут добавить scale information, но должны присутствовать в постановке.


**Схемы и разбор:** Incremental SfM: Images → keypoints / matching → RANSAC → relative geometry → Triangulate → register cameras → Bundle adjustment → sparse map; SLAM: Новый frame / sensor data → Tracking → current pose → Local map + keyframes → Loop closure → map correction.

## PointNet и PointNet++: обучение на множествах точек

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как сеть обрабатывает облако точек без заданного порядка?

**Уровень:** углубление. **Предпосылки:** cv-camera, cv-classification

**Потребители:** cv-bev

**Порядок объяснения:**

1. Множество вместо grid.
2. PointNet.
3. PointNet++.
4. Разобранный пример: symmetric aggregation.
5. Ошибки и выбор.
6. Самопроверка с ответами.

**Разобранный пример:** Три point features: $(1,4)$, $(3,2)$, $(2,5)$. Max pooling даёт $(3,5)$. После любой перестановки результат тот же. Ни одна отдельная точка не имела vector $(3,5)$: global representation собирает компоненты разных points. Добавление point $(0,0)$ ничего не меняет, а outlier с feature $(100,0)$ меняет первую координату на 100. Invariance к порядку не равна устойчивости ко всем выбросам.

Для 1024 points и $D=64$ shared features содержат 65536 numbers. Повторённый global vector длины 1024 для каждой точки создаёт $1024^2=1048576$ values перед segmentation head. Локальная hierarchy уменьшает число centers на поздних stages, но grouping и nearest neighbour search тоже стоят времени и памяти.


**Схемы и разбор:** PointNet: N×3 points: unordered → Shared MLP → N×D → Symmetric max → global D → Class head / point-wise head; PointNet++: Points + features → Sample centers → group neighbours → Local PointNet → hierarchy → Feature propagation → labels.

**Разобранный пример:** Область $x\in[0,70.4)$ m, $y\in[-40,40)$ m и cell size 0.2 m даёт $352\times400=140800$ pillars. Point $(10.1,-3.9,1.2)$ имеет индексы $i_x=\lfloor10.1/0.2\rfloor=50$, $i_y=\lfloor36.1/0.2\rfloor=180$. Индексация должна учитывать выбранные axis order и half-open bounds.

При 64 features это уже 360448000 values, 1375 MiB без intermediate tensors. Sparse methods экономят пустые cells, поэтому сравнение с dense baseline не описывает их полную стоимость.

## NeRF: лучи, radiance field и volume rendering

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как обучить представление сцены по фотографиям и отрисовать новый вид?

**Уровень:** углубление. **Предпосылки:** cv-camera, cv-classification

**Потребители:** cv-gaussians

**Порядок объяснения:**

1. Scene representation вместо classifier.

3. Обучение и применение.
4. Разобранный пример: compositing двух samples.

**Разобранный пример:** Два samples имеют $\alpha_1=0.5$, $\alpha_2=0.25$, scalar colours 0.8 и 0.2. $T_1=1$, $T_2=1-0.5=0.5$. Weights: 0.5 и 0.125. Foreground contribution $0.5\cdot0.8+0.125\cdot0.2=0.425$. Remaining transmittance $0.5\cdot0.75=0.375$. При белом background полный colour равен 0.8, при чёрном — 0.425.

Если $\delta=0.1$ m и $\alpha=0.5$, density $\sigma=-\ln(1-0.5)/0.1\approx6.93147$ m$^{-1}$. Для $800\times800$ pixels и 128 samples на ray требуется 81920000 field evaluations до дополнительных coarse passes. Это объясняет цену naive rendering.


**Схемы и разбор:** NeRF field: Position x + direction d → Positional encoding → MLP → Density σ(x), colour c(x,d) → Обучаемое поле одной сцены; Rendering / training: Camera pose → pixel ray → Coarse / fine ray samples → Transmittance → weighted RGB → Image MSE → field gradients.

## 3D Gaussian Splatting: проекция, compositing и densification

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как явные 3D Gaussian primitives заменяют многократные запросы neural field?

**Уровень:** углубление. **Предпосылки:** cv-nerf

**Потребители:** Самостоятельное применение.

**Порядок объяснения:**

1. Явное представление сцены.
2. Covariance и проекция.
3. Оптимизация и densification.
4. Разобранный пример: compositing и память.
5. Сравнение с NeRF.
6. Самопроверка с ответами.

**Разобранный пример:** Пусть два projected primitives на pixel дают $\alpha_1=0.6$, $\alpha_2=0.5$ и scalar colours 1 и 0.2. Первый вклад 0.6. Transmittance перед вторым 0.4, второй вклад $0.4\cdot0.5\cdot0.2=0.04$. Black-background output 0.64. В обратном порядке получаем $0.5\cdot0.2+0.5\cdot0.6\cdot1=0.4$. Depth order существенно меняет изображение.

Для учебной записи с 3 mean, 3 scales, 4 quaternion rotation, 1 opacity и 48 colour coefficients нужно 59 float32 values на primitive, 236 bytes. Для миллиона primitives — 236000000 bytes, примерно 225.07 MiB только параметров. Optimizer states, gradients, sorting и rasterization buffers добавляются отдельно. Это объясняет, почему высокая скорость rendering не означает малую память обучения.


**Схемы и разбор:** 3DGS optimization: SfM points + camera poses → Means / scales / rotations / SH → Differentiable splat renderer → Photo loss → densify / prune; Rendering: 3D Gaussians + new camera → Project covariance → 2D ellipse → Tile binning + depth ordering → Alpha compositing → RGB.
