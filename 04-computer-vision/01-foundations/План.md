## Классическое CV: фильтры, границы, морфология, HOG и SIFT

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Когда фиксированные признаки полезнее обучения большой сети?

**Уровень:** углубление. **Предпосылки:** cv-input

**Потребители:** cv-sfm

**Порядок объяснения:**

1. От пикселей к измеряемому признаку.
2. Фильтрация, границы и морфология.
3. HOG и SIFT: два разных представления.
4. Разобранный пример: нормировка и геометрическая проверка.
5. Выбор и границы.
6. Самопроверка с ответами.

**Разобранный пример:** Для изображения $64\times128$, ячейки $8\times8$ образуют сетку $8\times16$. Блок $2\times2$ со сдвигом в одну ячейку занимает $7\times15=105$ положений. При девяти направлениях каждый блок имеет $4\cdot9=36$ компонент: вектор HOG содержит $105\cdot36=3780$ чисел. Это учебная конфигурация без дополнительных border effects.

Для SIFT пусть расстояния до двух ближайших дескрипторов равны 0.3 и 0.8. Их отношение 0.375; при выбранном на validation пороге 0.75 пара проходит первичный фильтр. Пара с расстояниями 0.3 и 0.35 имеет отношение 0.857 и отвергается как неоднозначная. Даже прошедшие пары проверяют геометрически: RANSAC ищет согласованную модель преобразования и отделяет выбросы.


**Схемы и разбор:** HOG + classifier: Изображение 64×128 → Градиенты → ячейки 8×16 → Блоки → вектор 3780 → Обучаемый SVM → класс; SIFT matching: Два изображения → Scale-space → keypoints → Дескрипторы → пары → RANSAC → геометрия.

## ResNet: residual-блоки, projection и градиенты

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Как residual-связь меняет вычисление и прохождение градиента?

**Уровень:** углубление. **Предпосылки:** cv-classification

**Потребители:** cv-efficient, cv-convnext

**Порядок объяснения:**

1. Проблема глубины.
2. Basic block и bottleneck.
3. Градиент и выход всей модели.
4. Разобранный пример: формы и число весов.
5. Стоимость и типичные ошибки.
6. Самопроверка с ответами.

**Разобранный пример:** Вход $[1,64,56,56]$. Две свёртки $3\times3$, 64 входных и выходных канала, stride 1 и padding 1 сохраняют форму. Без bias и параметров нормировки нужно $2\cdot9\cdot64^2=73728$ весов. Сложение требует точно такую же форму shortcut.

Для перехода к $[1,128,28,28]$ первая свёртка использует stride 2, а shortcut — projection $1\times1$, $64\to128$, stride 2. В projection $64\cdot128=8192$ весов. Попытка сложить с исходным $[1,64,56,56]$ некорректна.

В скалярном примере $F(x)=0.2x$, $x=3$: сумма равна 3.6. Если производная loss по выходу равна 2, до нелинейности градиент входа $2(1+0.2)=2.4$, из которых 2 приходят через shortcut.


**Схемы и разбор:** Residual block: x: B×64×56×56 → F: 3×3 → 3×3 → F(x) + shortcut x → ReLU → B×64×56×56; Смена стадии: x: B×64×56×56 → F stride 2; P: 1×1/2 → Сложение F(x) + P(x) → B×128×28×28.

**Разобранный пример:** Пусть $H=W=28$, $C_i=32$, $C_o=64$, $k=3$. Полная свёртка: $784\cdot9\cdot32\cdot64=14450688$ MAC. Depthwise: $784\cdot9\cdot32=225792$. Pointwise: $784\cdot32\cdot64=1605632$. Итого 1831424 MAC, примерно в 7.89 раза меньше. Это сравнение одной факторизованной операции, не полного MBConv: expansion тоже стоит вычислений.

При одновременном увеличении ширины в 1.2 раза и разрешения в 1.25 раза оценка затрат обычных свёрток растёт в $1.2^2\cdot1.25^2=2.25$ раза. Удвоить оба параметра означает примерно 16-кратный рост, даже без увеличения глубины.


**Схемы и разбор:** MobileNetV2: Узкий вход C → 1×1 expand → tC → Depthwise k×k → Linear 1×1 → C; +x; EfficientNet MBConv: Карта H×W×C → Expansion + depthwise → SE: pooling → gates → Projection → task head.

## ConvNeXt: современная свёрточная архитектура

**Статус сценария:** authored — расширение CV; приёмка текста отдельно

**Учебный вопрос:** Какие изменения позволяют CNN использовать идеи дизайна Transformer?

**Порядок объяснения:**

6. Самопроверка с ответами.

**Разобранный пример:** При $C=96$ depthwise имеет $49\cdot96=4704$ веса. Две pointwise-проекции: $96\cdot384+384\cdot96=73728$. Вместе 78432 веса без bias, norm и layer scale. Значит, несмотря на большой spatial kernel, в этом блоке большая часть весов находится в смешивании каналов.

Для четырёх стадий с базой 96 получаем $56^2\times96$, $28^2\times192$, $14^2\times384$, $7^2\times768$. Число активаций первой карты 301056, последней 37632. Удвоение входного разрешения при прежних stride увеличит площади примерно вчетверо. Последняя сетка перестанет быть $7\times7$, но pooling по пространству всё ещё даст вектор из 768 признаков.


**Схемы и разбор:** ConvNeXt backbone: B×3×224×224 → Stem 4/4 → 56×56×96 → Стадии → 7×7×768 → Pooling → logits B×K; Residual block: Карта H×W×C → DW 7×7 → LayerNorm → C → 4C → GELU → C → Layer scale → + shortcut.

### Расширение и продолжения

**Учебный вопрос:** Как окна и patch merging создают пространственную иерархию?

**Уровень:** углубление. **Предпосылки:** cv-vit

**Потребители:** Самостоятельное применение.

**Порядок объяснения:**

1. Как читать углубления этой ветки.
2. Разобранный пример для проверки контракта.
3. Ограничения переноса.
4. Самопроверка с ответами.

**Разобранный пример:**
Для сетки $56\times56$ и windows $7\times7$ имеется $8^2=64$ окна по 49 tokens. Attention scores на head: $64\cdot49^2=153664$ против $3136^2=9834496$ для полного внимания — в 64 раза меньше. Patch merging $2\times2$ переводит grid в $28\times28$; concatenation четырёх vectors ширины $C$ даёт $4C$, projection может уменьшить до $2C$.


**Схемы и разбор:** Swin stages: Patch grid H×W×C → W-MSA → shifted W-MSA → Mask для cyclic boundaries → Patch merge → H/2×W/2×2C.

**Практика и проверка:** вопросы и объяснения ответов находятся в главе. Изменение одного фактора разобрано в разделе самопроверки.

**Ограничения:** см. раздел границ, диагностики или выбора в главе.

**Критерий понимания:** объяснить вычислительный путь, воспроизвести расчёт и назвать условие, при котором вывод перестанет быть верным.
