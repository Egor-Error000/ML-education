
# План: Задачи Computer Vision — от постановки задачи к архитектурам

Принцип для каждой задачи: **сначала задача в отрыве от моделей** (что это, как
формально ставится, как измеряется, какие классические/базовые подходы) →
**потом архитектуры**, решающие эту задачу, с объяснением механики, включая
соответствующую голову/версию YOLO и 1-2 альтернативных подхода для контраста.

Порядок задач подобран по нарастанию сложности и с учётом зависимостей (каждая
следующая опирается на понятия из предыдущей).

---

## 1. Image Classification

*(Скорее всего уже знакомо через ваш SSL-проект — короткое повторение / фундамент для остального.)*

**Задача в отрыве от моделей:**
- Постановка: один label на изображение, no localization
- Метрики: accuracy, top-5 accuracy, confusion matrix, precision/recall/F1 по классам
- Базовые подходы: kNN на пикселях/эмбеддингах, простой MLP, лишь затем CNN

**Архитектуры:**
- Классический CNN pipeline: conv → pooling → FC (LeNet/AlexNet как исторический ориентир)
- ResNet — skip-connections, почему они решают vanishing gradient
- YOLO classification head — чем отличается/не отличается от "чистого" классификатора
- ViT (Vision Transformer) — для контраста CNN vs attention-based подход

---

## 2. Object Detection

**Задача в отрыве от моделей:**
- Постановка: множество объектов, каждому — bbox + класс + confidence
- Формат разметки: COCO/VOC/YOLO-форматы (уже разбирали в контексте данных)
- Метрики: IoU (Intersection over Union), precision/recall, **mAP** (mean Average
  Precision) — разобрать по шагам, как считается: IoU-порог → TP/FP/FN → precision-recall
  curve → AP → усреднение по классам
- Проблема дубликатов предсказаний → зачем нужен NMS (Non-Maximum Suppression),
  как работает алгоритмически, до знакомства с NMS-free моделями

**Классические подходы (до deep learning эры / ранний DL):**
- Sliding window + классификатор (исторический baseline, почему медленно)
- Two-stage: R-CNN → Fast R-CNN → Faster R-CNN (region proposal + классификация
  отдельно) — важно понять как контраст к one-stage
- One-stage: сама идея YOLO / SSD — почему это было прорывом по скорости

**Архитектуры (в хронологии, которую уже прошли вширь):**
- YOLOv1-v3: anchor-based эволюция, multi-scale prediction
- YOLOv8: anchor-free детекция, decoupled head
- YOLOv10/26: NMS-free подход — механика dual label assignment
- Альтернатива для контраста: RT-DETR (transformer-based detection, без anchor
  и без NMS изначально по другой причине, чем YOLO)

---

## 3. Semantic Segmentation

**Задача в отрыве от моделей:**
- Постановка: pixel-wise классификация, каждый пиксель → класс, без разделения
  на экземпляры
- Метрики: pixel accuracy, **IoU/Jaccard по классам**, mean IoU (mIoU) — главная
  метрика в сегментации
- Формат разметки: маски (обычно PNG с индексами классов на пиксель), отличие
  от bbox-разметки detection

**Архитектуры:**
- FCN (Fully Convolutional Network) — базовая идея: замена FC-слоёв на conv,
  чтобы сохранить пространственную структуру
- U-Net — encoder-decoder со skip-connections, почему это стало стандартом
  (особенно в медицине)
- DeepLab — atrous/dilated convolution, зачем нужно расширенное рецептивное поле
  без потери разрешения
- YOLO26 semantic segmentation head — как урезанная/интегрированная версия
  этих идей внутри единого фреймворка

---

## 4. Instance Segmentation

*(Идёт после semantic segmentation и object detection, т.к. это их пересечение.)*

**Задача в отрыве от моделей:**
- Постановка: bbox/маска + класс **для каждого экземпляра** отдельно, даже
  внутри одного класса
- Метрики: тот же mAP, что и в detection, но посчитанный по IoU масок, а не bbox
- Концептуальная сложность: как разделить два перекрывающихся объекта одного класса

**Архитектуры:**
- Mask R-CNN — как естественное расширение Faster R-CNN (детекция + segmentation
  head поверх ROI)
- YOLACT — one-stage подход к instance segmentation (прототипные маски +
  коэффициенты, идея ближе к YOLO-философии скорости)
- YOLOv8/YOLO11 instance segmentation head — как это встроено в unified-архитектуру

---

## 5. Pose Estimation / Keypoint Detection

**Задача в отрыве от моделей:**
- Постановка: N заданных keypoint'ов на объекте (скелет), не произвольная форма
- Метрики: **OKS** (Object Keypoint Similarity) — аналог IoU, но для точек с
  учётом их видимости/масштаба; PCK (Percentage of Correct Keypoints)
- Top-down vs bottom-up подход: сначала найти человека, потом keypoints внутри
  bbox (top-down) — или сначала найти все keypoints на картинке, потом
  сгруппировать их по людям (bottom-up). Это ключевая архитектурная развилка,
  важно понять её до конкретных моделей.

**Архитектуры:**
- OpenPose — классический bottom-up подход (part affinity fields)
- HRNet — почему сохранение высокого разрешения через всю сеть критично для
  точной локализации точек
- YOLOv8/11 pose head — top-down в едином проходе, как это устроено конкретно

---

## 6. Oriented Bounding Box (OBB) Detection

**Задача в отрыве от моделей:**
- Постановка: bbox + угол поворота (обычно 5 параметров: x, y, w, h, θ вместо 4)
- Почему обычный axis-aligned bbox неприменим: примеры с аэроснимками
  (корабли/самолёты под углом) — bbox захватывает избыточный фон, IoU с истинным
  объектом занижен
- Метрики: modified IoU с учётом поворота (rotated IoU) — сложнее вычисляется,
  чем обычный IoU

**Архитектуры:**
- Ранние подходы к rotated detection в аэрокосмических данных (до YOLO-эры)
- YOLOv8/11 OBB head — как angle предсказывается дополнительным параметром
- Проблема periodicity угла (0° и 180° могут визуально совпадать для
  симметричных объектов) и как её обходят в loss-функции

---

## 7. Multi-Object Tracking (MOT)

**Задача в отрыве от моделей:**
- Постановка: не разовая детекция, а сохранение identity объекта через
  последовательность кадров
- Проблемы: occlusion (временное перекрытие), id-switch (потеря идентичности),
  re-identification после долгого исчезновения из кадра
- Метрики: **MOTA** (Multi-Object Tracking Accuracy), **IDF1** — понять, почему
  простого accuracy на кадр недостаточно для видео-задачи

**Архитектуры / алгоритмы:**
- Разделение на два слоя: detector (YOLO) + association-алгоритм — это не одна
  модель, а pipeline
- SORT / DeepSORT — Kalman filter + IoU-matching, базовый classic подход
- ByteTrack / BoT-SORT — что используется в связке с YOLOv8/11/26 сейчас, чем
  отличается от DeepSORT

---

## 8. Depth Estimation

**Задача в отрыве от моделей:**
- Постановка: monocular depth estimation — предсказать расстояние до камеры по
  одному 2D-изображению (принципиально ill-posed задача без стерео/LiDAR)
- Метрики: RMSE, Abs Relative Error на глубине — регрессионные метрики, не
  detection-метрики
- Почему это вообще возможно из одной картинки: модель учится на монокулярных
  cues (перспектива, относительный размер, текстура) — важно понять эту
  предпосылку до архитектур

**Архитектуры:**
- MiDaS / DPT — специализированные модели для monocular depth, transformer-based
- YOLO26 depth estimation head — как интегрировано в единый фреймворк, на каких
  данных предобучено (NYU Depth V2 и т.д.)

---

## 9. Open-Vocabulary Detection

*(Последнее в списке — требует понимания object detection (п.2) и базового
знакомства с text-image моделями типа CLIP.)*

**Задача в отрыве от моделей:**
- Постановка: детекция по произвольному текстовому запросу класса, не
  зафиксированному в train
- Зачем: не нужно переобучать модель под каждый новый набор классов
- Принципиальная идея: совмещение visual embedding space и text embedding space
  (тот же принцип, что в CLIP — притягивание похожих по смыслу изображения и текста)

**Архитектуры:**
- CLIP как база — короткое напоминание механики contrastive image-text обучения
  (перекликается с вашим SSL-проектом, только модальности разные)
- YOLO-World — как совмещает YOLO-детектор с текстовым энкодером
- YOLO26 open-vocabulary версия

3. Базовые подходы

Часть B. Архитектуры
1. Классический CNN pipeline

    Слой: conv -> BN -> ReLU -> pooling.

    Conv: local receptive field, weight sharing. Формула: (f * x)[i,j] = Σ_{m,n} w[m,n] x[i+m,j+n] + b. Выход: feature map.

    Pooling: max/avg, уменьшает разрешение, даёт локальную инвариантность.

    Иерархия: края -> текстуры -> части -> объекты.

    В конце: global average pooling или flatten -> FC -> softmax.

    LeNet-5: 2 conv, pool, FC, 10 классов, digit recognition.

    AlexNet: глубже, ReLU, dropout, augmentation, GPU. Победа ImageNet 2012.

    VGG: 3x3 conv стеки, глубина.

    Inception/GoogLeNet: multi-scale.

    EfficientNet: compound scaling.

    Обучение: CE, SGD/Adam, augmentation (crop, flip, color jitter, mixup/cutmix), weight decay, dropout, BN.

    Плюсы: inductive bias locality, translation equivariance, параметры эффективны. Минусы: ограниченный глобальный контекст (решается attention/большими рецептивными полями).

2. ResNet

    Проблема: с глубиной ошибка растёт не из-за переобучения, а из-за оптимизации: vanishing/exploding gradients, degradation.

    Residual block: y = F(x, W) + x. Если размерности не совпадают, проекция W_s x.

    F учит "остаток" относительно identity. Легче учить близко к нулю, чем полное преобразование.

    Градиент: ∂L/∂x = ∂L/∂y (1 + ∂F/∂x). Даже если ∂F мало, градиент не затухает благодаря 1.

    Bottleneck: 1x1 -> 3x3 -> 1x1 для экономии.

    Варианты: ResNet-18/34/50/101/152. BN после conv.

    Итог: позволил очень глубокие сети, стал backbone для detection/segmentation.

3. YOLO classification head

    YOLO обычно detection. Но в Ultralytics есть YOLOv8/11/26-cls.

    Архитектура: backbone (CSPDarknet/C2f/SPPF) -> classification head: Conv -> AdaptiveAvgPool -> Dropout -> Linear -> K logits.

    Отличие от detection head: detection предсказывает для каждой spatial location/anchor класс + bbox; classification model предсказывает один глобальный класс на изображение.

    Отличие от "чистого" классификатора: тот же фреймворк, backbone, training pipeline, augmentations, export. Но по сути это обычный CNN-классификатор с GAP+FC.

    Зачем: единый API, предобученные веса, удобно сравнивать, использовать backbone для других задач.

    Не путать: classification head внутри detection (ветка cls) и отдельная YOLO-cls модель.

4. ViT (Vision Transformer)

    Идея: изображение как последовательность патчей.

    Patch embedding: x ∈ R^{H×W×C} -> N = HW/P^2 патчей P×P. Каждый flatten -> линейная проекция в D. + positional embedding. + [CLS] token.

    Transformer encoder: L блоков. В каждом: LayerNorm -> Multi-Head Self-Attention -> residual -> LayerNorm -> MLP (GELU) -> residual.

    Self-attention: Q,K,V. Attention(Q,K,V)=softmax(QK^T/√d_k)V. Все патчи могут взаимодействовать сразу, глобальный контекст с первого слоя.

    Классификация: голова на [CLS] или mean-pool патчей -> Linear -> K.

    Contrast with CNN:

        CNN: locality, translation equivariance, weight sharing — встроены. Хорошо работает на малых данных.

        ViT: меньше inductive bias, нужно много данных или сильная аугментация/предобучение (JFT, ImageNet-21k, MAE, DINO). Зато лучше масштабируется, глобальные зависимости.

    Гибриды: Swin (оконное внимание, иерархия), ConvNeXt (CNN с дизайном в духе трансформеров). DeiT — distillation для данных.

    Итог: для классификации сейчас часто CNN (EfficientNet/ConvNeXt) или ViT/Swin в зависимости от данных и ресурсов.

1. Image Classification
A. Задача в отрыве от моделей
1.1. Постановка

Image Classification — это задача, где модели нужно по изображению выдать один класс (или вероятности по классам), без указания местоположения объекта.

Формально:

    Вход: изображение x∈RH×W×Cx∈RH×W×C.

    Выход: класс y∈{1,…,K}y∈{1,…,K}, где KK — число классов.

    Модель учит функцию fθ:X→Yfθ​:X→Y.

    Обычно модель выдаёт вектор логитов z∈RKz∈RK, затем вероятности:
    pθ(y=k∣x)=exp⁡(zk)∑j=1Kexp⁡(zj)
    pθ​(y=k∣x)=∑j=1K​exp(zj​)exp(zk​)​

    для взаимоисключающих классов.

    Решение на инференсе:
    y^=arg⁡max⁡kpθ(k∣x)
    y^​=argkmax​pθ​(k∣x)

Обучение:

    Датасет: D={(xi,yi)}i=1ND={(xi​,yi​)}i=1N​.

    Функция потерь — кросс-энтропия:
    L=−1N∑i=1Nlog⁡pθ(yi∣xi)
    L=−N1​i=1∑N​logpθ​(yi​∣xi​)

    Оптимизация: SGD/Adam + backpropagation.

Важно: в классификации нет bbox, масок, ключевых точек. Модель отвечает только за глобальное семантическое содержание изображения: «что здесь изображено в целом?».

Если классов может быть несколько одновременно, это уже multi-label classification: тогда используют сигмоиду на каждый класс и binary cross-entropy. Но в базовой постановке из плана — один label на изображение.
1.2. Метрики

Главные метрики:

    Accuracy — доля правильных ответов:
    Accuracy=число правильных предсказанийвсего примеров
    Accuracy=всего примеровчисло правильных предсказаний​

    Top-k accuracy — правильным считается ответ, если истинный класс попал в top-k предсказаний. Часто используют top-5 accuracy на ImageNet:

        модель выдаёт 5 наиболее вероятных классов;

        если истинный класс среди них — пример засчитан.

    Confusion matrix — матрица K×KK×K:

        строки — истинные классы;

        столбцы — предсказанные;

        диагональ — правильные ответы;

        вне диагонали — какие классы модель путает.

    Precision / Recall / F1 по классам:

        Precision: TPTP+FPTP+FPTP​ — насколько модель точна, когда говорит «это класс k».

        Recall: TPTP+FNTP+FNTP​ — какую долю объектов класса k модель нашла.

        F1: 2⋅P⋅RP+R2⋅P+RP⋅R​.

        Для многоклассовой задачи считают per-class, затем усредняют:

            macro-F1 — среднее по классам, все классы равны;

            micro-F1 — агрегирует TP/FP/FN по всем классам;

            weighted-F1 — среднее с учётом размера класса.

    Для бинарной классификации дополнительно смотрят ROC-AUC и PR-AUC, особенно при дисбалансе.

Почему accuracy может обманывать: если 99% примеров — класс «фон», модель, всегда предсказывающая «фон», получит 99% accuracy, но не будет решать задачу.
1.3. Базовые подходы до CNN

    kNN на пикселях:

        изображение разворачивают в вектор;

        сравнивают по L2 или косинусу;

        минусы: проклятие размерности, нет инвариантности к сдвигу, масштабу, освещению.

    kNN на эмбеддингах:

        берут предобученную CNN/CLIP;

        извлекают эмбеддинг;

        обучают kNN или линейный классификатор.

        Это сильный простой baseline, но не самостоятельная архитектура.

    Классические признаки + SVM:

        HOG, SIFT, LBP, цветовые гистограммы;

        затем SVM или Random Forest.

        Исторически работало, но уступает CNN.

    MLP на пикселях:

        flatten изображения → полносвязные слои → softmax.

        Проблемы: огромное число параметров, нет локальности и weight sharing, сильное переобучение.

        Пример: изображение 224×224×3224×224×3 — это 150 528 входов. Первый скрытый слой на 1000 нейронов даст ~150 млн параметров.

Вывод: нужна архитектура, которая использует локальность, разделяемые веса и иерархию признаков. Это и есть CNN.
B. Архитектуры
2.1. Классический CNN pipeline

Базовая схема:
Conv→BN→ReLU→Pool→⋯→FC→Softmax
Conv→BN→ReLU→Pool→⋯→FC→Softmax

Ключевые идеи:

    Локальное рецептивное поле: нейрон смотрит не на всё изображение, а на небольшой участок.

    Weight sharing: один и тот же фильтр применяется по всей картинке.

    Translation equivariance: сдвиг объекта на входе приводит к сдвигу карты признаков.

    Pooling даёт локальную инвариантность и уменьшает разрешение.

    Иерархия признаков:

        ранние слои — края, углы, цвета;

        средние — текстуры, части объектов;

        глубокие — объекты и сцены.

Формула свёртки:
yi,j,k=ϕ(∑c,m,nwk,c,m,n⋅xc,i+m,j+n+bk)
yi,j,k​=ϕ(c,m,n∑​wk,c,m,n​⋅xc,i+m,j+n​+bk​)

где ww — ядро свёртки, cc — входной канал, kk — выходной канал.

Исторические ориентиры:

    LeNet-5 (1998): 2 свёрточных слоя + pooling + FC. Распознавание цифр.

    AlexNet (2012): глубже, ReLU, dropout, data augmentation, обучение на GPU. Победа на ImageNet.

    VGG: стек 3×3 свёрток, показал важность глубины.

    Inception/GoogLeNet: multi-scale ветки.

    EfficientNet: compound scaling глубины, ширины и разрешения.

Обучение CNN:

    loss: cross-entropy;

    оптимизаторы: SGD + momentum, Adam;

    регуляризация: weight decay, dropout, batch norm;

    аугментации: random crop, flip, color jitter, mixup, cutmix;

    нормализация входов.

Плюсы CNN: сильные встроенные inductive biases — локальность, разделяемые веса, иерархия.
Минусы: ограниченный глобальный контекст; решается увеличением рецептивного поля или attention-механизмами.
2.2. ResNet

Проблема: с ростом глубины обычные CNN начинают работать хуже не из-за переобучения, а из-за degradation problem и vanishing/exploding gradients.

ResNet предлагает skip connection:
y=F(x,W)+x
y=F(x,W)+x

где F(x,W)F(x,W) — остаточное преобразование. Если размерности не совпадают, используют проекцию WsxWs​x.

Почему это помогает:

    сети проще выучить «ничего не менять», чем полное преобразование;

    градиент течёт по identity-пути:
    ∂L∂x=∂L∂y(1+∂F∂x)
    ∂x∂L​=∂y∂L​(1+∂x∂F​)

    даже если ∂F∂x∂x∂F​ мал, градиент не затухает благодаря единице;

    появляется возможность обучать очень глубокие сети: 50, 101, 152 слоя.

Варианты:

    ResNet-18/34 — basic block;

    ResNet-50/101/152 — bottleneck: 1×1 → 3×3 → 1×1 для экономии вычислений;

    batch norm после свёрток.

ResNet стал стандартным backbone для detection, segmentation, pose и других задач.
2.3. YOLO classification head

YOLO — это прежде всего detection, но в семействе Ultralytics есть отдельные classification-модели: YOLOv8-cls, YOLO11-cls, YOLO26-cls.

    backbone: CSPDarknet / C2f / SPPF — как в detection;

        Conv 1×11×1;

        AdaptiveAvgPool до 1×11×1;

        Dropout;

        Linear → KK логитов.

То есть по сути это обычный CNN-классификатор с GAP + FC.

Чем отличается от «чистого» классификатора:

    почти ничем архитектурно;

    но встроен в единый YOLO-фреймворк: те же аугментации, training loop, экспорт, API, предобученные веса.

Чем отличается от classification-ветки в detection head:

    в detection голова предсказывает класс для каждой пространственной позиции/anchor;

2.4. ViT — Vision Transformer

ViT — принципиально другой подход: изображение представляется как последовательность патчей.

Схема:

    Изображение H×W×CH×W×C разрезается на патчи P×PP×P.

        Например, 224×224224×224, патч 16×1616×16 → 196 патчей.

    Каждый патч flatten → линейная проекция в размерность DD.

    Добавляется positional embedding.

    Добавляется обучаемый токен [CLS].

    Последовательность проходит через LL Transformer-блоков:

        LayerNorm;

        Multi-Head Self-Attention;

        residual;

        LayerNorm;

        MLP (GELU);

        residual.

    Классификационная голова берёт [CLS] или mean-pool патчей → Linear → KK.

Self-attention:
Attention(Q,K,V)=softmax(QKTdk)V
Attention(Q,K,V)=softmax(dk​
​QKT​)V

Ключевое отличие от CNN:

    CNN: локальность и translation equivariance встроены архитектурно.

    ViT: меньше inductive bias, все патчи могут взаимодействовать сразу, глобальный контекст с первого слоя.

    ViT требует много данных или сильного предобучения/augmentation. На маленьких датасетах чистый ViT проигрывает CNN.

    На больших данных ViT масштабируется лучше.

Альтернативы и гибриды:

    DeiT — distillation для обучения ViT на ImageNet-1k;

    Swin Transformer — оконное внимание и иерархия, ближе к CNN;

    ConvNeXt — CNN, модернизированная под дизайн трансформеров.

Что такое backbone

Backbone (дословно «позвоночник», «хребет») — это основная часть нейросети, которая извлекает признаки из изображения. Обычно backbone принимает изображение и превращает его в набор feature maps или эмбеддингов, а дальше уже специализированные «головы» (heads) решают конкретную задачу: классификацию, детекцию, сегментацию, позу и т.д.

Упрощённо:
Изображение→Backbone→Признаки→Head→Ответ
Изображение→Backbone→Признаки→Head→Ответ

Например, в детекции:
Backbone→Neck (FPN/PAN)→Detection Head
Backbone→Neck (FPN/PAN)→Detection Head

В классификации:
Backbone→Classification Head
Backbone→Classification Head

В сегментации:
Backbone (encoder)→Decoder→Маска
Backbone (encoder)→Decoder→Маска
Зачем выделяют backbone

    Переиспользование. Один и тот же backbone можно подключить к разным головам. ResNet-50 может быть backbone и для классификации, и для Faster R-CNN, и для Mask R-CNN.

    Transfer learning. Backbone предобучают на большом датасете (например, ImageNet), а потом дообучают под конкретную задачу. Это экономит данные и время.

    Разделение ответственности. Backbone отвечает за общие признаки: края, текстуры, формы, части объектов. Голова — за конкретную задачу.

    Масштабируемость. Можно заменить backbone на более мощный (ResNet → Swin → ViT), не переписывая всю архитектуру.

Примеры backbone

    CNN-based: LeNet, AlexNet, VGG, ResNet, EfficientNet, ConvNeXt, CSPDarknet (в YOLO).

    Transformer-based: ViT, Swin Transformer, DeiT.

    Гибридные: CNN + Transformer.

Для плотных задач (детекция, сегментация) backbone часто должен давать multi-scale features — карты признаков разного разрешения. У CNN это естественно: разные стадии имеют разный stride. У чистого ViT обычно одно разрешение, поэтому для детекции/сегментации чаще берут Swin или гибриды.

2. Почему ViT так устроен
2.1. Глобальный контекст с первого слоя

В CNN нейрон в первом слое видит только маленький участок. Чтобы увидеть всё изображение, нужно много слоёв. В ViT каждый патч через self-attention может взаимодействовать с каждым другим патчем уже в первом блоке. Это даёт глобальный контекст сразу.
2.2. Меньше inductive bias

CNN «знает» заранее:

    локальность;

    трансляционную эквивариантность;

    иерархию.

ViT почти ничего этого не знает. Он должен выучить эти свойства из данных. Поэтому:

    на маленьких датасетах ViT проигрывает CNN;

    на больших датасетах (JFT-300M, ImageNet-21k) ViT выигрывает и лучше масштабируется.

Это компромисс: меньше встроенных предположений → больше гибкости, но нужно больше данных.
2.3. Позиционные эмбеддинги возвращают пространство

Без positional embeddings ViT видит изображение как мешок патчей. Позиционные эмбеддинги добавляют информацию о том, где находится патч. Это ключевой элемент.
2.4. CLS-токен как агрегатор

[CLS] через attention собирает глобальную информацию. Его выход — компактное представление всего изображения. Это удобно для классификации.
2.5. Масштабируемость

ViT хорошо масштабируется:

    больше данных → лучше;

    больше модель → лучше;

    больше разрешение → лучше, если достаточно данных.

Это согласуется с scaling laws, как в NLP.
3. Сложности и ограничения ViT

    Квадратичная сложность attention.
    O(N2)
    O(N2)

    где NN — число патчей. Если уменьшить патч, NN растёт квадратично, и вычисления становятся очень дорогими.

    Нужно много данных.
    На ImageNet-1k чистый ViT без сильных аугментаций и дистилляции работает хуже ResNet. DeiT показал, как обучать ViT на меньших данных.

    Одно разрешение.
    У чистого ViT feature maps одного масштаба. Для детекции и сегментации нужны multi-scale признаки, поэтому часто используют Swin, PVT, ViTDet или гибриды.

    Позиционные эмбеддинги и смена разрешения.
    При тестировании на другом разрешении их приходится интерполировать.

4. Варианты и развитие

    DeiT — distillation + сильные аугментации, чтобы обучать ViT на ImageNet-1k.

    Swin Transformer — иерархия, локальные окна, shifted windows. Сложность линейна по числу патчей, есть multi-scale.

    MAE, BEiT, DINO — self-supervised предобучение ViT.

    Hybrid — CNN извлекает признаки, затем Transformer обрабатывает последовательность.

    ViTDet — ViT как backbone для detection.

    CLIP — ViT как image encoder, обучаемый на парах изображение-текст.

5. Итог

    Backbone — это извлекатель признаков. Он превращает изображение в эмбеддинги/feature maps, которые затем используются головой под конкретную задачу.

    ViT — это Transformer encoder, который работает не со словами, а с патчами изображения.

    Изображение → патчи → линейная проекция → + positional embeddings → + CLS → Transformer блоки → голова.

    Почему так: self-attention даёт глобальный контекст, positional embeddings возвращают пространство, CLS агрегирует информацию, а отсутствие сильных inductive bias позволяет ViT лучше масштабироваться на больших данных.

    Главные ограничения: квадратичная сложность, потребность в данных, одно разрешение. Отсюда — Swin, DeiT, гибриды.

2.5. Матричная форма для всего изображения

Соберём все векторы патчей в одну матрицу:
Xpatches∈RN×(P2C)

Строка nn — это xi,j⊤xi,j⊤​ для соответствующего патча. Порядок строк: сначала по ii, потом по jj (или наоборот — зависит от реализации, но фиксирован).

Тогда проекция всех патчей сразу:
Z=Xpatches E+1Nb⊤

где Z∈RN×DZ∈RN×D, 1N1N​ — вектор из единиц длины NN.

Это обычное матричное умножение + broadcast bias. Именно так это и реализовано в коде: Linear(P*P*C, D) применяется к тензору формы (N, P*P*C).
2.6. Эквивалентность свёртке

Ключевой факт: линейная проекция flatten-патчей эквивалентна свёртке с ядром P×PP×P, stride PP, числом выходных каналов DD.
Доказательство

Рассмотрим свёртку:
Conv2D(X,W,b)с W∈RD×C×P×P,  b∈RD
Conv2D(X,W,b)с W∈RD×C×P×P,b∈RD

Выход свёртки:
Yi,j,d=∑c=0C−1∑p=0P−1∑q=0P−1Wd,c,p,q⋅XiP+p,  jP+q,  c+bd
Yi,j,d​=c=0∑C−1​p=0∑P−1​q=0∑P−1​Wd,c,p,q​⋅XiP+p,jP+q,c​+bd​

Теперь посмотрим на линейную проекцию патча:
zi,j(d)=∑k=0P2C−1Ek,d xi,j(k)+bd
zi,j(d)​=k=0∑P2C−1​Ek,d​xi,j(k)​+bd​

Раскроем xi,j(k)xi,j(k)​ через компоненты патча. По определению vec:
xi,j(cP2+pP+q)=XiP+p,  jP+q,  c
xi,j(cP2+pP+q)​=XiP+p,jP+q,c​

Подставляем:
zi,j(d)=∑c=0C−1∑p=0P−1∑q=0P−1EcP2+pP+q,  d⋅XiP+p,  jP+q,  c+bd
zi,j(d)​=c=0∑C−1​p=0∑P−1​q=0∑P−1​EcP2+pP+q,d​⋅XiP+p,jP+q,c​+bd​

Сравниваем с формулой свёртки. Они совпадают, если положить:
Wd,c,p,q=EcP2+pP+q,  d
Wd,c,p,q​=EcP2+pP+q,d​

То есть:
Patch embedding=Conv2D с kernel P,  stride P,  out_channels D
Patch embedding=Conv2D с kernel P,stride P,out_channels D​
Что это даёт

    Понимание. ViT на входе — это свёрточный слой с большим ядром и большим stride. Никакой магии: сначала изображение «прореживается» свёрткой до сетки Nh×NwNh​×Nw​, а потом эти векторы идут в Transformer.

    Реализация. В коде можно делать либо unfold + Linear, либо Conv2d(P, P, D). Второе часто быстрее и использует оптимизированные CUDA-ядра.

    Параметры. У свёртки и у линейного слоя одинаковое число параметров: D⋅C⋅P2+DD⋅C⋅P2+D. Это не совпадение, а следствие эквивалентности.

    Инициализация. Иногда patch embedding инициализируют как свёртку (например, из предобученного CNN), но обычно обучают с нуля.

Тонкость с порядком flatten

Эквивалентность свёртке выполняется только при согласованном порядке flatten и порядка осей в весах свёртки. Если vec использует порядок (p,q,c)(p,q,c) вместо (c,p,q)(c,p,q), то соответствие будет другим, но всё равно линейным отображением. Главное — фиксировать порядок и согласовать его с реализацией.

В PyTorch:

    nn.Conv2d использует веса формы (out, in, kH, kW) и порядок (c, p, q) при вычислении;

    nn.Linear после flatten использует row-major порядок (c, p, q).

Поэтому они эквивалентны.

В коде:

2.9. Почему именно патчи, а не пиксели?

Если бы мы взяли каждый пиксель как отдельный токен:
N=H⋅W=224⋅224=50,176
N=H⋅W=224⋅224=50,176

Сложность self-attention:
O(N2)=O(50,1762)≈2.5⋅109
O(N2)=O(50,1762)≈2.5⋅109

Против N=196N=196:
O(1962)≈3.8⋅104
O(1962)≈3.8⋅104

Разница — в 65,000 раз. Это неподъёмно.

Патчи решают две задачи:

    Резко сокращают число токенов. N=HW/P2N=HW/P2. При P=16P=16 это уменьшение в 256 раз.

    Дают локальные признаки. Каждый патч — это уже небольшой фрагмент изображения с локальной структурой. Линейная проекция превращает его в эмбеддинг.

Компромисс: чем меньше патч, тем больше токенов, тем детальнее, но тем дороже. Стандарт — P=16P=16 или P=14P=14. Для плотных задач (детекция, сегментация) иногда берут P=8P=8 или используют иерархические архитектуры (Swin).
2.10. Что именно выучивает проекция?

Матрица EE — это обучаемый линейный фильтр, который каждому патчу ставит в соответствие вектор в пространстве DD. Интерпретации:

    Каждая строка Ek,:Ek,:​ — это «шаблон» для одного компонента эмбеддинга.

    Столбец E:,dE:,d​ — это линейная функция от всех пикселей патча, выдающая dd-ю компоненту.

    После обучения патч-эмбеддинги похожих патчей (например, «трава», «небо», «край объекта») оказываются близки в RDRD.

По сути, это обучаемый токенизатор: он переводит непрерывное пиксельное представление в последовательность векторов, с которой умеет работать Transformer.

В отличие от NLP, где токены дискретны и берутся из словаря, здесь токены непрерывны и порождаются линейным слоем. Это одна из ключевых адаптаций Transformer к изображениям.
2.11. Варианты и обобщения

    Перекрывающиеся патчи. Если stride <P<P, патчи перекрываются. Тогда patch embedding — это свёртка с kernel PP, stride S<PS<P. Это увеличивает NN и даёт более плотное покрытие.

    Multi-scale patch embedding. В Swin Transformer патчи меньшего размера на ранних стадиях и объединение (patch merging) на поздних — аналог иерархии CNN.

    Conv stem. Вместо одного слоя P×PP×P ставят несколько свёрток 3×33×3 до patch embedding. Это добавляет локальный inductive bias и помогает на малых данных (например, в некоторых вариантах ViT и в Hybrid ViT).

    Learnable vs fixed. Обычно EE обучается. Но можно инициализировать его свёрткой из предобученной CNN или даже фиксировать (например, использовать DCT-базис). На практике обучаемый вариант работает лучше.

    Positional embeddings добавляются после. Важно: patch embedding не содержит информации о позиции. Она добавляется на следующем шаге. Сам по себе patch embedding — это permutation-invariant преобразование.

    Патч (i,j)(i,j) — это подтензор P×P×CP×P×C, вырезанный с шагом PP.

    Patch embedding — это обучаемый токенизатор, переводящий пиксели в последовательность векторов для Transformer.

1.1. Постановка

Object Detection — это задача, где модели нужно найти на изображении все объекты интереса, и для каждого выдать:

    bbox (bounding box) — прямоугольник, ограничивающий объект;

    класс объекта;

    confidence — уверенность модели в том, что это действительно объект.

Формально:

    Вход: изображение x∈RH×W×Cx∈RH×W×C.

    Выход: множество детекций
    D={(bi,ci,si)}i=1M
    D={(bi​,ci​,si​)}i=1M​

    где:

        bi=(x1,y1,x2,y2)bi​=(x1​,y1​,x2​,y2​) — координаты bbox (или x,y,w,hx,y,w,h);

        ci∈{1,…,K}ci​∈{1,…,K} — класс;

        si∈[0,1]si​∈[0,1] — confidence score.

Число MM заранее неизвестно — оно зависит от изображения. Это ключевое отличие от классификации, где выход всегда один.

Что значит «найти все объекты»:

    Нужно не просто определить, что на картинке есть кошка, а указать где она;

    если на картинке две кошки — нужно две детекции;

    если объектов нет — пустое множество.

Почему это сложнее классификации:

    Переменное число выходов. Нельзя просто выдать фиксированный вектор.

    Локализация. Нужно предсказать непрерывные координаты, а не дискретный класс.

    Перекрытия. Объекты могут перекрываться, один объект может быть внутри другого.

    Масштаб. Объекты могут быть разного размера: от нескольких пикселей до всего изображения.

    Дисбаланс. Фона обычно гораздо больше, чем объектов.

1.3. IoU — Intersection over Union

Базовая метрика для сравнения двух bbox.

Для bbox AA и BB:
IoU(A,B)=∣A∩B∣∣A∪B∣
IoU(A,B)=∣A∪B∣∣A∩B∣​

где ∣A∩B∣∣A∩B∣ — площадь пересечения, ∣A∪B∣∣A∪B∣ — площадь объединения.

Площадь объединения:
∣A∪B∣=∣A∣+∣B∣−∣A∩B∣
∣A∪B∣=∣A∣+∣B∣−∣A∩B∣

Как вычислить пересечение:

Пусть A=(x1A,y1A,x2A,y2A)A=(x1A​,y1A​,x2A​,y2A​), B=(x1B,y1B,x2B,y2B)B=(x1B​,y1B​,x2B​,y2B​).

Координаты пересечения:
x1∩=max⁡(x1A,x1B),y1∩=max⁡(y1A,y1B)
x1∩​=max(x1A​,x1B​),y1∩​=max(y1A​,y1B​)
x2∩=min⁡(x2A,x2B),y2∩=min⁡(y2A,y2B)
x2∩​=min(x2A​,x2B​),y2∩​=min(y2A​,y2B​)

Ширина и высота пересечения:
w∩=max⁡(0,x2∩−x1∩),h∩=max⁡(0,y2∩−y1∩)
w∩=max(0,x2∩​−x1∩​),h∩=max(0,y2∩​−y1∩​)

Площадь пересечения:
∣A∩B∣=w∩⋅h∩
∣A∩B∣=w∩⋅h∩

Свойства IoU:

    IoU∈[0,1]IoU∈[0,1];

    IoU=1IoU=1 — идеальное совпадение;

    IoU=0IoU=0 — нет пересечения;

    не зависит от масштаба (относительная метрика).

Порог IoU: обычно IoU≥0.5IoU≥0.5 считается «детекция правильная». В COCO используют усреднение по порогам 0.5:0.05:0.95.
1.4. Precision, Recall, TP/FP/FN

Для одного класса и одного порога IoU:

    FP (False Positive) — предсказание с IoU<thresholdIoU<threshold или неправильным классом, либо лишнее предсказание.

    FN (False Negative) — истинный объект, для которого нет предсказания с IoU≥thresholdIoU≥threshold.

Precision=TPTP+FP
Precision=TP+FPTP​
Recall=TPTP+FN
Recall=TP+FNTP​

Проблема: нужно выбрать порог confidence. Если порог низкий — много FP, recall высокий. Если высокий — мало FP, но много FN.

Решение: precision-recall curve — график precision vs recall при всех порогах confidence.

1.6. NMS — Non-Maximum Suppression

Проблема: модель часто выдаёт несколько bbox для одного объекта. Нужно оставить один.

Алгоритм:

    Собрать все предсказания для одного класса.

    Отсортировать по убыванию confidence.

    Взять предсказание с максимальным confidence — это «победитель».

    Удалить все предсказания, у которых IoU с победителем > threshold (например, 0.5).

    Повторять, пока не останутся предсказания.

Псевдокод:
text

def nms(boxes, scores, iou_threshold):
    keep = []
    order = argsort(scores)[::-1]
    while order:
        i = order[0]
        keep.append(i)
        ious = [iou(boxes[i], boxes[j]) for j in order[1:]]
        order = [j for j, o in zip(order[1:], ious) if o <= iou_threshold]
    return keep

Параметры:

    iou_threshold — обычно 0.5 или 0.7;

    чем ниже порог, тем агрессивнее подавление.

Проблемы NMS:

    Жадность. Порядок обработки влияет на результат.

    Перекрывающиеся объекты. Если два объекта одного класса сильно перекрываются, NMS может удалить один из них.

    Скорость. Для большого числа предсказаний NMS может быть медленным.

    Не дифференцируемость. Нельзя обучать end-to-end.

Soft-NMS: вместо удаления — уменьшать confidence пропорционально IoU:
sj=sj⋅e−IoU2σ
sj​=sj​⋅e−σIoU2​

NMS-free подходы: YOLOv10, RT-DETR — обучаются так, чтобы не требовать NMS.
1.7. Классические подходы
Sliding Window + Classifier

Идея: двигаем окно фиксированного размера по изображению с шагом, классифицируем каждое окно.

Проблемы:

    Вычислительная сложность. Для изображения H×WH×W и окна K×KK×K с шагом SS: HWS2S2HW​ окон. Для каждого — forward pass классификатора.

    Масштаб. Нужно перебирать размеры окна.

    Форма. Объекты не прямоугольные.

    Дисбаланс. Большинство окон — фон.

Исторически использовалось с HOG+SVM, но было очень медленным.
R-CNN (2014)

Идея: сначала region proposals, потом классификация.

    Selective Search генерирует ~2000 регионов-кандидатов.

    Каждый регион масштабируется до фиксированного размера (например, 224×224224×224).

    CNN извлекает признаки.

    SVM классифицирует.

    Линейная регрессия уточняет bbox.

Проблемы:

    Очень медленно: 2000 forward pass на изображение.

    Не end-to-end.

    Много дискового пространства для признаков.

Fast R-CNN (2015)

Улучшения:

    CNN прогоняется один раз по всему изображению → feature map.

    RoI Pooling извлекает фиксированный вектор для каждого региона из feature map.

    Далее — FC слои для классификации и регрессии bbox.

RoI Pooling:

    Регион проецируется на feature map;

    делится на k×kk×k бинов;

    в каждом бине — max pooling;

    результат — фиксированный k×k×Ck×k×C тензор.

Плюсы:

    В 10 раз быстрее R-CNN.

    End-to-end обучение (кроме region proposals).

Минусы:

    Region proposals всё ещё отдельный этап (Selective Search).

    Не полностью end-to-end.

Faster R-CNN (2015)

Ключевая идея: RPN (Region Proposal Network) — обучаемая сеть для генерации регионов.

Архитектура:

    Backbone → feature map.

    RPN предсказывает:

        objectness score для каждого anchor;

        смещения bbox (dx, dy, dw, dh).

    Anchors — набор bbox фиксированного размера и соотношения сторон в каждой позиции feature map.

        Например, 9 anchors: 3 масштаба × 3 соотношения.

    RoI Pooling → классификация + регрессия.

Anchor:
anchor=(xc,yc,w,h)

    pp — вероятность объекта;

    t=(tx,ty,tw,th)t=(tx​,ty​,tw​,th​) — смещения.

Loss:
L=Lcls+λLreg

    LclsLcls​ — cross-entropy для objectness;

    LregLreg​ — smooth L1 для bbox.

Плюсы:

    Полностью end-to-end.

    Быстрее Fast R-CNN.

    Точность высокая.

Минусы:

    Two-stage: сначала proposals, потом классификация.

    Медленнее one-stage.

One-stage: YOLO и SSD

Идея: одна сеть предсказывает классы и bbox напрямую, без отдельного этапа proposals.

YOLO (You Only Look Once, 2015):

    Изображение делится на S×SS×S grid.

    Каждая ячейка предсказывает BB bbox + confidence + KK классов.

    Выход: S×S×(B⋅5+K)S×S×(B⋅5+K).

    Loss: сумма localization loss, confidence loss, classification loss.

SSD (Single Shot MultiBox Detector, 2016):

    Multi-scale feature maps.

    Default boxes (аналоги anchors) разного размера.

    Предсказания на нескольких масштабах.

Почему one-stage быстрее:

    Нет отдельного RPN.

    Один forward pass.

    Проще архитектура.

Почему two-stage точнее:

    RPN фокусируется на потенциальных объектах.

    RoI Pooling даёт более точные признаки для каждого региона.

    Меньше дисбаланс классов на этапе классификации.

2.6. YOLOv10 / YOLO26 — NMS-free

Проблема NMS:

    Не дифференцируем.

    Гиперпараметр IoU threshold.

    Медленно при большом числе предсказаний.

    Может удалять правильные детекции.

Идея NMS-free:

    Обучить модель так, чтобы для каждого объекта было ровно одно предсказание.

    Тогда NMS не нужен.

Dual label assignment (YOLOv10):

    One-to-many: несколько предсказаний на объект (для богатого supervision).

    One-to-one: одно предсказание на объект (для NMS-free инференса).

    Два heads: один для one-to-many, другой для one-to-one.

    На инференсе используется one-to-one head.

Consistent dual assignments:

    Оба assignment согласованы.

    One-to-one head получает градиенты от one-to-many.

Преимущества:

    Нет NMS → быстрее инференс.

    Нет гиперпараметра.

    End-to-end обучение.

YOLO26:

    Дальнейшее развитие.

    Ещё более эффективный NMS-free.

    Улучшенные heads для segmentation, pose, OBB, depth.

RT-DETR (Real-Time DETR, 2023):

3. Semantic Segmentation
A. Задача в отрыве от моделей
1.1. Постановка

Semantic Segmentation — это задача, где модели нужно присвоить каждому пикселю изображения класс объекта, к которому он принадлежит. При этом объекты одного класса не разделяются между собой.

Формально:

    Вход: изображение x∈RH×W×Cx∈RH×W×C.

    Выход: карта классов
    Y^∈{1,…,K}H×W
    Y^∈{1,…,K}H×W

    где KK — число классов (включая фон).

    Или вероятностная карта:
    P^∈[0,1]H×W×K,P^i,j,k=p(yi,j=k∣x)
    P^∈[0,1]H×W×K,P^i,j,k​=p(yi,j​=k∣x)

Функция модели:
fθ:RH×W×C→RH×W×K
fθ​:RH×W×C→RH×W×K

Решение на инференсе:
Y^i,j=arg⁡max⁡kP^i,j,k
Y^i,j​=argkmax​P^i,j,k​

Ключевое отличие от classification и detection:
Задача	Выход
Classification	один класс на изображение
Detection	множество bbox + классы
Semantic Segmentation	класс на каждый пиксель, без разделения объектов
Instance Segmentation	класс + экземпляр на каждый пиксель

Пример: если на картинке три кошки, semantic segmentation выдаст одну маску «кошка» на всех трёх. Instance segmentation выдаст три отдельные маски.

Почему это сложнее:

    Плотное предсказание. Нужно предсказать H⋅WH⋅W значений, а не одно.

    Пространственная точность. Границы объектов должны быть точными.

    Контекст. Чтобы понять, что пиксель — это «дорога», нужно смотреть на большой контекст.

    Дисбаланс. Фон обычно занимает большую часть пикселей.

    Мультимасштабность. Объекты разного размера: от маленьких до огромных.

1.2. Формат разметки

Маски — обычно PNG с индексами классов на пиксель:

    Один канал (grayscale), значение пикселя = индекс класса.

    Пример: 0 — фон, 1 — кошка, 2 — собака, 3 — машина.

    Размер маски = размер изображения.

Альтернативы:

    COCO panoptic — JSON с сегментами.

    Cityscapes — PNG с индексами классов, отдельно instance IDs.

    Pascal VOC — PNG с палитрой, где каждому классу соответствует цвет.

Важно: в semantic segmentation объекты одного класса сливаются в одну маску. Если два человека перекрываются, semantic segmentation не различает их.

Формат данных:
text

    img1.jpg
    img2.jpg
  masks/

Матрица K×KK×K, где CijCij​ — число пикселей истинного класса ii, предсказанных как jj. По ней считают все остальные метрики.
1.4. Базовые подходы до FCN

    Пиксельные признаки + классификатор.

        Для каждого пикселя берут признаки (цвет, текстура, HOG);

        обучают SVM/Random Forest;

        медленно, нет контекста.

    Superpixels.

        Изображение разбивается на регионы (SLIC, Felzenszwalb);

        признаки региона → классификатор;

        быстрее, но зависит от качества суперпикселей.

    MRF/CRF.

        Вероятностная модель;

        учёт пространственной согласованности;

        часто используется как post-processing для CNN.

    Sliding window classification.

        Классифицируем каждое окно;

        очень медленно.

Почему не работало:

    Нет end-to-end обучения;

    Нет иерархии признаков;

    Нет учёта глобального контекста.

B. Архитектуры
2.1. FCN — Fully Convolutional Network (2015)

Ключевая идея: заменить полносвязные слои на свёрточные, чтобы сеть могла работать с изображениями любого размера и выдавать пространственную карту.

Проблема: в классификационных CNN (AlexNet, VGG) в конце стоят FC-слои, которые «выпрямляют» пространственную структуру:
feature map 7×7×512→flatten→4096→4096→1000
feature map 7×7×512→flatten→4096→4096→1000

Решение FCN:

    FC-слой 40964096 можно представить как свёртку 7×7×512×40967×7×512×4096;

    FC-слой 10001000 — как свёртку 1×1×4096×10001×1×4096×1000;

    тогда выход — карта 1×1×10001×1×1000, но её можно «растянуть» на любой вход.

Архитектура FCN:

    Backbone (VGG-16) без FC-слоёв → feature map с stride 32.

    Свёртки 1×11×1 для получения KK каналов.

    Upsampling (transposed convolution) до исходного разрешения.

Проблема: после 5 pooling'ов разрешение падает в 32 раза. Прямой upsample даёт грубые маски.

Решения:

    FCN-32s: upsample stride 32 → грубо.

    FCN-16s: combine с pool4 → лучше.

    FCN-8s: combine с pool3 → ещё лучше.

Skip connections:
output=upsample(conv1×1(pool5))+conv1×1(pool4)
output=upsample(conv1×1​(pool5))+conv1×1​(pool4)

Затем upsample до полного разрешения.

Loss: pixel-wise cross-entropy:
L=−1HW∑i,jlog⁡p(yi,j∣x)
L=−HW1​i,j∑​logp(yi,j​∣x)

Значение FCN:

    Первая end-to-end обучаемая сеть для сегментации.

    Показала, что CNN можно использовать для плотных задач.

    Ввела идею skip connections для восстановления разрешения.

2.2. U-Net (2015)

Идея: encoder-decoder с skip connections между соответствующими уровнями.

Архитектура (U-образная):

Encoder (contracting path):

    Свёртки 3×33×3 + ReLU;

    Max pooling 2×22×2;

    Разрешение уменьшается, число каналов растёт.

Bottleneck:

    Самый глубокий уровень;

    Максимальное семантическое содержание.

Decoder (expanding path):

    Upsampling (transposed conv или bilinear);

    Concatenation с feature map из encoder;

    Свёртки 3×33×3 + ReLU.

Финальный слой:

    1×11×1 свёртка → KK каналов;

    Softmax.

Схема:
text

Input → Conv → Conv → Down → Conv → Conv → Down → ... → Bottleneck
  |                    |                              |
  └────────────────────┴──────────────────────────────┘
                       (skip connections)
  |                    |                              |
Output ← Conv ← Conv ← Up ← Conv ← Conv ← Up ← ... ← Bottleneck

Почему это работает:

    Skip connections передают высокочастотную информацию (границы, текстуры) с ранних слоёв на поздние.

    Decoder восстанавливает пространственное разрешение.

    Concatenation (а не сложение) даёт сети доступ к обоим типам признаков.

Формально:
xdec(l)=Conv(Concat[Up(xdec(l+1)),xenc(l)])
xdec(l)​=Conv(Concat[Up(xdec(l+1)​),xenc(l)​])

Loss:

    Pixel-wise cross-entropy;

    Часто добавляют weighted loss для границ:
    w(x)=wc(x)+w0⋅exp⁡(−(d1(x)+d2(x))22σ2)
    w(x)=wc​(x)+w0​⋅exp(−2σ2(d1​(x)+d2​(x))2​)

    где d1,d2d1​,d2​ — расстояния до ближайших границ.

Применение:

    Медицинская визуализация (клетки, органы);

    Спутниковые снимки;

    Дорожная разметка.

Почему U-Net стал стандартом:

    Простой;

    Эффективный;

    Работает на малых данных;

    Легко модифицируется.

Варианты:

    U-Net++ — вложенные skip connections;

    Attention U-Net — attention на skip connections;

    ResU-Net — residual blocks;

    3D U-Net — для объёмных данных.

2.3. DeepLab

Ключевая проблема: в CNN pooling уменьшает разрешение, что плохо для сегментации. Но без pooling рецептивное поле маленькое.

Решение: atrous/dilated convolution.
Dilated (atrous) convolution

Обычная свёртка 3×33×3:
yi,j=∑m=−11∑n=−11wm,n⋅xi+m,j+n
yi,j​=m=−1∑1​n=−1∑1​wm,n​⋅xi+m,j+n​

Dilated свёртка 3×33×3 с dilation rate rr:
yi,j=∑m=−11∑n=−11wm,n⋅xi+m⋅r,j+n⋅r
yi,j​=m=−1∑1​n=−1∑1​wm,n​⋅xi+m⋅r,j+n⋅r​

Эффект:

    r=1r=1 — обычная свёртка, рецептивное поле 3×33×3;

    r=2r=2 — рецептивное поле 5×55×5, но параметров столько же, сколько у 3×33×3;

    r=4r=4 — рецептивное поле 9×99×9.

Формула рецептивного поля:

Для стека свёрток с dilation rates r1,…,rLr1​,…,rL​:
RF=1+∑l=1L(kl−1)⋅rl
RF=1+l=1∑L​(kl​−1)⋅rl​

где klkl​ — размер ядра.

Зачем:

    Увеличивает рецептивное поле без уменьшения разрешения;

    Не добавляет параметров;

    Позволяет сохранить детали.

Atrous Spatial Pyramid Pooling (ASPP)

Идея: применить несколько dilated свёрток с разными rr параллельно и объединить результаты.
ASPP(x)=Concat[Convr=1(x),Convr=6(x),Convr=12(x),Convr=18(x),GAP(x)]
ASPP(x)=Concat[Convr=1​(x),Convr=6​(x),Convr=12​(x),Convr=18​(x),GAP(x)]

Зачем:

    Multi-scale контекст;

    Разные rr улавливают объекты разного размера.

DeepLab версии

DeepLab v1 (2015):

    VGG-16 backbone;

    Dilated conv для сохранения разрешения;

    CRF как post-processing.

DeepLab v2 (2016):

    ResNet backbone;

    ASPP.

DeepLab v3 (2017):

    Улучшенный ASPP;

    Image-level features (GAP);

    Batch norm.

DeepLab v3+ (2018):

    Encoder-decoder (как U-Net);

    ASPP в encoder;

    Skip connections;

    Depthwise separable conv для скорости.

Формально DeepLab v3+:
Output=Decoder(ASPP(Encoder(x)),Low-level features)
Output=Decoder(ASPP(Encoder(x)),Low-level features)

Почему DeepLab важен:

    Показал силу dilated convolutions;

    ASPP — стандартный блок для multi-scale;

    DeepLab v3+ — один из лучших архитектур для semantic segmentation.

2.6. Функции потерь
Cross-Entropy
LCE=−1HW∑i,jlog⁡p(yi,j∣x)
LCE​=−HW1​i,j∑​logp(yi,j​∣x)

Проблема: дисбаланс классов.
Weighted Cross-Entropy
LWCE=−1HW∑i,jwyi,jlog⁡p(yi,j∣x)
LWCE​=−HW1​i,j∑​wyi,j​​logp(yi,j​∣x)

где wkwk​ — вес класса kk. Часто wk=1/freqkwk​=1/freqk​.
Focal Loss
Lfocal=−1HW∑i,jα(1−pt)γlog⁡pt
Lfocal​=−HW1​i,j∑​α(1−pt​)γlogpt​

где ptpt​ — вероятность истинного класса, γγ — фокусирующий параметр.

Эффект: уменьшает вклад «лёгких» примеров, фокусируется на сложных.
Dice Loss
LDice=1−2∑i,jpi,jyi,j∑i,jpi,j+∑i,jyi,j
LDice​=1−∑i,j​pi,j​+∑i,j​yi,j​2∑i,j​pi,j​yi,j​​

Плюсы: работает при дисбалансе.
IoU Loss
LIoU=1−∑p⋅y∑p+∑y−∑p⋅y
LIoU​=1−∑p+∑y−∑p⋅y∑p⋅y​
Комбинированные
L=LCE+λLDice
L=LCE​+λLDice​

Или:
L=LCE+λLIoU
L=LCE​+λLIoU​

4. Instance Segmentation
A. Задача в отрыве от моделей
1.1. Постановка

Instance Segmentation — это задача, где модели нужно для каждого экземпляра объекта на изображении выдать:

    маску (попиксельную);

    класс;

    confidence (опционально);

    bbox (опционально, но часто предсказывается).

Формально:

    Вход: изображение x∈RH×W×Cx∈RH×W×C.

    Выход: множество экземпляров
    D={(Mi,ci,si)}i=1M
    D={(Mi​,ci​,si​)}i=1M​

    где:

        Mi∈{0,1}H×WMi​∈{0,1}H×W — бинарная маска ii-го экземпляра;

        ci∈{1,…,K}ci​∈{1,…,K} — класс;

        si∈[0,1]si​∈[0,1] — confidence.

Ключевое отличие от semantic segmentation:
Задача	Выход
Semantic	одна маска на класс (все объекты класса слиты)
Instance	отдельная маска на каждый экземпляр

Пример: три кошки на картинке:

    Semantic segmentation: одна маска «кошка» на всех трёх;

    Instance segmentation: три отдельные маски, каждая со своим контуром.

Ключевое отличие от object detection:
Задача	Выход
Detection	bbox + класс
Instance	маска (попиксельно) + класс

Почему это сложнее, чем detection + semantic по отдельности:

    Нужно разделить перекрывающиеся объекты одного класса.

        В semantic segmentation это не проблема (все кошки — одна маска).

        В instance segmentation нужно понять, где заканчивается одна кошка и начинается другая.

    Нужна точная граница.

        Bbox грубый, маска — точная.

        Нужно предсказать контур с точностью до пикселя.

    Переменное число экземпляров.

        Как в detection, число объектов заранее неизвестно.

    Совмещение двух задач.

        Нужно и найти объект (detection), и сегментировать его (segmentation).

Формально: instance segmentation = detection + попиксельная сегментация для каждого экземпляра.

COCO
json

{

  "annotations": [
    {
      "image_id": 1,
      "category_id": 1,

Форматы segmentation:

    Polygon: список точек контура (для не-перекрывающихся объектов);

    RLE (Run-Length Encoding): для перекрывающихся объектов и iscrowd.

RLE (Run-Length Encoding)

Компактное представление бинарной маски:
text

В COCO RLE кодируется как:
json

где counts — чередование длин нулей и единиц.
Pascal VOC

    PNG-маски с палитрой;

    Каждый экземпляр — отдельный цвет;

    Отдельно class для каждого экземпляра.

YOLO-формат для segmentation
text

    Полигон, нормализованный к [0,1][0,1];

    Число точек может варьироваться.

1.3. Метрики

Instance segmentation использует те же метрики, что detection, но IoU считается по маскам, а не по bbox.
Mask IoU

Для предсказанной маски MM и истинной GG:
Mask IoU=∣M∩G∣∣M∪G∣
Mask IoU=∣M∪G∣∣M∩G∣​
Mask mAP

    mAP@0.5 — IoU threshold 0.5;

    mAP@0.5:0.95 — COCO-style, усреднение по 10 порогам.

Алгоритм:

    Для каждого класса собрать все предсказания.

    Отсортировать по confidence.

    Для каждого предсказания: сопоставить с истинным объектом по Mask IoU.

    TP/FP/FN → precision-recall curve → AP.

    Усреднить по классам → mAP.

Отличие от detection mAP:

    IoU считается по маскам, а не по bbox;

    Маски точнее, поэтому метрика строже;

    Часто mAP по маскам ниже, чем mAP по bbox.

Дополнительные метрики

    Boundary IoU — IoU только по пикселям у границ;

    Boundary F1 — F1 по границам;

    Panoptic Quality (PQ) — для panoptic segmentation.

1.4. Концептуальная сложность

Как разделить два перекрывающихся объекта одного класса?

Это ключевая проблема instance segmentation. Есть несколько подходов:

    Top-down (detection-first):

        Сначала найти bbox каждого объекта (detection);

        Потом внутри каждого bbox сегментировать объект;

        Пример: Mask R-CNN.

    Bottom-up (embedding-first):

        Сначала сегментировать всё (semantic);

        Потом сгруппировать пиксели в экземпляры по эмбеддингам;

        Пример: DeepMask, associative embedding.

    One-stage (dense prediction):

        Предсказать маски напрямую, без явного detection;

        Пример: YOLACT, SOLO.

B. Архитектуры
2.1. Mask R-CNN (2017)

Идея: естественное расширение Faster R-CNN: добавить segmentation head поверх RoI.

Архитектура:

    Backbone (ResNet-FPN) → feature map.

    RPN → region proposals.

    RoIAlign → фиксированный вектор для каждого RoI.

    Два параллельных head:

        Classification head: класс + bbox regression (как в Faster R-CNN);

        Mask head: бинарная маска 28×2828×28 для каждого класса.

Ключевое отличие от Faster R-CNN:

    Добавлена mask branch;

    RoIAlign вместо RoIPool.

RoIAlign

Проблема RoIPool: квантование координат (округление до целых пикселей) → потеря точности.

RoIAlign:

    Не округляет координаты;

    Использует bilinear interpolation для выборки значений в дробных координатах;

    Точнее для масок.

Формально:

Для точки (x,y)(x,y) в RoI:
f(x,y)=∑i,jf(xi,yj)⋅max⁡(0,1−∣x−xi∣)⋅max⁡(0,1−∣y−yj∣)
f(x,y)=i,j∑​f(xi​,yj​)⋅max(0,1−∣x−xi​∣)⋅max(0,1−∣y−yj​∣)

где (xi,yj)(xi​,yj​) — ближайшие целые пиксели.
Mask head

    Вход: RoIAlign feature 14×14×C14×14×C;

    4 свёртки 3×33×3;

    Transposed conv 2×22×2 → 28×2828×28;

    1×11×1 conv → KK каналов;

    Sigmoid → бинарная маска для каждого класса.

Важно: маска предсказывается для каждого класса независимо, без softmax между классами. Класс выбирается по classification head, затем берётся соответствующая маска.

Формально:
M∈R28×28×K,Mk=σ(Conv(RoIAlign(x,b)))
M∈R28×28×K,Mk​=σ(Conv(RoIAlign(x,b)))

Loss:
L=Lcls+Lbox+Lmask

где:

    LclsLcls​ — cross-entropy для класса;

    LboxLbox​ — smooth L1 для bbox;

    LmaskLmask​ — binary cross-entropy для маски.

Lmask=−1282∑i,j[yi,jlog⁡y^i,j+(1−yi,j)log⁡(1−y^i,j)]

Почему работает:

    RoIAlign даёт точные признаки;

    Отдельная mask branch не мешает classification;

    Multi-task learning улучшает обе задачи.

Плюсы:

    Высокая точность;

    End-to-end;

Минусы:

2.2. YOLACT (2019)

Идея: one-stage instance segmentation через прототипные маски.

Ключевая идея: не предсказывать маску для каждого объекта напрямую, а:

    Предсказать K прототипов масок (глобальных, для всего изображения);

    Для каждой детекции предсказать коэффициенты c∈RKc∈RK;

Формально:
Mi=σ(∑k=1Kci,k⋅Pk)
Mi​=σ(k=1∑K​ci,k​⋅Pk​)

где:

Архитектура:

    Backbone (ResNet-FPN) → feature maps.

    Protonet: несколько свёрток → KK прототипов H/4×W/4H/4×W/4.

        class;

        bbox;

        KK mask coefficients.

Почему это работает:

    Прототипы — глобальные, разделяются между всеми объектами;

    Коэффициенты — компактные (K чисел на объект);

    Линейная комбинация даёт маску;

    Быстро: нет RoIAlign, нет отдельной mask branch на каждый RoI.

Loss:
L=Lcls+Lbox+Lmask
L=Lcls​+Lbox​+Lmask​

LmaskLmask​ — cross-entropy между собранной маской и ground truth.

Плюсы:

    Простой.

Минусы:

5. Pose Estimation / Keypoint Detection
A. Задача в отрыве от моделей
1.1. Постановка

Pose Estimation (оценка позы) — это задача, где модели нужно найти на изображении ключевые точки (keypoints) объекта и собрать их в скелет. Чаще всего речь о человеческой позе: суставы и части тела.

Формально:

    Вход: изображение x∈RH×W×Cx∈RH×W×C.

    Выход: для каждого объекта — набор из NN ключевых точек:
    P={(pi,vi)}i=1N
    P={(pi​,vi​)}i=1N​

    где:

        pi=(xi,yi)pi​=(xi​,yi​) — координаты точки ii;

        vi∈{0,1,2}vi​∈{0,1,2} — видимость:

            0 — не размечена / вне изображения;

            1 — размечена, но не видна (перекрыта);

            2 — видна.

Ключевое отличие от всех предыдущих задач:
Задача	Выход
Classification	один класс
Detection	bbox + класс
Semantic Segmentation	класс на пиксель
Instance Segmentation	маска на экземпляр
Pose Estimation	N фиксированных keypoints на объект

Что значит «фиксированные keypoints»:

    Набор точек заранее задан: например, 17 точек для COCO (нос, глаза, уши, плечи, локти, запястья, бёдра, колени, лодыжки).

    Это не произвольная форма, а заранее определённый скелет.

    Для каждого объекта предсказываются одни и те же NN точек.

Пример (COCO, 17 keypoints):
text

0: nose
1: left_eye        2: right_eye
3: left_ear        4: right_ear
5: left_shoulder   6: right_shoulder
7: left_elbow      8: right_elbow
9: left_wrist      10: right_wrist
11: left_hip       12: right_hip
13: left_knee      14: right_knee
15: left_ankle     16: right_ankle

Другие наборы:

    MPII: 16 keypoints.

    COCO: 17 keypoints.

    Human3.6M: 17 keypoints (3D).

    OpenPose: 18 или 25 keypoints (body + hands + face).

    Face landmarks: 5, 68 или 468 точек.

    Hand pose: 21 keypoint.

Почему это сложнее detection:

    Точность. Нужно предсказать координаты с точностью до нескольких пикселей.

    Окклюзия. Точки могут быть перекрыты — нужно предсказать их положение или пометить как невидимые.

    Переменное число людей. Как в detection, число объектов неизвестно.

    Связность. Точки не независимы — они образуют скелет, и это нужно учитывать.

    Масштаб. Люди могут быть разного размера.

    Поза. Люди могут быть в произвольных позах, в том числе редких.

Формально: pose estimation = detection + предсказание NN точек для каждого объекта.

1.3. Метрики
OKS — Object Keypoint Similarity

Главная метрика для pose estimation. Аналог IoU, но для точек.
OKS=∑iexp⁡(−di22s2ki2)⋅δ(vi>0)∑iδ(vi>0)
OKS=∑i​δ(vi​>0)∑i​exp(−2s2ki2​di2​​)⋅δ(vi​>0)​

где:

    didi​ — евклидово расстояние между предсказанной и истинной точкой ii:
    di=(xi−x^i)2+(yi−y^i)2
    di​=(xi​−x^i​)2+(yi​−y^​i​)2
    ​

    ss — масштаб объекта (обычно area bboxarea bbox
    ​);

    kiki​ — константа, зависящая от типа точки (определяется из статистики разметки);

    δ(vi>0)δ(vi​>0) — индикатор, учитываем только видимые точки.

Смысл:

    Чем ближе предсказание к истине, тем ближе OKS к 1;

    ss нормирует ошибку по размеру объекта: для крупного объекта допускается большая абсолютная ошибка;

    kiki​ учитывает, что разные точки имеют разную «сложность» (например, глаза сложнее, чем плечи).

Значения kiki​ для COCO:

OKS как IoU: OKS ∈ [0, 1], порог 0.5 или 0.75 используется для TP/FP.
mAP для pose

    AP@0.75 — строже;

Алгоритм:

    Для каждого изображения — все предсказания.

    Сопоставить с истинными объектами по OKS.

    TP/FP/FN → precision-recall → AP.

    Усреднить по классам (обычно только person).

    AP^M — для средних объектов;

    AP^L — для крупных;

    AR — average recall.

Доля точек, для которых расстояние до истинной меньше порога:

где dnormdnorm​ — нормировка:

    PCK: нормировка на размер торса (расстояние между плечами и бёдрами).

Порог αα: обычно 0.5 (50% от нормировки).

Для 3D:
MPJPE=1N∑i∥pi−p^i∥
MPJPE=N1​i∑​∥pi​−p^​i​∥

    P-MPJPE: после выравнивания по Procrustes;

    N-MPJPE: после выравнивания по масштабу и повороту.

Другие

    PDJ (Percentage of Detected Joints) — доля точек в пределах порога;

    AUC — площадь под кривой PCK.

1.4. Top-down vs Bottom-up

Ключевая архитектурная развилка.
Top-down

Идея: сначала найти каждого человека (detection), потом внутри bbox предсказать keypoints.

Pipeline:

    Detector (YOLO, Faster R-CNN) → bbox для каждого человека.

    Для каждого bbox — crop + resize.

    Pose model → keypoints внутри bbox.

Плюсы:

    Точность выше: модель работает с одним человеком, может использовать больше параметров;

    Проще обучение: одна поза на изображение;

    Хорошо работает при небольшом числе людей.

Минусы:

    Зависит от качества detector;

    Медленно при большом числе людей (N forward pass);

    Ошибки detector'а передаются в pose.

Примеры: Mask R-CNN (keypoint branch), HRNet, SimpleBaseline, YOLOv8-pose.
Bottom-up

Идея: сначала найти все keypoints на изображении, потом сгруппировать их по людям.

Pipeline:

    Pose model → heatmap для каждой точки + grouping cues (part affinity fields, embeddings).

    Группировка точек в скелеты.

    Получение поз для каждого человека.

Плюсы:

    Быстрее при большом числе людей (один forward pass);

    Не зависит от detector;

    Real-time.

Минусы:

    Сложнее: нужно правильно сгруппировать точки;

    Точность ниже при окклюзиях;

    Проблемы с перекрывающимися людьми.

Примеры: OpenPose, Associative Embedding, HigherHRNet, YOLO-pose (bottom-up вариант).
Сравнение
	Top-down	Bottom-up
Порядок	detect → keypoints	keypoints → group
Число forward	N + 1	1
Точность	Выше	Ниже
Скорость	Падает с N	Постоянная
Зависимость от detector	Да	Нет
Окклюзии	Лучше	Хуже
1.5. Heatmap-подход

Основной способ представления keypoints в deep learning.

Вместо прямого предсказания координат (x,y)(x,y), модель предсказывает heatmap — карту вероятностей:
H∈[0,1]H′×W′×N
H∈[0,1]H′×W′×N

где H′,W′H′,W′ — разрешение heatmap (обычно H/4×W/4H/4×W/4), NN — число точек.

Ground truth heatmap:

Для каждой точки pi=(xi,yi)pi​=(xi​,yi​) создаётся гауссово распределение:
Hi(u,v)=exp⁡(−(u−xi)2+(v−yi)22σ2)
Hi​(u,v)=exp(−2σ2(u−xi​)2+(v−yi​)2​)

где (u,v)(u,v) — координаты пикселя heatmap, σσ — стандартное отклонение (обычно 2).

Предсказание координат:
p^i=arg⁡max⁡(u,v)Hi(u,v)
p^​i​=arg(u,v)max​Hi​(u,v)

Или с sub-pixel точностью: взвешенное среднее по окрестности максимума.

Loss:
L=∑i=1N∑u,v(Hi(u,v)−H^i(u,v))2
L=i=1∑N​u,v∑​(Hi​(u,v)−H^i​(u,v))2

MSE между предсказанной и истинной heatmap.

Почему heatmap, а не регрессия координат:

    Heatmap сохраняет пространственную структуру;

    Легче обучать: задача плотного предсказания, как в сегментации;

    Более устойчиво к шуму;

    Работает с окклюзиями: если точка не видна, heatmap размыта, но модель может предсказать её положение.

Недостатки:

    Дорого по памяти: H′×W′×NH′×W′×N;

    Нужна постобработка (argmax, refinement);

    Квантование координат.

1.6. Альтернативы heatmap
Прямая регрессия координат

Модель предсказывает (x,y)(x,y) напрямую:
p^i=FC(features)
p^​i​=FC(features)

Плюсы: просто, быстро.
Минусы: хуже точность, нет пространственной структуры.
Integral regression

Предсказывается heatmap, но координаты — через soft-argmax:
x^i=∑u,vu⋅softmax(Hi(u,v))
x^i​=u,v∑​u⋅softmax(Hi​(u,v))

Плюсы: дифференцируемо, end-to-end.
Минусы: сложнее.
SimCC (Simple Coordinate Classification)

B. Архитектуры
2.1. OpenPose (2017)

Классический bottom-up подход.

Архитектура:

    Backbone (VGG-19) → feature map.

    Two-branch multi-stage CNN:

        Branch 1: heatmaps для NN keypoints;

        Branch 2: Part Affinity Fields (PAFs) — векторные поля, кодирующие связи между точками.

Part Affinity Fields (PAFs):

Для каждой пары связанных точек (например, плечо-локоть) предсказывается 2D векторное поле:
L∈RH′×W′×2×C
L∈RH′×W′×2×C

где CC — число связей (обычно 17 для COCO).

Идея: для пикселя на линии между двумя точками предсказывается единичный вектор, направленный от первой точки ко второй.

Формально:

Для связи между точками p1p1​ и p2p2​:
L(p)=p2−p1∥p2−p1∥
L(p)=∥p2​−p1​∥p2​−p1​​

для точек pp на отрезке между p1p1​ и p2p2​.

Loss:
L=Lheatmap+LPAF
L=Lheatmap​+LPAF​

Группировка:

    Найти все keypoints (argmax heatmap).

    Для каждой пары связанных точек — вычислить интеграл PAF вдоль линии:
    E=∫01L(p(t))⋅p2−p1∥p2−p1∥dt
    E=∫01​L(p(t))⋅∥p2​−p1​∥p2​−p1​​dt

    Сопоставить пары с максимальным EE (bipartite matching).

    Real-time;

    Не зависит от detector;

    Работает с толпой.

    Сложная группировка;

6. Oriented Bounding Box (OBB) Detection
A. Задача в отрыве от моделей
1.1. Постановка

Oriented Bounding Box Detection (детекция ориентированных ограничивающих рамок) — это задача detection, где вместо обычного axis-aligned bbox (выровненного по осям) предсказывается повёрнутый прямоугольник с углом наклона.

Формально:

    Вход: изображение x∈RH×W×Cx∈RH×W×C.

    Выход: множество детекций
    D={(bi,ci,si)}i=1M
    D={(bi​,ci​,si​)}i=1M​

    где:

        bi=(xc,yc,w,h,θ)bi​=(xc​,yc​,w,h,θ) — 5 параметров вместо 4;

        ci∈{1,…,K}ci​∈{1,…,K} — класс;

        si∈[0,1]si​∈[0,1] — confidence.

Пять параметров OBB:

    xc,ycxc​,yc​ — центр прямоугольника;

    ww — ширина (обычно вдоль «длинной» оси);

    hh — высота (перпендикулярно ширине);

    θθ — угол поворота.

Альтернативные параметризации:

    OpenCV-формат: (xc,yc,w,h,θ)(xc​,yc​,w,h,θ), где θ∈[−90°,0°)θ∈[−90°,0°).

    8-точечный: (x1,y1,x2,y2,x3,y3,x4,y4)(x1​,y1​,x2​,y2​,x3​,y3​,x4​,y4​) — четыре угла.

    6-параметрический: (x1,y1,x2,y2,h)(x1​,y1​,x2​,y2​,h) — две противоположные вершины + высота.

Ключевое отличие от обычного detection:
	Axis-aligned bbox	Oriented bbox
Параметров	4 (x1,y1,x2,y2x1​,y1​,x2​,y2​)	5 (xc,yc,w,h,θxc​,yc​,w,h,θ)
Ориентация	Всегда горизонтальная	Произвольный угол
Покрытие объекта	Плохое при наклоне	Точное
IoU	Простой	Сложный (rotated IoU)

Пример: самолёт на аэроснимке под углом 45°. Axis-aligned bbox захватит много фона (треугольники по углам). Oriented bbox точно обведёт самолёт.
1.2. Почему обычный bbox неприменим

Проблема 1: Избыточный фон.

Для наклонного объекта axis-aligned bbox:

    площадь bbox = w⋅h⋅(cos⁡θ+sin⁡θ)w⋅h⋅(cosθ+sinθ);

    для θ=45°θ=45°: площадь в 2≈1.412
    ​≈1.41 раза больше;

    для тонких длинных объектов (корабли, самолёты, мосты) — ещё хуже.

Проблема 2: Заниженный IoU.

Если истинный объект повёрнут, а предсказание — axis-aligned:
IoU=∣A∩B∣∣A∪B∣
IoU=∣A∪B∣∣A∩B∣​

Для повёрнутого прямоугольника IoU с axis-aligned bbox может быть < 0.5, даже если объект найден правильно. Это ломает метрики и NMS.

Проблема 3: NMS удаляет правильные детекции.

Если два объекта расположены рядом под углом, их axis-aligned bbox сильно перекрываются → NMS удаляет один из них.

Проблема 4: Неточная локализация.

Для задач, где важна точная граница (аэроснимки, документы, text detection), axis-aligned bbox недостаточен.

Где нужен OBB:

    Аэроснимки и спутниковые изображения:

        корабли, самолёты, здания, мосты;

        объекты ориентированы произвольно.

    Text detection:

        текст под углом;

        вывески, номера машин.

    Промышленность:

        детали на конвейере;

        дефекты под углом.

    Медицина:

        клетки, органы;

        ориентированные структуры.

    Документы:

        сканы под углом;

        таблицы, формы.

    Robotics:

        объекты для захвата;

        ориентированные поверхности.

1.4. Метрики
Rotated IoU

Главная сложность: IoU для повёрнутых прямоугольников не имеет простой формулы.

Способы вычисления:

    Полигональный подход:

        Представить каждый OBB как полигон из 4 точек;

        Вычислить пересечение полигонов (Sutherland-Hodgman);

        Площадь пересечения → IoU.

    Triangulation:

        Разбить пересечение на треугольники;

        Суммировать площади.

    Аналитический (для двух прямоугольников):

        Сложно, много случаев.

Формально:
Rotated IoU=∣A∩B∣∣A∣+∣B∣−∣A∩B∣
Rotated IoU=∣A∣+∣B∣−∣A∩B∣∣A∩B∣​

где ∣A∩B∣∣A∩B∣ — площадь пересечения двух повёрнутых прямоугольников.

Проблема: Rotated IoU не дифференцируем по углу, что затрудняет обучение.
Альтернативы Rotated IoU

    Gaussian IoU:

        Каждый OBB → 2D Gaussian;

        IoU → расстояние между Gaussian;

        Дифференцируемо.

    ProbIoU:

        Вероятностная интерпретация;

        Замкнутая формула;

        Дифференцируемо.

    KLD (Kullback-Leibler Divergence):

        Расстояние между распределениями;

        Для loss-функции.

mAP для OBB

    mAP@0.5 — Rotated IoU threshold 0.5;

    mAP@0.5:0.95 — усреднение по порогам;

    Алгоритм тот же, что в обычном detection, но IoU — rotated.

DOTA метрики:

    mAP — mean Average Precision;

    AP@0.5, AP@0.75;

    mAP@0.5:0.95.

Проблема periodicity угла

Ключевая сложность: угол θθ и θ+180°θ+180° описывают один и тот же прямоугольник, если поменять ww и hh местами:
(xc,yc,w,h,θ)≡(xc,yc,h,w,θ+90°)
(xc​,yc​,w,h,θ)≡(xc​,yc​,h,w,θ+90°)
(xc,yc,w,h,θ)≡(xc,yc,w,h,θ+180°)
(xc​,yc​,w,h,θ)≡(xc​,yc​,w,h,θ+180°)

Последствия:

    Loss по углу: если истинный угол 0°0°, а предсказанный 179°179°, MSE даст огромную ошибку, хотя визуально это почти одно и то же.

    NMS: два предсказания с углами 1°1° и 179°179° могут быть одним объектом.

    Обучение: модель не может стабильно выучить угол.

Решения:

    Ограничение диапазона:

        θ∈[−90°,0°)θ∈[−90°,0°) (OpenCV);

        Или θ∈[−45°,135°)θ∈[−45°,135°);

        Но проблема на границах остаётся.

    Угол как классификация:

        Разбить 360°360° на BB бинов;

        Предсказывать распределение по бинам;

        Пример: CSL (Circular Smooth Label).

    Угол как вектор:

        Предсказывать (cos⁡θ,sin⁡θ)(cosθ,sinθ);

        Или (cos⁡2θ,sin⁡2θ)(cos2θ,sin2θ) для учёта 180°180°-периодичности;

        Loss — косинусное расстояние.

    Rotation-aware loss:

        Учитывать периодичность в loss;

        Пример: Rotated IoU loss, ProbIoU loss.

    Определение «длинной» стороны:

        Всегда w≥hw≥h;

        Тогда θ∈[−90°,90°)θ∈[−90°,90°);

        Убирает неоднозначность w↔hw↔h.

    KLD / Gaussian loss:

7. Multi-Object Tracking (MOT)
A. Задача в отрыве от моделей
1.1. Постановка

Multi-Object Tracking — это задача, где модели нужно не просто найти объекты на отдельном кадре, а сохранить идентичность (identity) каждого объекта через последовательность кадров видео.

Формально:

    Вход: последовательность кадров {xt}t=1T{xt​}t=1T​, где xt∈RH×W×Cxt​∈RH×W×C.

    Выход: для каждого кадра — множество треков:
    Tt={(bit,cit,idit,sit)}i=1Mt
    Tt​={(bit​,cit​,idit​,sit​)}i=1Mt​​

    где:

        bitbit​ — bbox объекта ii в кадре tt;

        citcit​ — класс;

        iditidit​ — уникальный идентификатор трека (целое число);

        sitsit​ — confidence.

Ключевое отличие от detection:
	Detection	Tracking
Вход	одно изображение	последовательность кадров
Выход	bbox + класс	bbox + класс + ID
Задача	найти объекты	найти + связать объекты во времени
Идентичность	Нет	Есть

Что значит «сохранить identity»:

    Если человек появился в кадре 1 с ID=5, то в кадре 2, 3, ..., пока он в кадре, у него должен быть тот же ID=5.

    Если он ушёл и вернулся — по возможности тот же ID.

    Два разных человека не должны получить один ID.

Формально: MOT = detection на каждом кадре + ассоциация детекций между кадрами.
1.2. Ключевые проблемы
Occlusion (перекрытие)

Объект может быть временно перекрыт другим объектом или вышел из кадра.

Виды:

    Partial occlusion — часть объекта видна;

    Full occlusion — объект полностью скрыт;

    Self-occlusion — объект перекрывает сам себя (например, человек в позе);

    Crowd occlusion — много объектов, плотно перекрывающихся.

Проблема: detector может не найти объект при полном перекрытии. Tracker должен «помнить» его и восстановить ID после появления.
ID switch (id-switch)

Объект получает новый ID или его ID переходит другому объекту.

Причины:

    Ошибка detector'а;

    Ошибка ассоциации;

    Долгая окклюзия;

    Похожие объекты.

ID switch — главная проблема MOT. Метрика IDF1 и IDs (ID switches) измеряют её.
Re-identification (ReID)

После долгого отсутствия объект возвращается в кадр. Нужно узнать его и присвоить тот же ID.

Проблемы:

    Изменение внешнего вида (освещение, поза, ракурс);

    Изменение масштаба;

    Другие объекты похожего вида.

ReID — отдельная задача, часто используется как компонент MOT.
Другие проблемы

    Масштаб: объекты могут быть разного размера;

    Скорость: объекты могут двигаться быстро;

    Появление/исчезновение: объекты входят и выходят из кадра;

    Похожие объекты: одинаково одетые люди, одинаковые машины;

    Камера: движение камеры, смена ракурса;

    Реальное время: нужно обрабатывать 30+ FPS.

1.4. Метрики
MOTA — Multi-Object Tracking Accuracy
MOTA=1−∑t(FNt+FPt+IDSt)∑tGTt
MOTA=1−∑t​GTt​∑t​(FNt​+FPt​+IDSt​)​

где:

    FNtFNt​ — false negatives (пропущенные объекты);

    FPtFPt​ — false positives (лишние детекции);

    IDStIDSt​ — ID switches;

    GTtGTt​ — число истинных объектов в кадре tt.

Смысл: комбинированная метрика, учитывающая пропуски, ложные срабатывания и смены ID.

Проблема: может быть отрицательной (если ошибок больше, чем объектов). Не учитывает, насколько хорошо сохраняется ID.
IDF1
IDF1=2⋅IDTP2⋅IDTP+IDFP+IDFN
IDF1=2⋅IDTP+IDFP+IDFN2⋅IDTP​

где:

    IDTPIDTP — истинно положительные по ID;

    IDFPIDFP — ложные по ID;

    IDFNIDFN — пропущенные по ID.

Смысл: F1-мера по идентичности, а не по кадрам. Показывает, насколько хорошо трекер сохраняет ID.

IDF1 vs MOTA:

    MOTA фокусируется на detection-ошибках;

    IDF1 фокусируется на association-ошибках;

    Хороший трекер должен иметь высокие обе.

HOTA — Higher Order Tracking Accuracy
HOTA=DetA⋅AssA
HOTA=DetA⋅AssA
​

где:

    DetADetA — detection accuracy;

    AssAAssA — association accuracy.

Смысл: балансирует detection и association. Считается более справедливой, чем MOTA.

HOTA разбивается на:

    DetA — насколько хорошо детектируются объекты;

    AssA — насколько хорошо связываются;

    LocA — насколько точны bbox;

    HOTA — общая.

Другие метрики

    MT (Mostly Tracked) — доля треков, отслеженных ≥ 80% времени;

    ML (Mostly Lost) — доля треков, отслеженных ≤ 20% времени;

    IDs (ID Switches) — число смен ID;

    FM (Fragmentations) — число разрывов треков;

    MOTP — средняя ошибка локализации;

    AMOTA — для 3D MOT.

HOTA	detection + association	Сбалансированная	Сложнее

B. Архитектуры и алгоритмы
2.1. Разделение на два слоя

Ключевая идея MOT: это не одна модель, а pipeline из двух компонентов:

    Detector (YOLO, Faster R-CNN) → bbox на каждом кадре.

    Association algorithm → связывание bbox в треки.

Почему так:

    Detector можно менять независимо;

    Association можно менять независимо;

    Легче отлаживать;

    Можно использовать SOTA detector и SOTA association.

Pipeline:
text

Frame t → Detector → Detections_t → Association → Tracks_t
                ↑                              ↓
                └──────── Kalman filter ───────┘

Компоненты association:

    Motion model: предсказание положения объекта (Kalman filter).

    Appearance model: эмбеддинги для ReID.

    Matching: сопоставление детекций с треками (Hungarian algorithm).

    Track management: создание, удаление, обновление треков.

2.2. SORT (2016)

Simple Online and Realtime Tracking — базовый алгоритм.

Компоненты:

    Detector: Faster R-CNN (в оригинале).

    Kalman filter: предсказание положения.

    Hungarian algorithm: сопоставление.

    IoU: метрика близости.

Kalman filter:

Состояние объекта:
x=[u,v,s,r,u˙,v˙,s˙]T
x=[u,v,s,r,u˙,v˙,s˙]T

где:

    (u,v)(u,v) — центр bbox;

    ss — площадь;

    rr — соотношение сторон;

    (u˙,v˙,s˙)(u˙,v˙,s˙) — скорости.

Предсказание:
xt∣t−1=Fxt−1∣t−1
xt∣t−1​=Fxt−1∣t−1​
Pt∣t−1=FPt−1∣t−1FT+Q
Pt∣t−1​=FPt−1∣t−1​FT+Q

Обновление:
Kt=Pt∣t−1HT(HPt∣t−1HT+R)−1
Kt​=Pt∣t−1​HT(HPt∣t−1​HT+R)−1
xt∣t=xt∣t−1+Kt(zt−Hxt∣t−1)
xt∣t​=xt∣t−1​+Kt​(zt​−Hxt∣t−1​)

Hungarian algorithm:

Строится матрица стоимостей:
Cij=1−IoU(di,tj)
Cij​=1−IoU(di​,tj​)

где didi​ — детекция, tjtj​ — трек.

Задача: найти оптимальное сопоставление с минимальной стоимостью.

Алгоритм:

    Предсказать положение треков (Kalman).

    Вычислить IoU между детекциями и предсказанными треками.

    Hungarian algorithm → сопоставление.

    Обновить треки.

    Создать новые треки для несопоставленных детекций.

    Удалить треки, не обновлённые NN кадров.

Плюсы:

    Простой;

    Быстрый (260+ FPS);

    Хороший baseline.

Минусы:

    Нет appearance-модели;

    Плохо при окклюзиях;

    Много ID switches;

    Не работает при движении камеры.

2.3. DeepSORT (2017)

Deep SORT = SORT + appearance model.

Ключевое добавление: ReID-эмбеддинги для каждого объекта.

Компоненты:

    Detector: Faster R-CNN / YOLO.

    Kalman filter: как в SORT.

    Appearance model: CNN для эмбеддингов.

    Matching: комбинация motion + appearance.

Appearance model:

    CNN (в оригинале — deep cosine metric learning);

    Для каждого bbox — эмбеддинг e∈R128e∈R128;

    Нормализованный.

Matching:
Cij=λ⋅dmotion(i,j)+(1−λ)⋅dappearance(i,j)
Cij​=λ⋅dmotion​(i,j)+(1−λ)⋅dappearance​(i,j)

где:

    dmotiondmotion​ — Mahalanobis distance от Kalman;

    dappearancedappearance​ — косинусное расстояние между эмбеддингами.

Каскадное сопоставление:

2.4. ByteTrack (2021)

Ключевая идея: использовать low-confidence detections для трекинга.

Проблема: обычные трекеры отбрасывают детекции с низким confidence. Но при окклюзии объект может иметь низкий confidence — и трек теряется.

Решение ByteTrack:

    Разделить детекции на high и low по confidence.

    Сопоставить high-детекции с треками (как обычно).

    Сопоставить low-детекции с оставшимися треками (по IoU).

    Это позволяет восстановить треки при окклюзии.

Алгоритм:
text

1. Detections → high (conf > τ), low (τ > conf > 0.1)
2. Kalman predict
3. Match high detections with tracks (IoU + Hungarian)
4. Match low detections with unmatched tracks (IoU + Hungarian)
5. Create new tracks for unmatched high detections
6. Delete tracks not updated for N frames

Почему работает:

    Low-детекции часто соответствуют реальным объектам при окклюзии;

    IoU-матчинг достаточно надёжен;

    Нет appearance-модели → быстрее.

Плюсы:

    SOTA на MOT17, MOT20;

    30+ FPS;

    Простой;

    Не нужен ReID.

Минусы:

    Нет appearance;

    Плохо при похожих объектах;

    Зависит от detector'а.

8. Depth Estimation
A. Задача в отрыве от моделей
1.1. Постановка

Depth Estimation (оценка глубины) — это задача, где модели нужно по изображению предсказать расстояние от камеры до каждой точки сцены.

Формально:

    Вход: изображение x∈RH×W×Cx∈RH×W×C.

    Выход: карта глубины
    D^∈RH×W
    D^∈RH×W

    где D^(u,v)D^(u,v) — расстояние до точки, спроецированной в пиксель (u,v)(u,v).

Ключевое отличие от всех предыдущих задач:
Задача	Выход
Classification	один класс
Detection	bbox + класс
Segmentation	класс на пиксель
Pose	keypoints
Depth Estimation	непрерывное значение на пиксель

Это регрессия на каждом пикселе, а не классификация.

Разновидности:

    Monocular Depth Estimation (MDE): по одному изображению с одной камеры.

    Stereo Depth Estimation: по паре изображений (стерео).

    Multi-view Depth Estimation: по нескольким видам.

    RGB-D Depth Estimation: с использованием depth-сенсора как вход.

    Video Depth Estimation: по последовательности кадров.

В плане фокус на monocular depth estimation — самой сложной и интересной постановке.
1.2. Почему monocular depth — ill-posed задача

Фундаментальная проблема: по одному 2D-изображению невозможно однозначно восстановить 3D-структуру сцены.

Причина: проецирование 3D → 2D теряет информацию. Бесконечно много 3D-сцен могут дать одно и то же 2D-изображение.

Пример: маленький объект близко и большой объект далеко могут выглядеть одинаково.

Формально: проекция
π:R3→R2
π:R3→R2

не является инъективной — многие 3D-точки проецируются в один пиксель.

Scale ambiguity: даже если модель восстановит относительную глубину, абсолютный масштаб неизвестен. Например, игрушечная машинка и настоящая машинка могут выглядеть одинаково, но расстояния различаются в разы.

Вывод: monocular depth — принципиально ill-posed задача без дополнительных предположений.
1.3. Почему это всё-таки возможно

Модель учится на монокулярных cues — признаках, которые коррелируют с глубиной:
Перспектива

    Параллельные линии сходятся в точке схода;

    Чем дальше объект, тем ближе он к точке схода;

    Размер объекта на изображении обратно пропорционален расстоянию:
    sizeimage∝1Z
    sizeimage​∝Z1​

Относительный размер

    Машина обычно больше человека;

    Если машина на изображении меньше человека — она дальше;

    Модель учит типичные размеры объектов.

Текстура

    Чем дальше поверхность, тем мельче текстура;

    Градиент текстуры коррелирует с глубиной.

Окклюзия

    Если объект A перекрывает объект B, то A ближе;

    T-junctions — важный cue.

Тени и освещение

    Тени дают информацию о расположении объектов;

    Освещение — о форме поверхностей.

Defocus blur

    Чем дальше объект, тем более размыт (при фиксированной фокусировке);

    Глубина резкости коррелирует с глубиной.

Атмосферная перспектива

    Далёкие объекты более размытые и менее контрастные;

    Туман, дымка.

Знание сцены

    Модель учит типичные сцены: дорога уходит вдаль, небо далеко, стены вертикальны;

    Это semantic prior.

Ключевая идея: хотя задача ill-posed математически, статистически она разрешима: модель учит p(depth∣image)p(depth∣image) на большом датасете.

Ограничения:

    Работает только для сцен, похожих на обучающие;

    Абсолютный масштаб не восстанавливается без дополнительной информации;

    Возможны систематические ошибки на нетипичных сценах.

9. Open-Vocabulary Detection
A. Задача в отрыве от моделей
1.1. Постановка

Open-Vocabulary Detection (OVD) — это задача detection, где модель должна находить объекты по произвольному текстовому запросу, а не только по классам, зафиксированным при обучении.

Формально:

    Вход:

        изображение x∈RH×W×Cx∈RH×W×C;

        текстовый запрос qq (например, «красная чашка», «человек в шляпе», «собака»).

    Выход: множество детекций
    D={(bi,si)}i=1M
    D={(bi​,si​)}i=1M​

    где:

        bibi​ — bbox;

        sisi​ — confidence;

        класс не фиксирован — он определяется запросом qq.

Ключевое отличие от обычного detection:
	Closed-vocabulary	Open-vocabulary
Классы	Фиксированы при обучении	Произвольные
Вход	Только изображение	Изображение + текст
Выход	Класс из KK	Соответствие запросу
Новые классы	Нужно переобучение	Работает zero-shot

Пример:

    Обычный YOLO, обученный на COCO (80 классов), не найдёт «красную чашку», если такого класса не было.

    Open-vocabulary модель найдёт её по текстовому запросу, даже если никогда не видела этот класс при обучении.

Разновидности:

    Zero-shot detection: детекция классов, не виденных при обучении.

    Open-vocabulary detection: детекция по произвольному тексту.

    Open-set detection: детекция + отказ от неизвестных классов.

    Referring expression detection: детекция по описанию («человек слева от машины»).

1.2. Зачем это нужно

Проблема closed-vocabulary detection:

    Фиксированный набор классов. Модель знает только те классы, на которых обучалась.

    Переобучение под новые классы. Каждый раз, когда нужен новый класс, нужно:

        собрать данные;

        разметить;

        переобучить;

        это дорого и долго.

    Длинный хвост. В реальном мире классов гораздо больше, чем в COCO.

    Контекстные запросы. Иногда нужно найти не «собаку», а «собаку на поводке у женщины в красном».

Что даёт open-vocabulary:

    Гибкость. Можно задать любой класс в момент инференса.

    Zero-shot. Не нужно переобучение под новые классы.

    Единая модель. Одна модель для множества задач.

    Интерфейс на естественном языке. Пользователь пишет запрос — модель находит.

    Комбинируемость. Можно комбинировать классы, атрибуты, отношения.

Применения:

    Поиск по изображениям: найти все объекты по описанию;

    Робототехника: найти объект по команде;

    AR/VR: интеракция с объектами;

    Автономное вождение: редкие объекты;

    Медицина: редкие патологии;

    E-commerce: поиск товаров;

    Видеонаблюдение: поиск по описанию.

1.3. Принципиальная идея

Совмещение visual и text embedding space.

Ключевая идея: если изображение и текст, описывающий его, находятся в общем пространстве эмбеддингов, то можно:

    Закодировать изображение (или его часть) в вектор;

    Закодировать текст в вектор;

    Сравнить их (косинусное расстояние);

    Если близко — объект соответствует запросу.

Формально:
sim(x,q)=fimg(x)⋅ftext(q)∥fimg(x)∥⋅∥ftext(q)∥
sim(x,q)=∥fimg​(x)∥⋅∥ftext​(q)∥fimg​(x)⋅ftext​(q)​

где:

    fimgfimg​ — image encoder;

    ftextftext​ — text encoder.

Почему это работает:

    Модель обучается на парах (изображение, текст);

    Похожие по смыслу пары сближаются в пространстве;

    Непохожие — отдаляются;

    Это contrastive learning, тот же принцип, что в SSL.

Для detection:

    Нужно не просто сравнить всё изображение с текстом;

    Нужно найти регионы, соответствующие тексту;

    Регион → эмбеддинг → сравнение с текстовым эмбеддингом.

1.4. CLIP — база для open-vocabulary

CLIP (Contrastive Language-Image Pre-training, 2021) — ключевая работа, сделавшая open-vocabulary возможным.
Архитектура

    Image encoder: ResNet или ViT;

    Text encoder: Transformer;

    Оба проецируют в общее пространство RdRd.

Формально:
v=fimg(x)∈Rd
v=fimg​(x)∈Rd
t=ftext(q)∈Rd
t=ftext​(q)∈Rd

Нормализуются:
v^=v∥v∥,t^=t∥t∥
v^=∥v∥v​,t^=∥t∥t​

Сходство:
s=v^⊤t^
s=v^⊤t^
Обучение

    Датасет: 400M пар (изображение, текст) из интернета;

    Contrastive loss (InfoNCE):

L=−1N∑i=1Nlog⁡exp⁡(sii/τ)∑j=1Nexp⁡(sij/τ)
L=−N1​i=1∑N​log∑j=1N​exp(sij​/τ)exp(sii​/τ)​

где:

    siisii​ — сходство правильной пары;

    sijsij​ — сходство с неправильными;

    ττ — температура.

Смысл: максимизировать сходство правильных пар, минимизировать — неправильных.
Zero-shot classification

Для класса cc формируется текст «a photo of a {c}». Затем:
p(c∣x)=exp⁡(v^⊤t^c)∑c′exp⁡(v^⊤t^c′)
p(c∣x)=∑c′​exp(v^⊤t^c′​)exp(v^⊤t^c​)​

Это позволяет классифицировать по произвольным классам без обучения.
Ограничения CLIP

    Только глобальное сходство. CLIP сравнивает всё изображение с текстом, не локализует.

    Нет плотного предсказания. Не работает для detection/segmentation напрямую.

    Слабое пространственное понимание. Плохо с отношениями («слева от», «над»).

    Чувствительность к формулировке. «Собака» и «пёс» могут дать разные результаты.

    Не различает похожие классы. Тонкие различия теряются.

Вывод: CLIP — база, но для detection нужны дополнительные механизмы локализации.

    Тестируется на novel classes;

1.6. Проблемы OVD

    Локализация. CLIP не локализует — нужно добавить detection head.

    Alignment. Visual и text пространства должны быть согласованы.

    Fine-grained. Тонкие различия между классами.

    Отношения. «Собака слева от машины» — сложно.

    Атрибуты. «Красная чашка» vs «чашка».

    Композициональность. «Кошка на столе» — нужно понимать и объект, и отношение.

    Domain gap. CLIP обучен на интернете, не на специфичных доменах.

    Скорость. Text encoder работает на инференсе.

    Русский язык. Большинство моделей — на английском.

    Точность ниже Grounding DINO;

    Ограниченная композициональность;

    Зависит от CLIP.

YOLO-World v2:

    Улучшенная архитектура;

    Лучше на LVIS;

    Быстрее.

2.10. Обучение OVD
Датасеты

    Base classes: COCO, Objects365, OpenImages;

    Novel classes: LVIS, OV-COCO;

    Grounding: GoldG, Flickr30k, VG.

Стратегии

    Zero-shot: обучение только на base, тест на novel;

    Few-shot: несколько примеров novel;

    Generalized: тест на base + novel;

    Self-training: псевдо-разметка.

Loss-функции

Detection loss:
Ldet=Lcls+Lbox
Ldet​=Lcls​+Lbox​

Alignment loss:
Lalign=−log⁡exp⁡(spos/τ)∑exp⁡(s/τ)
Lalign​=−log∑exp(s/τ)exp(spos​/τ)​

Contrastive:
Lcontrast=−1N∑ilog⁡exp⁡(sii/τ)∑jexp⁡(sij/τ)
Lcontrast​=−N1​i∑​log∑j​exp(sij​/τ)exp(sii​/τ)​

Комбинированные:
L=Ldet+λLalign
L=Ldet​+λLalign​
2.11. Промптинг

Качество промпта влияет на результат.

Страategies:

    Простой промпт: «dog»;

    Шаблон: «a photo of a dog»;

    Ансамбль: несколько шаблонов, усреднение;

    Описательный: «a brown dog running»;

    Negative prompts: «dog, not cat».

Prompt engineering:

    Разные формулировки дают разные результаты;

    Ансамбль промптов улучшает точность;

    Для специфичных доменов — domain-specific промпты.

2.12. Композициональность

Проблема: OVD плохо работает с:

    Атрибутами: «красная чашка»;

    Отношениями: «собака слева от машины»;

    Композициями: «кошка на столе».

Решения:

    Compositional CLIP: обучение на композициях;

    Scene graph: явное моделирование отношений;

    LLM + detector: LLM разбивает запрос на части;

    Attribute-aware: отдельные головы для атрибутов.

Пример pipeline:
text

"красная чашка на столе" → LLM → ["красная чашка", "стол"] → detector → bbox

2.13. Оценка

Протоколы:

    Zero-shot: base → novel;

    Generalized: base + novel;

    Cross-dataset: обучение на COCO, тест на LVIS.

Метрики:

    AP_novel — главная;

    AP_base — сохранение базовых;

    AP — общая;

    Recall@K — для retrieval.

Проблемы оценки:

    Разные split'ы;

    Разные промпты;

    Разные backbone.

2.16. Что важно вынести из пункта 9

    Open-Vocabulary Detection: детекция по произвольному текстовому запросу.

    Идея: совмещение visual и text embedding space.

    CLIP: contrastive image-text обучение, база для OVD.

    Метрики: AP_novel, AP_base, mAP.

    Подходы: region-based (ViLD, RegionCLIP), dense (GLIP, Grounding DINO).

    YOLO-World: real-time OVD, RepVL-PAN, prompt-then-detect.

    YOLO26-OV: NMS-free, multi-task.

    Обучение: base + novel, contrastive + detection loss.

    Проблемы: композициональность, fine-grained, скорость.

    Применения: поиск, робототехника, AR, e-commerce.

Итоговая последовательность прохождения

Все 9 пунктов плана пройдены:

    Image Classification — фундамент: backbone, ResNet, ViT.

    Object Detection — ядро: IoU, mAP, NMS, YOLO, RT-DETR.

    Semantic Segmentation — попиксельная классификация: FCN, U-Net, DeepLab.

    Instance Segmentation — пересечение detection и semantic: Mask R-CNN, YOLACT, YOLO-seg.

    Pose Estimation — keypoints: OpenPose, HRNet, YOLO-pose.

    OBB Detection — повёрнутые bbox: ProbIoU, YOLO-OBB.

    Multi-Object Tracking — identity через кадры: SORT, DeepSORT, ByteTrack, BoT-SORT.

    Depth Estimation — расстояние: MiDaS, DPT, Depth Anything, YOLO-depth.

    Open-Vocabulary Detection — детекция по тексту: CLIP, GLIP, Grounding DINO, YOLO-World.

Ключевые сквозные темы:

    Backbone — общий для всех задач (ResNet, ViT, Swin, C2f).

    Heads — специализированные под задачу.

    Loss — cross-entropy, IoU, Dice, SILog, contrastive.

    YOLO-фреймворк — unified для detection, segmentation, pose, OBB, depth, OVD.

    Тренды: anchor-free → NMS-free → multi-task → open-vocabulary.

    CLIP — связующее звено между vision и language.
