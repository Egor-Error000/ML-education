# План: Работа с категориальными признаками — от кодирования к продвинутым методам

Принцип для каждой темы: **сначала проблема в отрыве от конкретного метода**
(что именно ломается при наивном подходе, почему) → **потом методы**,
решающие эту проблему, с механикой и trade-off'ами.

Порядок тем — от базового кодирования к статистическим методам, затем к
специфике конкретных моделей (бустинг, нейросети) и, наконец, к смежным
проблемам данных, которые обычно всплывают вместе с категориальными признаками.

---

## 1. Базовое кодирование и его границы применимости

**Проблема в отрыве от методов:**
- Постановка: модели работают с числами, категории — не числа; нужен способ перевести одно в другое, не внося ложной информации
- Опасность №1: label encoding вносит фиктивный порядок там, где его нет (категория "3" не "больше" категории "1")
- Опасность №2: one-hot трактует все категории как равноудалённые — даже когда часть из них семантически ближе друг к другу

**Методы:**
- One-Hot Encoding — N категорий → N бинарных столбцов; безопасно для линейных моделей и деревьев, ломается при высокой кардинальности
- Label / Ordinal Encoding — категория → целое число; корректно **только** для признаков с естественным порядком (размер S/M/L/XL, уровень образования)
- Dummy Encoding — one-hot минус один столбец (baseline-категория неявно кодируется всеми нулями) — устраняет мультиколлинеарность для линейных моделей (проблема dummy variable trap)

---

## 2. Проблема высокой кардинальности

*(Разбирали основательно — здесь: карта проблемы + один метод, который не обсуждали.)*

**Проблема в отрыве от методов:**
- One-hot при тысячах уникальных категорий → разреженная матрица, замедление обучения, ухудшение сплитов в деревьях
- Новые категории в проде, которых не было в трейне — ломают fixed-size one-hot представление

**Методы:**
- Frequency / Count Encoding — категория → частота её встречаемости; дёшево, без риска утечки таргета, но полезно только если сама частота несёт сигнал
- Hashing Trick — категория → hash(category) % N бакетов; фиксированная размерность независимо от кардинальности, работает "на лету" с новыми категориями, но вносит коллизии (разные категории схлопываются в один бакет)
- **Смежное, не обсуждали:** Feature Hashing с несколькими независимыми хеш-функциями (как в Bloom filter) — снижает вероятность катастрофической коллизии за счёт нескольких хешей на одну категорию вместо одного

---

## 3. Target Encoding (Mean Encoding)

*(Разбирали подробно с числовым примером — здесь: карта метода + смежные варианты.)*

**Проблема в отрыве от методов:**
- Постановка: заменяем категорию на статистику таргета по этой категории — превращаем 1 категориальный столбец в 1 числовой, а не в N бинарных
- Ключевая опасность: прямая утечка (leakage) — если считать статистику по всей выборке разом, признак начинает буквально содержать ответ

**Методы:**
- Базовый Target/Mean Encoding — среднее таргета по категории
- K-Fold Target Encoding — статистика для каждой строки считается по **остальным** фолдам, не включая её саму — устраняет прямую утечку
- Smoothing (сглаживание) — притягивание оценки редких категорий к глобальному среднему через взвешивание по количеству наблюдений: `(count * cat_mean + w * global_mean) / (count + w)`
- CatBoost Ordered Target Encoding — статистика считается только по объектам, идущим раньше текущего в случайной перестановке; устраняет утечку без ручного K-fold
- **Смежное, не обсуждали:** Leave-One-Out Encoding — вариант K-fold в пределе: для каждой строки статистика считается по всем остальным строкам **кроме неё самой** (не по фолдам, а буквально построчно) — сильнее защищает от утечки на очень маленьких датасетах, но дороже вычислительно
- **Смежное, не обсуждали:** Weight of Evidence (WoE) Encoding — специфика кредитного скоринга: log(P(target=1|category) / P(target=0|category)) — по сути логарифм отношения шансов вместо голого среднего, связан с логистической регрессией напрямую и традиционно требуется в некоторых регулируемых индустриях (банкинг) как интерпретируемый стандарт

## 4. Обучаемые представления категорий (нейросетевой подход)

**Проблема в отрыве от методов:**
- Постановка: one-hot и target encoding задают признак **до** обучения основной модели; но иногда лучше позволить модели самой выучить, какие категории "похожи"
- One-hot не даёт понятия близости между категориями в принципе (все равноудалены)

**Методы:**
- Embedding-слои — категория → индекс → learnable вектор фиксированной размерности, обучается вместе с сетью через backprop; стандарт в рекомендательных системах и в NLP (для токенов — тот же принцип)
- **Смежное, не обсуждали:** Entity Embeddings (популяризовано на Kaggle-соревнованиях для табличных данных) — тот же принцип embedding-слоёв, но явно вынесенный как техника для **табличных** данных с категориальными признаками, не только для NLP/recsys; можно обучить отдельно и потом использовать полученные embedding-векторы как признаки для любой другой модели (в том числе для бустинга)
- **Смежное, не обсуждали:** Предобученные категориальные эмбеддинги между задачами — если категория (например, "город", "модель телефона") повторяется в разных датасетах/задачах компании, эмбеддинги можно переиспользовать как transfer learning для табличных данных, а не обучать с нуля каждый раз

## 5. Нативная поддержка категорий в бустинге

**Проблема в отрыве от методов:**
- Постановка: ручное кодирование теряет информацию, которую сам алгоритм построения дерева мог бы использовать напрямую при поиске оптимального разбиения

**Методы:**
- LightGBM categorical support — Fisher-подобный алгоритм оптимального разбиения категорий на группы прямо при построении дерева, без явного кодирования
- CatBoost categorical support — комбинация ordered target encoding (раздел 3) с автоматическими комбинациями категориальных признаков между собой (feature crosses), которые вручную перебрать почти невозможно при большом числе признаков
- **Смежное, не обсуждали:** XGBoost categorical support (experimental, начиная с версии 1.5+) — в отличие от LightGBM/CatBoost исторически требовал ручного one-hot/target encoding; нативная поддержка появилась позже и работает иначе (через одностороннее разбиение по категориям, не Fisher-группировку) — важно знать при сравнении трёх основных бустинг-библиотек на собесе

---

## 6. Взаимодействия между категориальными признаками (Feature Crosses)

*(Логическое продолжение того, что CatBoost делает автоматически — какие есть ручные альтернативы.)*

**Проблема в отрыве от методов:**
- Постановка: иногда сигнал скрыт не в отдельном признаке, а в **комбинации** двух категориальных признаков ("город" × "день недели" может быть информативнее каждого по отдельности)
- Проблема наивного подхода: перемножение "в лоб" двух high-cardinality признаков даёт ещё более высокую кардинальность результата

**Методы:**
- Ручные Feature Crosses — конкатенация значений двух категорий в одну новую категорию, дальше кодируется любым методом выше
- **Смежное, не обсуждали:** Field-aware Factorization Machines (FFM) — модель, изначально спроектированная под задачи с большим числом категориальных признаков и их попарных взаимодействий (реклама/CTR-prediction), где взаимодействия учитываются через факторизацию, а не явный перебор всех пар
- CatBoost's automatic feature crosses (раздел 5) — упомянуть снова как контраст: автоматизированная версия того же принципа

## 7. Множественные категории на одно наблюдение (Multi-valued categorical)

**Проблема в отрыве от методов:**
*(Не обсуждали в чате — логически примыкающая тема, часто всплывает сразу после базового one-hot.)*
- Постановка: иногда одно наблюдение принадлежит **нескольким** категориям одновременно (пользователь интересуется несколькими жанрами фильмов; товар относится к нескольким тегам) — стандартный one-hot тут не подходит напрямую

**Методы:**
- Multi-Hot Encoding — обобщение one-hot: единица ставится в каждый релевантный столбец, а не только в один
- Count-based multi-hot — вместо бинарного флага пишется количество вхождений (если категория может повторяться, например теги с весами)
- Обучаемый pooling эмбеддингов (mean/sum/max-pooling по эмбеддингам всех активных категорий) — нейросетевой аналог multi-hot, стандарт в recsys для признаков типа "список интересов пользователя"

---

## 8. Пропущенные значения в категориальных признаках

**Проблема в отрыве от методов:**
*(Не обсуждали в чате — почти всегда идёт рука об руку с кодированием категорий на практике.)*
- Постановка: пропуск в категориальном признаке — это не то же самое, что пропуск в числовом; часто сам факт пропуска несёт сигнал (например, "не указал доход" коррелирует с чем-то содержательным)

**Методы:**
- "Missing" как отдельная категория — простейший и часто неожиданно сильный baseline: не удалять и не импутировать, а явно завести категорию "NaN"
- Импутация модой (наиболее частой категорией) — годится, если пропусков мало и они действительно случайны (MCAR)
- Индикатор пропуска + импутация — отдельный бинарный признак "было ли значение пропущено", дополнительно к самой импутации, чтобы не терять сигнал о факте пропуска

---

## 9. Специфика временных данных для категориальных признаков

**Проблема в отрыве от методов:**
*(Логически примыкает к target encoding — тот же риск утечки, но в другой форме.)*
- Постановка: если данные упорядочены во времени (временной ряд, лог событий), обычный K-fold target encoding всё равно может протечь "из будущего в прошлое"

**Методы:**
- Time-based Target Encoding — статистика для каждой строки считается только по данным, предшествующим ей по времени (не по случайным фолдам) — это то же самое, что делает CatBoost ordered encoding по своей случайной перестановке, но явно привязанное к реальному времени, а не искусственному порядку
- Rolling/Expanding window statistics по категории — среднее/count не по всей истории сразу, а по скользящему окну — учитывает, что "популярность" категории может со временем меняться (drift)

## Итоговая последовательность прохождения

1. Базовое кодирование и его границы (One-Hot, Label/Ordinal, Dummy)
2. Проблема высокой кардинальности (Frequency, Hashing Trick)
3. Target Encoding (базовый → K-Fold → Smoothing → CatBoost Ordered → LOO → WoE)
4. Обучаемые представления (Embedding-слои, Entity Embeddings)
5. Нативная поддержка в бустинге (LightGBM, CatBoost, XGBoost — сравнение подходов)
6. Взаимодействия признаков (Feature Crosses, FFM)
7. Множественные категории на одно наблюдение (Multi-Hot, pooling эмбеддингов)
8. Пропущенные значения в категориальных признаках
9. Временная специфика (Time-based Target Encoding, rolling statistics)
