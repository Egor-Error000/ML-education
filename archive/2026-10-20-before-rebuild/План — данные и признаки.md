# План модуля: данные и признаки

**Срез: 20 октября 2026.** Новый маршрут объединяет прежние планы [данных](<01-data/План — данные и качество ML-эксперимента.md>) и [категориальных признаков](<03-categorical-features/План — категориальные признаки.md>). Девять глав каждой ветки сохранены: первая отвечает за достоверность эксперимента и данные, вторая — за представления и обработку признаков. Подробные главы и карта их исходников указаны в [редакционной карте курса](<Редакционная карта курса.md>).

## Маршрут

**Общее ядро:** D1–D6 (задача, split, качество, метрики, синтетика/dedup, загрузка) → F1–F6 (тип и преобразования признаков, числовые и категориальные данные, взаимодействия, наборы) → D9 (drift и достоверность вывода в месте применения). Ветви D7/D8 дают специфические данные CV и текста; F7–F9 — временные/пространственные данные, embeddings, отбор и генерацию признаков. Их берут по задаче.

Общее предположение для каждой главы: преобразование, которое учится на выборке, обучается после split и только на train/внутренней обучающей складке. Validation/test получают уже зафиксированное состояние. Для cross-fitted encoding описать отдельную схему; для нового production объекта сохранить mapping/parameters и same transform. Любую тему проверять на утечку её статистик, labels, groups, duplicate relatives, time, document chunks и augmentation lineage.

## Часть I. Данные и достоверность эксперимента

**Критерий каждой главы:** читатель без подсказки выполняет указанный ручной расчёт или решение, объясняет предпосылку и показывает, какая проверка защищает будущую оценку. Для практических глав дополнительно требуется воспроизводимый артефакт; его наличие не подразумевается чтением.

### D1. Постановка задачи, единица наблюдения и паспорт данных

**Уровень:** общее ядро. **Предпосылки:** таблица и основные понятия supervised learning. **Используют:** все модули.

**Сценарий:** определить prediction unit/population/time of prediction → измеряемую цель и цену ошибки → происхождение, схему и ограничения доступа → baseline/metric. Разобрать строки-события, связанные группы и delayed label на одном датасете. Формулы: empirical risk и метрика; назвать estimand и единицу агрегации. Схема: источник → snapshot → объект/метка → split → модель → будущий объект. Практика: заполнить паспорт с доступностью признаков. Ограничения: набор без репрезентативного sampling не определяет будущую популяцию.

### D2. Split, cross-validation и утечки

**Уровень:** общее ядро. **Предпосылки:** D1, индексированные примеры. **Используют:** вся практика.

**Сценарий:** random/stratified → group/time/blocked split → train-only fit → CV/nested tuning → leakage audit. Разобрать, почему group split предотвращает знакомство с тем же субъектом, а temporal split моделирует будущее. Формулы: mean metric over folds; cross-fit target statistic (полное обучение — F3). Числовой пример покажет leakage через duplicated patient и preprocessing до split. Схема имеет data flow для train/validation/test и внутренней CV. Практика: сравнить random и group/time оценку. Ограничения: stratification не устраняет зависимость; test не используется для выбора.

### D3. Пропуски, аномальные значения и качество labels

**Уровень:** общее ядро. **Предпосылки:** D1–D2. **Используют:** F3, F7 и анализ ошибок в каждом модуле.

**Сценарий:** схема/единицы/sentinel → MCAR/MAR/MNAR как предположения → outlier vs valid rare case → annotation protocol/disagreement → audit/repair. Определить missing indicator, imputers и label noise. Пример: одна колонка с невозможной единицей и меткой, где арбитраж разрешает disagreement. Схема: raw → checks → suspect candidates → human review → frozen train-only repair. Практика: slice audit и ручная проверка sample. Ограничения: автоматический score чистоты не доказывает ошибочность строки; удаление редкого случая меняет population.

### D4. Дисбаланс, метрики, decision thresholds и калибровка

**Уровень:** общее ядро. **Предпосылки:** D1–D2 и вероятность. **Используют:** классификация CV/BERT, target encoding и production monitoring.

**Сценарий:** prevalence → confusion matrix/precision/recall/PR vs ROC → weights/resampling → threshold by error cost → calibration. Формулы: PR, F1, Brier/log loss и expected cost; assumptions явно связать с единицей наблюдения. Пример вручную сравнит accuracy и PR при редком событии, затем выберет порог. Схема развести fit, calibration validation и test evaluation. Практика: сравнить no-resampling, weighted loss и threshold. Ограничения: resampling меняет prevalence; калибровка не исправляет ranking.

### D5. Аугментации, синтетические данные и дедупликация

**Уровень:** общее ядро; генерация синтетики — основа ветки по задаче. **Предпосылки:** D1–D4. **Используют:** D7–D8, CV и генерация признаков.

**Сценарий:** преобразование и label-preserving invariance → augmentation → synthetic source/provenance → exact/near dedup → split by duplicate component → held-out real evaluation. Развести data synthesis, dataset distillation и model distillation. Пример: геометрически меняющая метку трансформация и пара почти-дубликатов между folds. Схема показывает lineage и групповой split. Практика: human audit кандидатов MinHash/perceptual hash. Ограничения: у similarity thresholds есть false positives/negatives; синтетический прирост проверять на независимой реальной выборке.

### D6. Загрузка, batching и воспроизводимость

**Уровень:** общее ядро. **Предпосылки:** D1–D2. **Используют:** каждый практический pipeline.

**Сценарий:** manifest/version/hash → dataset/shards → sampler → collate/padding → worker/transfer → checkpoint/restart. Объяснить batching and loss normalization, а не список параметров loader. Пример оценит samples/s и потерю наблюдений после restart. Схема data source → loader → batch → device и контроль возобновления shard cursor. Практика: измерить отдельные bottlenecks и сравнить конфигурации. Ограничения: workers/prefetch зависят от платформы и формы данных; фиксировать seeds и versions.

### D7. Изображения и аннотации

**Уровень:** основа ветки CV; достаточно локального введения. **Предпосылки:** D1–D2; CV-архитектура не нужна. **Используют:** CV B–I.

**Сценарий:** dataset IDs/labels → pixel/tensor representation → coordinate contracts → synchronized augmentation for boxes/masks/keypoints/OBB → sequence-level split → shards. Пример конвертирует одну рамку в xyxy и normalized xywh, проверяя clip/empty target. Схема связывает image, annotation и transform с общим RNG. Практика: визуализировать до/после и сверить IDs. Ограничения: форматные соглашения и angle range задаются dataset/model; video frames делить по source sequence.

### D8. Текст, токенизация и разбиение документов

**Уровень:** основа ветки NLP/LLM; достаточно локального введения. **Предпосылки:** D1–D2. **Используют:** BERT и LLM apps/adaptation.

**Сценарий:** Unicode/normalization → tokenizer vocabulary/byte fallback → roles/templates/masks → truncation/packing → document-level split → chunking/metadata. Разобрать различие SentencePiece framework и алгоритмов, EOS и loss masks. Пример вручную показывает subword offsets, token budget и adjacent chunk leakage. Схема: raw document → normalization → tokenizer → chunks with source IDs → split → batch. Практика: проверить token IDs и target mask. Ограничения: язык и нормализация влияют на coverage; split делается до chunking.

### D9. Drift, интервалы и надёжность вывода

**Уровень:** углубление; для меняющихся production domains — основа ветки. **Предпосылки:** D1–D4, временные данные для time series. **Используют:** оценки всех модулей.

**Сценарий:** covariate/label/concept shift → slice/time metrics → confidence intervals and repeated seeds → paired comparison → monitoring/trigger. Формулы: Wilson/Bootstrap и block/group resampling на правильной единице. Пример покажет узкий row-wise CI при зависимых группах и более честный group bootstrap. Схема: frozen evaluation → slice monitor → relabel → retrain decision. Практика: задать интервал и sensitivity analysis. Ограничения: observed drift не доказывает падение model quality; importance weighting требует assumptions.

## Часть II. Представление и создание признаков

### F1. Типы признаков и контракты представлений

**Уровень:** общее ядро. **Предпосылки:** D1–D2. **Используют:** F2–F9, clustering.

**Сценарий:** nominal/ordinal/count/continuous/time/set/text/image → representation and units → model compatibility → missing/unknown/value ranges. Пример сравнит упорядочивание номинальных кодов с корректным представлением. Схема source field → typed feature → transformation → model. Практика: составить schema contract. Ограничения: integer dtype не означает числовую геометрию; после fit сохранять versioned feature contract.

### F2. Числовые преобразования, масштабирование и пропуски

**Уровень:** общее ядро. **Предпосылки:** F1, D2. **Используют:** F3–F9, regularization, clustering.

**Сценарий:** units/skew/outliers → scaling/normalization/binning/log transforms → train-only fit and serialization → inverse/unknown handling. Формулы: standard/min-max/robust scale и их ranges. Малый пример покажет сдвиг test по train mean и евклидово расстояние до/после scale. Схема sklearn-style pipeline с fit(train) и transform(validation/new). Практика: сравнить unscaled/scaled baseline. Ограничения: scaling меняет metric geometry, не делает распределение нормальным.

### F3. Категориальные представления: словарь, one-hot и частотные кодировки

**Уровень:** общее ядро для табличного маршрута. **Предпосылки:** F1–F2, D2. **Используют:** F4–F6 и все табличные models.

**Сценарий:** nominal/ordinal semantics → one-hot/dummy geometry → high cardinality → count/frequency and signed hashing → dictionary/unknown policy. Формулы: one-hot, frequency и hashing collision expectation (предпосылки независимости пояснить). Пример считает три ID и collision. Схема vocab fit on train → stored map → transform unseen. Практика: memory/quality comparison на фиксированном split. Ограничения: mapping неизвестной категории и hash seed должны быть частью модели.

### F4. Target statistics, WoE и cross-fitting

**Уровень:** общее ядро после F3. **Предпосылки:** D2–D4, условные средние/логарифмы. **Используют:** native boosting, production risk.

**Сценарий:** naive target mean → leakage → out-of-fold encoding → smoothing/prior → ordered/leave-one-out variants → nested validation. Формула: smoothed mean `(n_c μ_c + α μ)/(n_c+α)`, OOF assignment и WoE. Пример ручной на 10 строках. Схема inner folds и transform(validation/test) с полным train statistic. Практика: сравнить naive и OOF, найти target leak. Ограничения: time/group constraints требуют соответствующей складки; test labels never inform encoding.

### F5. Обучаемые embeddings категорий

**Уровень:** основа ветки deep tabular. **Предпосылки:** F3, neural embeddings, backprop; D2. **Используют:** F6 и downstream tasks.

**Сценарий:** embedding lookup → gradients/rare category → pooling/regularization → pretrained/reused table → cold-start/unknown. Вычислить один gradient update на мини-таблице. Схема category ID → row lookup → concatenate → MLP/loss. Практика: frequency slice, unknown bucket и ablation. Ограничения: vector distance может не выражать meaningful relationship; обученные значения привязаны к словарю/task/split.

### F6. Нативные категориальные модели и feature interactions

**Уровень:** общее ядро табличной ветки; interaction networks — углубление. **Предпосылки:** F3–F4 и дерево решений. **Используют:** F5/F8, dataset baseline.

**Сценарий:** partition/category statistics in boosting → compare CatBoost/LightGBM/XGBoost contracts and versions → additive model limit/XOR → manual crosses → FM/FFM. Показать FM identity and sparse interaction score. Схема дерева показывает category grouping, затем отдельная схема pair interactions. Пример XOR неразделимого additive baseline. Практика: compare native model to one-hot with leakage-safe validation. Ограничения: categorical support is implementation/version-specific; encoder dtype and unseen categories must be checked at recheck time.

### F7. Наборы категорий, время и география

**Уровень:** основа ветки по типу данных. **Предпосылки:** F1–F3, D2/D9. **Используют:** recommendation, event, geographic and temporal tasks.

**Сценарий:** set vs multiset vs ordered sequence → multi-hot/count/mean pooling → empty/PAD and weights → event time/availability time → rolling/expanding statistics → geographic locality/time zones. Пример сравнит mean/sum pooling и причинно корректный rolling statistic. Схема event time/label availability/train cutoff. Практика: compute features online for one timeline and check point-in-time values. Ограничения: future feedback/aggregation leakage, timezone boundaries, centroid behavior on wrap-around geography.

### F8. Эмбеддинги и learned representations

**Уровень:** основа ветки representation learning. **Предпосылки:** F1, D2, embeddings; BERT не обязателен. **Используют:** clustering and retrieval.

**Сценарий:** lookup/sequence pooling → learned feature vector → geometric similarity → frozen vs task-trained embeddings → out-of-sample transform. Пример cosine vs Euclidean before/after normalization. Схема raw object → encoder → vector → downstream model. Практика: check neighbors against labels and independent use case. Ограничения: embedding may encode source/shortcut; feature extraction must be fit without test leakage; representation is not explanation.

### F9. Отбор, сокращение и автоматическая генерация признаков

**Уровень:** углубление; основы выбора — основа ветки interpretability. **Предпосылки:** F1–F8, D2/D9. **Используют:** production pipeline.

**Сценарий:** feature quality/missingness → filter/wrapper/embedded selection → multicollinearity/stability → PCA/SVD vs feature selection → relational/time feature synthesis → search budget and validation correction. Пример: correlated features cause unstable ranking; compare selector fitted in each CV fold. Схема: candidate generator → validation-aware search → prune → locked transform. Практика: nested selection with group/time split. Ограничения: feature importance is not causality; AutoFE can overfit validation and explode search space.

## Единый pipeline и production контракт

Каждая глава явно отвечает на четыре вопроса: когда выполняется `fit`; какие объекты/labels/groups/time попадают в fit; что сохраняется после fit; как обрабатывается новый, missing, rare или unknown объект. Общий pipeline: **split by prediction unit → fit transforms only on training fold → validate/select → refit approved transforms on full training split → freeze artifact → transform validation/test/new data with saved state**. Target encoding uses cross-fitting inside the training split. Dedup/group lineage и time availability входят в split contract.
