# Инструменты разовой перестройки

Исторические скрипты переноса и подготовки первой редакции пяти модулей. Сохранены для разбора происхождения материалов; обычная сборка использует только `tools/build_course.cjs`.

- `snapshot_course.py` — сохранение исходного среза.
- `course_blueprint.py`, `migration_content.py`, `migration_topics.py`, `migrate_course.py` — структура и первоначальная миграция.
- `course_diagrams.py` — исходное построение схем.
- `restore_project_protocols.py` — восстановление протоколов проектов BERT.

Пути к корню проекта учитывают архивное размещение. Начальная миграция v2 заблокирована от повторного запуска. Её прежняя отметка о завершении не означает содержательной приёмки редакции v3.

## Разовые операции редакции v3

`prepare_revision_v3.py` проверил исходные байты и Git перед переводом манифестов на канонические окончания строк, вынес служебные маркеры в сайдкар и архивные изображения в активные ресурсы. Повторный запуск запрещён проверкой версии.

`rewrite_*_v3.py` содержат авторские редакции выбранных глав и явные карты старых разделов. `review_*_v3.py` сохраняют индивидуальные назначения прочитанных исходных единиц; это записи уже выполненной сверки, а не автоматический способ принять новую версию текста. `author_scenarios_v3.py` хранит первоначальное авторское задание сценариев; действующие сценарии редактируются в `editorial/chapter-scenarios.json`.

Общие операции очистки контекста и терминологии применялись однократно и затем исправлялись предметным чтением. Их повторный запуск поверх отредактированных глав может вернуть старые формулировки. `refresh_revision_cards_v3.py` обновляет инвентаризацию и хэши, но закрывает только явно перечисленные главы с отдельным свидетельством чтения. Остальные карточки остаются открытыми.

Обычная сборка не запускает ни один из этих скриптов. Текущие главы редактируются вместе с явными диапазонами в `coverage.json` через инструменты `tools/`.

Пакет 02: `batch02_support.py` и `batch02_*.py` хранят авторские переписывания 20 глав и точные карты прежних разделов. Это разовые операции, повторный запуск поверх новой редакции запрещается проверкой исходных привязок/заголовков. `finish_batch02_metadata.py` фиксирует авторские сценарии; `polish_batch02_reading.py` и `fix_batch02_practice.py` — последующие явные исправления. `accept_batch02.py` записывает уже выполненное содержательное чтение только этой партии; `promote_batch02.py` публикует совпадающие отчёты. Эти скрипты не являются способом принять произвольные будущие изменения.
