# План: Задачи Computer Vision — от постановки задачи к архитектурам

Принцип для каждой задачи: **сначала задача в отрыве от моделей** (что это, как
формально ставится, как измеряется, какие классические/базовые подходы) →
**потом архитектуры**, решающие эту задачу, с объяснением механики, включая
соответствующую голову/версию YOLO и 1-2 альтернативных подхода для контраста.

Ядро: классификация → detection и semantic segmentation → instance segmentation. Остальные задачи — независимые прикладные ветки с собственными предпосылками.

---

## 1. Image Classification


**Задача в отрыве от моделей:**
- Постановка: один label на изображение, no localization
- Метрики: accuracy, top-5 accuracy, confusion matrix, precision/recall/F1 по классам
- Базовые подходы: kNN на пикселях/эмбеддингах, простой MLP, лишь затем CNN

**Архитектуры:**
- Классический CNN pipeline: conv → pooling → FC (LeNet/AlexNet как исторический ориентир)
- ResNet — skip-connections, почему они решают vanishing gradient
- YOLO classification head — чем отличается/не отличается от "чистого" классификатора
- ViT (Vision Transformer) — для контраста CNN vs attention-based подход

---

## 2. Object Detection

**Задача в отрыве от моделей:**
- Постановка: множество объектов, каждому — bbox + класс + confidence
- Формат разметки и геометрические преобразования: [CV-данные](../01-data/%D0%9F%D0%BB%D0%B0%D0%BD%20%E2%80%94%20%D0%B4%D0%B0%D0%BD%D0%BD%D1%8B%D0%B5%20%D0%B8%20%D0%BA%D0%B0%D1%87%D0%B5%D1%81%D1%82%D0%B2%D0%BE%20ML-%D1%8D%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D0%B0.md); здесь — только интерпретация выхода и matching.
- Метрики: IoU (Intersection over Union), precision/recall, **mAP** (mean Average
  Precision) — разобрать по шагам, как считается: IoU-порог → TP/FP/FN → precision-recall
  curve → AP → усреднение по классам
- Проблема дубликатов предсказаний → зачем нужен NMS (Non-Maximum Suppression),
  как работает алгоритмически, до знакомства с NMS-free моделями

**Классические подходы (до deep learning эры / ранний DL):**
- Sliding window + классификатор (исторический baseline, почему медленно)
- Two-stage: R-CNN → Fast R-CNN → Faster R-CNN (region proposal + классификация
  отдельно) — важно понять как контраст к one-stage
- One-stage: сама идея YOLO / SSD — почему это было прорывом по скорости

**Архитектуры (в хронологии, которую уже прошли вширь):**
- История YOLO: v1 — прямое предсказание boxes без anchor-механизма v2/v3; anchors и multi-scale изучать как отдельные идеи.
- YOLOv8: anchor-free детекция, decoupled head
- YOLOv10/26: NMS-free подход — механика dual label assignment
- Альтернатива для контраста: RT-DETR (transformer-based detection, без anchor
  и без NMS изначально по другой причине, чем YOLO)

## 3. Semantic Segmentation

**Задача в отрыве от моделей:**
- Постановка: pixel-wise классификация, каждый пиксель → класс, без разделения
  на экземпляры
- Метрики: pixel accuracy, **IoU/Jaccard по классам**, mean IoU (mIoU) — главная
  метрика в сегментации
- Формат разметки: маски (обычно PNG с индексами классов на пиксель), отличие
  от bbox-разметки detection

**Архитектуры:**
- FCN (Fully Convolutional Network) — базовая идея: замена FC-слоёв на conv,
  чтобы сохранить пространственную структуру
- U-Net — encoder-decoder со skip-connections, почему это стало стандартом
  (особенно в медицине)
- DeepLab — atrous/dilated convolution, зачем нужно расширенное рецептивное поле
  без потери разрешения
- YOLO26 semantic segmentation head — как урезанная/интегрированная версия
  этих идей внутри единого фреймворка

---

## 4. Instance Segmentation


**Задача в отрыве от моделей:**
- Постановка: bbox/маска + класс **для каждого экземпляра** отдельно, даже
  внутри одного класса
- Метрики: тот же mAP, что и в detection, но посчитанный по IoU масок, а не bbox
- Концептуальная сложность: как разделить два перекрывающихся объекта одного класса

**Архитектуры:**
- Mask R-CNN — как естественное расширение Faster R-CNN (детекция + segmentation
  head поверх ROI)
- YOLACT — one-stage подход к instance segmentation (прототипные маски +
  коэффициенты, идея ближе к YOLO-философии скорости)
- YOLOv8/YOLO11 instance segmentation head — как это встроено в unified-архитектуру

---

## 5. Pose Estimation / Keypoint Detection

**Задача в отрыве от моделей:**
- Постановка: N заданных keypoint'ов на объекте (скелет), не произвольная форма
- Метрики: **OKS** (Object Keypoint Similarity) — аналог IoU, но для точек с
  учётом их видимости/масштаба; PCK (Percentage of Correct Keypoints)
- Top-down vs bottom-up подход: сначала найти человека, потом keypoints внутри
  bbox (top-down) — или сначала найти все keypoints на картинке, потом
  сгруппировать их по людям (bottom-up). Это ключевая архитектурная развилка,
  важно понять её до конкретных моделей.

**Архитектуры:**
- OpenPose — классический bottom-up подход (part affinity fields)
- HRNet — почему сохранение высокого разрешения через всю сеть критично для
  точной локализации точек
- YOLO pose head — совместное one-stage предсказание boxes и keypoints; отличать от двухэтапного top-down «детектор → crop → отдельная pose-модель».

## 6. Oriented Bounding Box (OBB) Detection

**Задача в отрыве от моделей:**
- Постановка: bbox + угол поворота (обычно 5 параметров: x, y, w, h, θ вместо 4)
- Почему обычный axis-aligned bbox неприменим: примеры с аэроснимками
  (корабли/самолёты под углом) — bbox захватывает избыточный фон, IoU с истинным
  объектом занижен
- Метрики: modified IoU с учётом поворота (rotated IoU) — сложнее вычисляется,
  чем обычный IoU

**Архитектуры:**
- Ранние подходы к rotated detection в аэрокосмических данных (до YOLO-эры)
- YOLOv8/11 OBB head — как angle предсказывается дополнительным параметром
- Проблема periodicity угла (0° и 180° могут визуально совпадать для
  симметричных объектов) и как её обходят в loss-функции

## 7. Multi-Object Tracking (MOT)

**Задача в отрыве от моделей:**
- Постановка: не разовая детекция, а сохранение identity объекта через
  последовательность кадров
- Проблемы: occlusion (временное перекрытие), id-switch (потеря идентичности),
  re-identification после долгого исчезновения из кадра
- Метрики: **MOTA** (Multi-Object Tracking Accuracy), **IDF1** — понять, почему
  простого accuracy на кадр недостаточно для видео-задачи

**Архитектуры / алгоритмы:**
- Разделение на два слоя: detector (YOLO) + association-алгоритм — это не одна
  модель, а pipeline
- SORT / DeepSORT — Kalman filter + IoU-matching, базовый classic подход
- ByteTrack / BoT-SORT — что используется в связке с YOLOv8/11/26 сейчас, чем
  отличается от DeepSORT

---

## 8. Depth Estimation

**Задача в отрыве от моделей:**
- Постановка: monocular depth estimation — предсказать расстояние до камеры по
  одному 2D-изображению (принципиально ill-posed задача без стерео/LiDAR)
- Метрики: RMSE, Abs Relative Error на глубине — регрессионные метрики, не
  detection-метрики
- Почему это вообще возможно из одной картинки: модель учится на монокулярных
  cues (перспектива, относительный размер, текстура) — важно понять эту
  предпосылку до архитектур

**Архитектуры:**
- MiDaS / DPT — специализированные модели для monocular depth, transformer-based
- YOLO26 depth estimation head — как интегрировано в единый фреймворк, на каких
  данных предобучено (NYU Depth V2 и т.д.)

---

## 9. Open-Vocabulary Detection

*(Последнее в списке — требует понимания object detection (п.2) и базового
знакомства с text-image моделями типа CLIP.)*

**Задача в отрыве от моделей:**
- Постановка: детекция по произвольному текстовому запросу класса, не
  зафиксированному в train
- Зачем: не нужно переобучать модель под каждый новый набор классов
- Принципиальная идея: совмещение visual embedding space и text embedding space
  (тот же принцип, что в CLIP — притягивание похожих по смыслу изображения и текста)

**Архитектуры:**
- CLIP как база — короткое напоминание механики contrastive image-text обучения
  (перекликается с вашим SSL-проектом, только модальности разные)
- YOLO-World — как совмещает YOLO-детектор с текстовым энкодером
- YOLO26 open-vocabulary версия

## Практика, потери и критерии освоения

Предпосылки: [данные](../01-data/%D0%9F%D0%BB%D0%B0%D0%BD%20%E2%80%94%20%D0%B4%D0%B0%D0%BD%D0%BD%D1%8B%D0%B5%20%D0%B8%20%D0%BA%D0%B0%D1%87%D0%B5%D1%81%D1%82%D0%B2%D0%BE%20ML-%D1%8D%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D0%B0.md), CNN training loop, receptive field и residual connections. Общие augmentation/MixUp/CutMix/dropout — в [регуляризации](../02-regularization/%D0%9F%D0%BB%D0%B0%D0%BD%20%E2%80%94%20%D1%80%D0%B5%D0%B3%D1%83%D0%BB%D1%8F%D1%80%D0%B8%D0%B7%D0%B0%D1%86%D0%B8%D1%8F.md). Здесь проверяется их влияние на конкретную задачу.

**Классификация — ядро:** frozen backbone + linear probe/kNN vs partial fine-tuning. Cross-entropy и calibration; imbalance-метрики по классам. Разобрать ошибки по источнику и сложности. Для SSL дополнительно positive/negative pairs, InfoNCE, collapse и отличие linear probe от полного fine-tuning.

**Detection — ядро:** вручную посчитать IoU и matching нескольких предсказаний с GT; сортировка confidence, дубликаты, PR → AP. Отличать AP@0.5 от AP@[0.5:0.95], AP small/medium/large. Разобрать classification/objectness, box loss (IoU/GIoU/DIoU/CIoU), assignment и FPN. Для DETR — set prediction/Hungarian matching, почему NMS не обязателен. Эксперимент: resolution/threshold/NMS, качество малых объектов и полная latency с preprocessing.

**Semantic segmentation — ядро:** CE vs Dice, ignore-index, class imbalance; confusion matrix на пикселях и mIoU. Boundary quality и влияние resize. На игрушечных масках показать высокую pixel accuracy при провале малого foreground. Проверить визуально выход и соответствие class-ID.

**Instance segmentation — ядро:** box AP vs mask AP, RoIAlign и prototype masks. Проверить соприкасающиеся объекты, пропущенные экземпляры и ошибки границ. Panoptic segmentation/PQ — углубление для объединения things/stuff.

**Pose — по задаче:** heatmaps vs coordinate regression, visibility, масштаб и OKS/PCK. Ошибки при occlusion и обрезании тела; вручную проверить преобразование keypoints после аугментации.

**OBB — по задаче:** угол, эквивалентность (w,h,theta), cyclic loss и rotated IoU. Проверить квадратные/почти квадратные объекты и переход через границу диапазона угла.

**Tracking — по задаче:** detector → Kalman prediction → association; отдельно движение и appearance. Добавить HOTA к MOTA/IDF1, исследовать ID switches и recovery после occlusion. Split по видео; хорошая frame-wise detection не доказывает хорошую идентичность треков.

**Depth — по задаче:** relative vs metric depth, scale ambiguity, validity mask, camera intrinsics и протокол scale alignment. Считать AbsRel/RMSE только по допустимым пикселям; не сравнивать метрики при разных align-протоколах.

**Open-vocabulary — углубление:** image-text contrastive learning, zero-shot vs адаптация на новых классах. Измерять seen/unseen отдельно, проверить перефразировки и языки запроса. Наличие текстового encoder не гарантирует произвольные новые классы.

**Готово:** для выбранной задачи есть baseline, формула потерь, ручной пример метрики, визуальная проверка выходов и три категории ошибок. Для deployment дополнительно измерена end-to-end latency, а не только forward на GPU.

Названия heads и версии — примеры реализаций; перед практикой сверять поддержку задачи и веса в [официальной документации Ultralytics](https://docs.ultralytics.com/tasks). Не требуется изучать каждую версию YOLO.
