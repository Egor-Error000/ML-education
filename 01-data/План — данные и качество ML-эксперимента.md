# План: данные и достоверность ML-эксперимента

[Единый маршрут](../README.md). Этот план отвечает за split, leakage, качество разметки и preprocessing. Кодирование — в [категориях](../03-categorical-features/%D0%9F%D0%BB%D0%B0%D0%BD%20%E2%80%94%20%D0%BA%D0%B0%D1%82%D0%B5%D0%B3%D0%BE%D1%80%D0%B8%D0%B0%D0%BB%D1%8C%D0%BD%D1%8B%D0%B5%20%D0%BF%D1%80%D0%B8%D0%B7%D0%BD%D0%B0%D0%BA%D0%B8.md), регуляризующие методы — в [регуляризации](../02-regularization/%D0%9F%D0%BB%D0%B0%D0%BD%20%E2%80%94%20%D1%80%D0%B5%D0%B3%D1%83%D0%BB%D1%8F%D1%80%D0%B8%D0%B7%D0%B0%D1%86%D0%B8%D1%8F.md).

## 1. Постановка задачи и паспорт данных — ядро

**Проблема:** строка не обязательно независимое наблюдение. Один пользователь, прибор, видео или документ может породить множество строк.

**Разобрать:** единицу предсказания, момент доступности признаков, задержку метки, способ отбора данных; различать классификацию, регрессию, ranking и retrieval. Определить метрику и цену ошибок до обучения.

**Практика:** паспорт датасета: источник, схема, размеры, группы/время, классы, пропуски, единицы измерения и ограничения использования. Указать признаки, реально доступные при инференсе.

**Готово, если:** ясно, на какие будущие объекты должна обобщаться модель и почему метрика соответствует задаче.

## 2. Split и утечки — ядро

Random/stratified split — для подходящих независимых данных; GroupKFold — для новых пользователей/объектов; временной holdout/walk-forward — для будущего; gap/embargo — при перекрывающихся окнах. Стратификация не устраняет групповые/временные утечки.

Сначала split, затем fit преобразований только на train: scaler, imputer, словарь, feature selection, PCA. Resampling — внутри train-фолда. Для target encoding нужен cross-fitting внутри обучающей части; механика — в плане категорий.

**Практика:** сравнить random и group/time split; специально добавить недоступный на момент предсказания признак и обнаружить завышение оценки. Проверить пересечение ID и дубликатов.

**Готово, если:** весь pipeline помещается внутри CV, а test не используется для подбора параметров.

## 3. Пропуски, выбросы и разметка — ядро

MCAR/MAR/MNAR как предположения; sentinel-значения, невозможные диапазоны, испорченные единицы и схемы. Импутация не восстанавливает автоматически истинное распределение.

Для меток: инструкция разметчикам, неоднозначность, disagreement и повторная разметка. Confident learning/cleanlab выделяют подозрительные примеры, но не доказывают ошибочность метки.

**Практика:** аудит случайной выборки и срезов; сравнение импутации, missing indicator и удаления признака. Проверить подозрительные метки вручную и измерить качество до/после.

**Готово, если:** очистка воспроизводима и не стирает редкие важные подгруппы.

## 4. Дисбаланс, пороги и калибровка — ядро

Prevalence; precision/recall, PR-AUC, ROC-AUC, macro/micro-F1, balanced accuracy. Высокий ROC-AUC не гарантирует полезную precision редкого класса.

Class/sample weights; oversampling/undersampling; ограничения SMOTE на категориях, границах и групповых данных. Focal loss — прикладное продолжение в CV. Порог и калибровка выбираются на validation/OOF: reliability diagram, Brier score/log loss. Балансировка может менять интерпретацию вероятностей.

**Практика:** без балансировки vs weighted loss vs resampling на одном split; выбрать порог под целевой recall или цену FP/FN. Проверить результат при изменении prevalence.

**Готово, если:** есть качество по классам, выбранный порог и диагностика вероятностей, а не одна accuracy.

## 5. Аугментации, синтетика и дедупликация — ядро + углубление

Преобразование сохраняет метку только при корректной инвариантности задачи. Механика MixUp/CutMix/label smoothing принадлежит плану регуляризации.

Синтетика: источник teacher, происхождение примера, разнообразие и фильтрация; независимый реальный holdout. Различать синтетический датасет, dataset distillation и дистилляцию модели.

Точные хеши; near-duplicates через MinHash/LSH для текстов и perceptual hashes/эмбеддинги для изображений. Порог имеет FP/FN. Группы дубликатов учитывать при split; обучаемые очистители не подгонять по test.

**Практика:** вручную проверить 20–50 изменённых примеров; сравнить реальные данные и смесь с синтетикой; убрать межсплитовые дубликаты и пересчитать оценку.

**Готово, если:** известны преобразования, меняющие метку; синтетический прирост подтверждён на независимых реальных данных.

## 6. Загрузка и воспроизводимость — ядро

Dataset/DataLoader, collate, padding/bucketing; num_workers/prefetch/pin_memory для конкретной платформы. Разделить время чтения, декодирования, преобразований, копирования и GPU-вычислений.

**Практика:** измерить samples/s и ожидание для нескольких конфигураций; проверить порядок/полноту примеров и seeds workers. На Windows учитывать запуск worker-процессов. Число workers выбирать по измерению.

Сохранять manifest, версию/хеш данных, split-ID, преобразования и версии библиотек. DVC — необязательная реализация версионирования.

**Готово, если:** можно восстановить данные/split, а bottleneck подтверждён профилированием.

## 7. CV-данные — прикладная ветка

- COCO/VOC/YOLO: xyxy/xywh, абсолютные/нормированные координаты, class-ID, фон/ignore-index. Для OBB — единицы и диапазон угла.
- Синхронные преобразования изображения, bbox, маски и keypoints. Nearest interpolation для дискретной маски; после crop обновлять исчезнувшие объекты.
- Малые объекты, пустые кадры, crowd и occlusion; полнота аннотаций. Видео разделять по последовательностям.
- WebDataset/шарды: shuffle, split по источникам и восстановление после прерывания. Изучать при необходимости streaming.

**Практика:** конвертация малого набора туда/обратно; визуализация аннотаций до/после. Проверить площади, координаты, ID и пустые примеры. Метрики/архитектуры — в [CV](../05-computer-vision/%D0%9F%D0%BB%D0%B0%D0%BD%20%E2%80%94%20%D0%BA%D0%BE%D0%BC%D0%BF%D1%8C%D1%8E%D1%82%D0%B5%D1%80%D0%BD%D0%BE%D0%B5%20%D0%B7%D1%80%D0%B5%D0%BD%D0%B8%D0%B5.md).

## 8. Текстовые и LLM-данные — прикладная ветка

- BPE/WordPiece; SentencePiece — инструмент с несколькими алгоритмами. Unicode, byte fallback/UNK, языки, длины и special tokens.
- Роли диалога, chat template, EOS и truncation; loss mask — в [SFT](../06-llm/02-adaptation/%D0%9F%D0%BB%D0%B0%D0%BD%20%E2%80%94%20%D0%B0%D0%B4%D0%B0%D0%BF%D1%82%D0%B0%D1%86%D0%B8%D1%8F%20LLM.md).
- Chunking: размер в токенах, границы разделов, overlap, metadata происхождения. Делить документы/источники до нарезки, не разносить соседние chunks между train/test.
- Instruction/preference data: происхождение, task mix, дубликаты и contamination. Эффект качества и количества проверять learning curve.

**Практика:** несколько chunk-размеров на фиксированных вопросах и релевантных фрагментах; метрики retrieval/ответа — в [RAG](../06-llm/03-inference/%D0%9F%D0%BB%D0%B0%D0%BD%20%E2%80%94%20%D0%B8%D0%BD%D1%84%D0%B5%D1%80%D0%B5%D0%BD%D1%81%20LLM.md). Перед SFT вручную проверить токены и labels одного batch.

## 9. Drift и статистическая надёжность — углубление

Covariate shift, label shift, concept drift; качество по времени, источнику и группе. Доверительные интервалы/вариативность по seeds. При связанных наблюдениях bootstrap учитывать по группам/блокам, а не считать строки независимыми.

**Итог:** паспорт данных, сохранённый split, pipeline, аудит утечек, baseline, сравнение одной интервенции и обоснование вывода. Этот артефакт используется во всех дальнейших планах.
