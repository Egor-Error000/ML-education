# И. Когда вчерашняя оценка перестаёт описывать будущее

[Оглавление](README.md). Пункт 9 плана. **Происхождение:** дополнение к плану, связанное с evaluation и monitoring из LLM-чатов. Здесь статистический смысл отделён от устройства serving.

## 1. Три вида изменения распределения

Совместное распределение раскладывается двумя способами:

$$
P(X,Y)=P(Y\mid X)P(X)=P(X\mid Y)P(Y).
$$

Covariate shift предполагает изменение $P(X)$ при сохранении $P(Y\mid X)$. Например, изменились доли типов входных объектов, но правило связи с target осталось прежним. Label shift предполагает изменение $P(Y)$ при сохранении $P(X\mid Y)$. Concept drift означает изменение условной связи $P(Y\mid X)$, например новое бизнес-правило меняет target при прежних features.

В реальности изменения могут сочетаться. Histogram drift входного признака не доказывает падение качества. Обратно, условная связь может измениться без заметной смены marginal feature distributions. Поэтому нужны и input monitoring, и delayed outcome quality, и срезы процесса сбора labels.

При covariate shift importance weighting теоретически использует:

$$
w(x)=\frac{p_{\mathrm{new}}(x)}{p_{\mathrm{old}}(x)},
\qquad
R_{\mathrm{new}}(f)=
\mathbb E_{\mathrm{old}}[w(X)\ell(f(X),Y)].
$$

Нужны сохранение conditional distribution и support: если новые объекты встречаются там, где старой плотности нет, веса не создадут отсутствующие знания. Очень большие weights увеличивают дисперсию; clipping стабилизирует, но вносит bias. Это не универсальная починка произвольного drift.

## 2. Выборка даёт неопределённую оценку

Метрика на finite dataset — случайная величина. Разные samples, seeds и training conditions дают разброс. Для независимых бинарных outcomes стандартная ошибка доли примерно:

$$
\operatorname{SE}(\widehat p)=
\sqrt{\frac{\widehat p(1-\widehat p)}n}.
$$

При $\widehat p=0.8,n=100$ получаем $0.04$. Грубый normal interval $0.8\pm1.96\cdot0.04$ имеет ширину около $\pm0.0784$. Для малых samples и крайних долей такой interval может быть плох; используют, например, Wilson или exact методы. Частотный 95% confidence interval относится к покрытию процедуры при повторных выборках, а не к вероятности уже фиксированного параметра внутри конкретного интервала.

Среднее по seeds показывает вариативность training/decoding при заданных данных. Оно не заменяет неопределённость от выбора самой популяции задач. Сто запусков на одном документе не равны ста независимым документам. Обе причины разброса могут требовать раздельного анализа.

## 3. Bootstrap должен сохранять зависимости

Обычный bootstrap resamples observations с возвращением и пересчитывает statistic. Для независимых строк это разумная базовая идея. Но если 100 кадров относятся одному видео, row bootstrap делает вид, что все кадры независимы, и может дать слишком узкий interval.

Cluster bootstrap выбирает группы с возвращением и сохраняет их внутренние observations. Block bootstrap для временных данных resamples блоки, чтобы частично сохранить локальную зависимость. Размер/вид блоков влияет на результат; нельзя просто назвать любой resampling «статистически корректным» без проверки assumptions.

При парном сравнении моделей resample одни и те же task IDs для обеих и анализируйте разность метрик. Иначе теряется зависимость результатов на лёгких/сложных задачах. Например, модели могут иметь почти одинаковые общие accuracy, но выигрывать на разных подгруппах; paired error analysis объяснит trade-offs лучше одной разности средних.

## 4. Много экспериментов и честный итог

Если перебрать сотни настроек и выбрать случайный максимум, validation improvement может не переноситься. Нужны закрытый test, ограниченный/задокументированный процесс подбора и, где уместно, nested CV. Не следует сообщать только лучший seed, скрывая остальные. Размер practically meaningful improvement задаётся ценой ошибки/compute, а не только statistical significance.

Slice analysis также создаёт риск случайных находок: среди множества малых групп какая-то почти неизбежно покажет extreme. Важные срезы задаются заранее, для неожиданных находок требуется независимое подтверждение. При этом редкий, но критичный дефект нельзя игнорировать лишь из-за малого размера; нужно честно описать, что известно и что требует дополнительной разметки.

Monitoring должен различать изменение input, деградацию output, задержку labels и изменение измерительного процесса. Если новая политика размечает только уверенные cases, observed accuracy может расти из-за отбора. Для надёжной оценки нужен понятный sampling labels и контроль пропущенных outcomes.

## 5. Итог и практика

Полный data artifact включает паспорт, versioned manifest, сохранённые split IDs, train-only pipeline, leakage/label audit, baseline и сравнение одной интервенции. В выводе указываются population, metric, uncertainty, slices и ограничения переноса. Он используется во всех следующих курсах.

1. Доказывает ли feature drift ухудшение качества? **Ответ:** нет; связь с target может сохраняться, а изменение быть безвредным.
2. Что делать с видео при bootstrap? **Ответ:** учитывать sequence/group dependence, а не считать соседние кадры независимыми.
3. Достаточен ли лучший из десяти seeds? **Ответ:** нет; он является отобранным максимумом и скрывает вариативность.

**Практика:** задайте два будущих сценария: новый источник с прежним правилом и новое правило target. Выберите monitoring и independent labels для каждого. На пяти группах примеров сравните row и group resampling концептуально: какие зависимости сохраняются? Завершите паспорт данных и напишите вывод без преувеличения объёма независимой информации.
