**Главное ограничение:** в сообщении «Пункт D4», строки 179–181, пользователь прямо говорит, что идёт изучение материала, а не создание агента. ## 2. Как переносить статусы

Для каждой темы хранить отдельные поля:

```text
topic_id: устойчивый идентификатор темы
coverage: не найдено | упомянуто | обзор | подробный разбор
understanding: не проверено | частично проверено | проверено
practice: не подтверждена | есть пользовательский артефакт | воспроизведена
source: файл + строки или страницы
correction_ids: необходимые поправки
next_step: один проверяемый вопрос или действие
```

Запрос «переходим дальше» подтверждает продолжение обсуждения, но не успешное решение задания. Чужая/вставленная сводка, сгенерированный пример и сообщение «мы закрыли всё» не заменяют доказательства. При отсутствии темы писать «не найдено в предоставленных документах», а не «никогда не изучал».

Не вычислять общий процент освоения: длинное обсуждение не равно большему навыку, а обновлённые планы содержат новые критерии и темы.

## 5. Этапы выполнения и проверки

### Этап 0. Инвентаризация — выполнен

Источники определены, вычислены хеши, построены message outlines, извлечён PDF, составлены карты тем/статусов и поправки. Обновлены восемь планов, исходные версии сохранены. Точки продолжения и формат урока уточнены по истории.

### Этап 1. Фиксация исходников — при выполнении миграции

Скопировать шесть файлов в `archive/study-sources`, проверить SHA-256 по manifest. Сохранить историю как read-only справочник; повторения в ней допустимы. Не делать rename/move оригиналов из Downloads. Критерий: шесть совпавших хешей и рабочие ссылки происхождения.

### Этап 2. Пилот: foundations + LoRA

Собрать из S1/S2 один согласованный разбор: модель → shapes → linear projection → A/B → один шаг → merge. Использовать разные обозначения для attention scores и LoRA A/B. Сохранить вопросы пользователя и ответы на них рядом с материалом. Применить C01–C05.

Критерий: все произведения согласованы по shapes; числовой шаг сходится; собственная ошибка исходника не становится вопросом пользователя, который якобы не понял правильный материал.

### Этап 3. Объединение adaptation

Основой взять поздний S3, углубления LoRA/DoRA/AdaLoRA/QLoRA — из S1/S2, distillation — из S4. Quantization и tool runtime оставить ссылками. Применить C06–C09. Проверить, что RLAIF, continual learning и agentic training не отмечены освоенными по одному упоминанию.

Критерий: каждая тема имеет одно основное объяснение, источник, уровень обсуждения и короткий контрольный вопрос.

### Этап 4. Объединение inference/applications

Последовательно собрать S4 → S5 → S6. Runtime-примеры пометить как version-sensitive/непроверенные. Отделить механизмы от конкретных runtime/framework APIs; research cases — в отдельную заметку. Применить C10–C14.

Критерий: E.2 является последней подробно обсуждённой основной темой этой ветки; E.3/E.4 ожидают отдельного разбора. RAG/AutoGen не превращаются в метку «обучал агентов».

### Этап 5. Перенос и короткая проверка понимания

Применить реестр как baseline; по спорным темам дать по одному небольшому заданию. Обновлять understanding по ответу пользователя, practice — только по его артефакту/запуску. Не требовать большой проект для продолжения теории.

Критерий: ни один статус не повышен из-за объёма текста или вставленной ассистентом демонстрации. Сначала поправки, затем новое обучение.

### Этап 6. Контроль качества и переход

Проверить локальные ссылки, соответствие IDs/aliases, отсутствие двух основных объяснений одной темы и unsupported benchmark numbers. Проверить formulas вручную/численно, code examples — только если их сохраняют как исполняемые. Сформировать короткую итоговую сводку и обновить CONTINUATION.

Критерий: любую запись прогресса можно проследить до оригинального сообщения/страницы; старые сводки явно исторические; нет слепого сброса пройденного и ложного «100% освоено».

## 7. Ближайший учебный маршрут

1. Короткие поправки: LoRA shapes/gradient, greedy-temperature, structured output и evaluation.
2. Продолжение inference: **E.3 — cache ответов приложения, semantic caching и invalidation**, затем **E.4 — мониторинг качества, drift и regression evaluation**. Prompt caching уже обсуждён; не начинать его заново.
3. Если выбирать adaptation: после поправок — **RLAIF/Constitutional AI с источником**, затем multi-objective alignment. LoRA+ — отдельное необязательное углубление после имеющегося обзора.
4. Agentic training — только как новая ветка: постановка среды/траектории → SFT на действиях → оценка. Не продолжать с GRPO, будто предыдущие агентные пункты уже пройдены.

На этом шаге календарные сроки не назначены: скорость зависит от выбранной ветки и того, нужен ли практический запуск.
