# Обычная генерация по одному токену

**Уровень:** общее ядро.

**Предпосылки:** [Обучение: targets, loss и обновление весов](<lm-training.md>)

**Используют:** [Задача адаптации, baseline и выбор вмешательства](<../03-adaptation/adapt-choice.md>), [От prompt к обычному циклу генерации](<../04-inference/infer-generation.md>), [Structured output: schema и смысл результата](<../05-applications/app-structured.md>)

**Учебный вопрос:** Как распределение превращается в продолжение и почему обучение отличается от применения?




## Обычный autoregressive цикл

При генерации веса фиксированы. Токенизируем prompt, получаем logits последней настоящей позиции, применяем policy выбора, добавляем один ID к prefix и повторяем. Остановка определяется EOS, максимальным числом новых токенов или правилом приложения. Без cache модель может заново обрабатывать весь prefix на каждом шаге — это корректный, хотя и дорогой baseline.

Пример: на первом шаге distribution по `[спит, ест, EOS]` равна `[0.6,0.3,0.1]`, greedy выбирает «спит». На новом prefix probability EOS может стать 0.7; следующий шаг завершит ответ. Вероятность выбранной двухшаговой траектории в этом учебном примере — $0.6\cdot0.7=0.42$. Нельзя использовать распределение первого шага для всех следующих: вход уже изменился.

Sampling выбирает по распределению, greedy — по argmax. Temperature, top-p и beam меняют процедуру и будут подробно разобраны в инференсе. Сохранённый KV-cache меняет организацию повторных вычислений; он не должен самовольно менять доступную информацию или выбранное распределение.

**Практика:** вручную выполните два шага по заданным таблицам probabilities, запишите обновлённый prefix и причину остановки. Ошибка — передать decoder сразу ещё не сгенерированные правильные токены и назвать результат свободной генерацией.

## Генерация, интерпретация и ограничения

<!-- /unit:68a56d2d6cac202fa7 -->

<!-- unit:9a1bd4deb344e5a8f0 -->
<a id="u-9a1bd4deb344e5a8f0"></a>

После обучения модель получает prefix, выдаёт распределение следующего токена, выбранный токен добавляется к prefix, процесс повторяется. Выбор токена — отдельный алгоритм: greedy, sampling и другие стратегии. Во время обычного такого использования градиентный спуск не выполняется: новый диалог меняет вход, а не автоматически веса.

<!-- /unit:9a1bd4deb344e5a8f0 -->

<!-- unit:618c2e628bdc339c88 -->
<a id="u-618c2e628bdc339c88"></a>

Низкая CE показывает способность предсказывать токены выбранного корпуса. Она не гарантирует правильность ответа на задачу, достоверность фактов или успешность действий с инструментами. Модель может уверенно воспроизводить неверный шаблон. Поэтому языковая ошибка и оценка приложения нужны для разных выводов.

<!-- /unit:618c2e628bdc339c88 -->

<!-- unit:0a403fca1c6950eff5 -->
<a id="u-0a403fca1c6950eff5"></a>

**Частые ошибки:** считать слово токеном во всех случаях; интерпретировать ID как вещественный признак; путать padding mask с causal; включать padding в loss; сдвигать labels дважды; сравнивать perplexity моделей с разными tokenizers как будто единица усреднения одинакова.

## Почему обычно берут последнюю позицию для продолжения

<!-- /unit:d118abf9f445a5d541 -->

<!-- unit:1344d3601524c6e0c5 -->
<a id="u-1344d3601524c6e0c5"></a>

Causal state на позиции t мог получить информацию только о разрешённых позициях не позже t. Поэтому logits этой позиции предсказывают токен t+1. Для prompt длины L его продолжение выбирается по logits последнего настоящего токена, а не последнего padding-элемента в прямоугольном batch.

<!-- /unit:1344d3601524c6e0c5 -->

<!-- unit:9ed8212176c49f1665 -->
<a id="u-9ed8212176c49f1665"></a>

На training можно получить logits сразу для всех L позиций и сравнить со сдвинутыми targets: ответы известны, mask предотвращает подсматривание. На generation следующий вход зависит от выбранного токена, поэтому цикл продолжается по шагам. KV-cache помогает переиспользовать K/V прошлого, но не превращает hidden state последней позиции в универсальную замену всему cache.

<!-- /unit:9ed8212176c49f1665 -->

<!-- unit:36a5262b8357c4cb4c -->
<a id="u-36a5262b8357c4cb4c"></a>

Если взять только последний hidden state и выбросить историю, в общем случае нельзя продолжить модель точно так же, как с полным KV-cache. В следующих слоях новый query обращается к K/V разных прошлых позиций. Один вектор D не хранит автоматически всю нужную структуру каждого слоя.

<!-- /unit:36a5262b8357c4cb4c -->

<!-- unit:3bd0573c8cdedd3725 -->
<a id="u-3bd0573c8cdedd3725"></a>

Именно поэтому образ «финальный hidden state — сжатый смысл всей истории без потерь» неверен. Он полезен как task-dependent representation разрешённого контекста, но не обладает общей гарантией обратимого хранения текста.
