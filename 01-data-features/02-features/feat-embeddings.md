## Карта вычисления и границы этапов

![Пакет A, A, B выбирает строки таблицы; вклады градиентов одного ID складываются](<../../оформление/course/feat-embeddings.svg>)

Схема показывает таблицу как обучаемый параметр: пакет A,A,B выбирает три строки, а после вычисления потерь оба вклада A складываются в один градиент. Числа ниже выведены для среднего значения половины квадрата ошибки. Близость строк зависит от задачи и не гарантирует универсального смысла категорий.

## Lookup и обучаемая функция

Для $K$ категорий обучаемая таблица векторных представлений (embedding) $E\in\mathbb R^{K\times d}$ возвращает строку $e_c$ категории $c$. Математически выбор строки равен $E^\top u_c$, где $u_c$ — столбец one-hot, но реализация может сразу прочитать нужную строку. Обучаются $Kd$ параметров: при $K=10\,000,d=16$ это 160 000 чисел, или 0.64 MB для весов float32 без состояния оптимизатора.

Разные поля обычно имеют собственные словари и таблицы: город с ID 7 и телефон с ID 7 не являются одним объектом. Выбранные векторы объединяют или передают в другие блоки модели. Размерность $d$ — выбираемый параметр: её увеличение повышает выразительность, но не добавляет наблюдений редкой категории.

### Выбор строк таблицы на числовом примере

Рассмотрим таблицу на 1000 ID с размерностью 4. ID 42 и 105 выбирают строки (0.1,−0.5,0.8,0.2) и (0.3,0.1,−0.2,0.9); на выходе получается матрица 2×4. Выбор строк сам по себе не смешивает информацию между категориями. Два табличных поля не становятся последовательностью только потому, что им назначены ID.

В текстовой модели исходный вектор токена также извлекают из таблицы. После последующего блока обработки состояние позиции может зависеть от остальных токенов и маски: это уже контекстное состояние, а не исходная статическая строка таблицы. Чтобы изучить табличные представления в этой главе, знать устройство такого блока не требуется; оно разбирается отдельно в основах языковых моделей.

Для пакета из $B$ строк одного поля ID имеют форму $B$, результат выбора строк — $B\times d$, а таблица — $K\times d$. Для $F$ полей с размерностями $d_1,\ldots,d_F$ объединение векторов имеет форму $B\times\sum_f d_f$. Дополнение до общей длины (padding), маска и объединение элементов нужны для наборов или последовательностей; одному категориальному значению искусственный PAD не нужен.

### Почему d=1 иногда уже достаточно

Для одного поля и линейного скалярного выхода предсказание равно $v^\top e_c+b$. При $d=1$ и ненулевом $v$ можно выразить произвольный коэффициент каждой категории, выбрав $e_c=(a_c-b)/v$. Поэтому замена $K$ one-hot коэффициентов на $K$ одномерных представлений сама по себе не ограничивает класс скалярных функций. Значение имеют регуляризация, разделение параметров и последующие блоки.

Для $M$ выходов и общей линейной головы $H$ размера $d\times M$ матрица эффектов категорий $W=EH$ имеет ранг не выше $d$. Теперь малая размерность связывает разные выходы. Матрица для трёх категорий и двух выходов со строками (1,0), (0,1), (1,1) имеет ранг 2: при $d=1$ её точно не воспроизвести, а $d=2$ достаточно. При отдельном смещении каждого выхода ограничение относится к эффектам после вычитания смещения.

Если дальше стоит нелинейная сеть, ограничение ранга линейной матрицы W уже не описывает всю функцию. Объединение векторов с одной линейной головой остаётся аддитивным по полям. Например, XOR двух бинарных полей нельзя выразить порогом суммы двух независимых эффектов: нужны взаимодействие, нелинейность или другой способ. Сам выбор строк таблицы взаимодействие не создаёт.

## Градиент и шаг оптимизации

Пусть скалярный прогноз $\widehat y=v^\top e_c+b$, а функция потерь $L=\tfrac12(\widehat y-y)^2$. По правилу цепочки:

$$
\frac{\partial L}{\partial e_c}=(\widehat y-y)v,
\qquad
\frac{\partial L}{\partial v}=(\widehat y-y)e_c.
$$

В этом примере градиент от данных получает выбранная строка таблицы. В пакете вклады всех обращений к одной строке складываются. Однако регуляризация или состояние оптимизатора могут менять и другие параметры, поэтому утверждение «невыбранные строки никогда не меняются» слишком сильное.

Возьмём $e_A=(1,2)$, $v=(0.5,-1)$, $b=0$, $y=0$. Прогноз равен −1.5, градиент выбранного вектора — (−0.75,1.5). При шаге обучения 0.1 и обновлении только вектора получаем (1.075,1.85), новый прогноз −1.3125 и уменьшение потерь с 1.125 до 0.861328125. Одновременное обновление головы даст другой результат; его разберём ниже.

### Gradient — это сумма по обращениям к row

Пусть $e_c$ — столбец, а $g_i$ — пришедший градиент при обращении к таблице в позиции $i$. Тогда все обращения к одной категории накапливаются:

$$
\nabla_{e_c}L=\sum_{i:c_i=c}g_i.
$$

Такая операция называется scatter-add: несколько обращений к одному ID добавляются к градиенту одной строки. Если функция потерь уже усреднена по $B$ примерам, пришедшие градиенты уже содержат множитель $1/B$ и повторно делить их нельзя. При масках знаменатель определяется формулой потерь, а не просто числом позиций дополненного массива.

Для предыдущей модели возьмём пакет A,A,B: $e_A=(1,2)$, $e_B=(-1,0)$, $v=(0.5,-1)$, метки (0,1,−1). Прогнозы равны −1.5,−1.5,−0.5, а ошибки — −1.5,−2.5,0.5. Для среднего значения половины квадрата ошибки градиенты равны

$$
\nabla_{e_A}L=(-2/3,4/3),\qquad
\nabla_{e_B}L=(1/12,-1/6),
$$
$$
\nabla_vL=(-1.5,-8/3),\qquad
\nabla_bL=-7/6.
$$

Строка A получает сумму двух разных ошибок, а не градиент только последней встречи. Некоторые реализации дополнительно делят градиент на частоту ID: это отдельное правило обновления, а не градиент исходной средней функции потерь. Такую настройку нельзя включать незаметно и считать прежний ручной вывод неизменным.

### Совместный update embedding и head

Вернёмся к одному примеру $e=(1,2),v=(0.5,-1),b=0,y=0$. Все gradients вычисляются по одному исходному состоянию: $\nabla_e=(-0.75,1.5)$, $\nabla_v=(-1.5,-3)$, $\nabla_b=-1.5$. При LR 0.1 совместный SGD step даёт e'=(1.075,1.85), v'=(0.65,−0.7), b'=0.15. Prediction становится −0.44625, half-squared loss 0.09956953125.

Это другой результат, чем обновление только embedding из раздела 2. Если сначала поменять embedding, затем пересчитать gradient head, получится последовательная block update scheme. Она может быть осмысленным отдельным алгоритмом, но не тем же simultaneous SGD step. Для конечного LR decrease не гарантирован произвольной nonlinear model; хороший результат этого маленького примера не превращается в universal theorem.

### Нулевой data gradient не всегда означает неподвижную row

Когда ID не встречался в batch, его lookup contribution к gradient равен нулю. Однако weight decay (затухание весов при обновлении), momentum от прежних batches, optimizer states, shared/tied weights и операции norm constraint могут менять row и без нового lookup occurrence. В dense Adam старые moments способны дать update при текущем нулевом gradient; sparse optimizer может иметь другой контракт того, какие rows вообще посещаются.

PAD row, отсутствующая из loss, и UNK row выполняют разные функции. PAD нужна для формы tensor и mask; UNK должна давать полезный fallback для неизвестного ID. Запрет lookup gradient для padding row не является доказательством, что любая внешняя операция над weights её сохранит. Замораживание всей matrix, mask gradients отдельных rows и исключение parameters из optimizer тоже не эквивалентны. Проверяют фактические updates и сохранённые optimizer states выбранного training code.

## Геометрия пространства

Представления категорий обучаются под конкретную цель, а не создают универсальную смысловую карту. Если цель — кликабельность рекламы, близкие векторы городов могут отражать рекламное поведение, а не географическую близость. Для другой задачи такая геометрия может быть неуместна.

Представление не определяется единственным образом: для обратимой матрицы $A$ можно заменить векторы на $Ae_c$, а веса линейной головы на $A^{-\top}v$ и сохранить предсказания. При этом евклидовы расстояния могут измениться. Интерпретация геометрии требует учитывать архитектуру, ограничения и регуляризацию.

При embedding+linear output без нелинейных interactions expressive power одного field может быть такой же, как отдельных category coefficients. Польза compact vector проявляется через shared factors, interactions, multitask transfer и data structure, но не гарантируется самим словом «embedding».

Для column vector e и linear head v преобразование $e'=Ae$, $v'=A^{-\top}v$ сохраняет scalar prediction. Возьмём e1=(1,0), e2=(0,1), A=diag(10,1). Distance между embeddings меняется с $\sqrt{2}$ до $\sqrt{101}$, но после соответствующей замены head predictions сохраняются. Это точный контрпример интерпретации расстояния как автоматически установленного свойства entities.

Cosine тоже не сохраняется при произвольном invertible A. Для u=(1,1), v=(1,−1) исходный cosine 0, а после того же A — 99/101≈0.9802. Orthogonal rotation сохраняет distances/cosine, но не произвольный rescaling осей. Norm constraints, normalization (нормировка по выбранному правилу) и contrastive objectives ограничивают допустимую геометрию; они являются частью метода, а не бесплатным свойством lookup.

Геометрия может быть полезной: похожие задачи и регуляризация способствуют разделению информации, а ближайшие соседи иногда имеют понятную структуру. Но это проверяют на конкретной последующей задаче или поиске. Красивая двумерная проекция не доказывает полезность исходных расстояний: проекция может их искажать.

Для двух fields dot-product score $e_u^\top f_i$ задаёт low-rank interaction matrix. Он связывает predictions для ещё не наблюдавшихся pairs через общие factors, но не может персонализировать совсем новую row без signal. Это иной источник inductive bias, чем отдельный scalar main effect для каждого ID. Механика pair interactions продолжена в главе [«Взаимодействия признаков, FM и FFM»](<feat-interactions.md>).

## Редкие категории и cold start

Редкие категории получают мало обновлений по данным. Объединение редких значений, меньшую размерность, затухание весов, ограничения нормы и общие признаки объекта сравнивают на проверочной части. Строке UNK нужен обучающий сигнал, например при контролируемом скрытии известных категорий. Случайно инициализированная строка для нового ID не знает его индивидуального эффекта.

Словарь сохраняют вместе с весами. Если при загрузке переставить ID, поиск вернёт неправильные строки без ошибки формы. Пропуск, PAD и UNK могут требовать отдельных строк; правила обновления PAD зависят от реализации и требуют проверки.

### Обучаемая таблица — не сжатое хранение one-hot input

При K=10 000 и d=16 таблица содержит 160 000 параметров, или 640 000 байт весов float32. Плотный градиент и два состояния Adam той же точности добавят 1 920 000 байт; вместе получится 2 560 000 байт без активаций, накладных расходов и остальных слоёв. При смешанной точности основные копии весов и типы градиентов могут изменить расчёт.

One-hot вход с одной активной категорией на объект можно хранить разреженно; скалярная линейная модель имеет для него всего K коэффициентов. Таблица с d=16 содержит в 16 раз больше параметров, хотя выдаёт компактный вектор на каждый пример. При K=1 000 000,d=64 одни веса float32 занимают 256 MB в десятичных единицах; веса, градиент и два состояния Adam — 1.024 GB. Компактность на выходе не гарантирует меньшей памяти всей системы.

Активации пакета B×d зависят от числа обращений к таблице, а сама таблица — от Kd. Разреженный градиент может уменьшить работу с затронутыми строками, но не делает веса бесплатными. Разделение таблицы между устройствами или перенос части данных увеличивает стоимость обмена и задержку.

### Размерность не заменяет наблюдения редкого ID

Если категория встречается r раз, её строка получает непосредственный сигнал примерно при этих r обращениях за проход, с поправкой на выборку. Рост d с 8 до 128 добавляет свободные координаты, а не наблюдения. При частоте p вероятность не встретить ID в B независимых выборках равна $(1-p)^B$. Для p=0.0001 и B=256 она около 0.9747: большинство таких пакетов не дают этому ID прямого градиента.

Более частое включение редких категорий меняет частоту обновлений и при неправильных весах может изменить целевую популяцию. Затухание весов к нулю задаёт простое предположение, но нулевой вектор не обязательно описывает среднее поведение. Альтернатива — использовать доступные свойства объекта: $e_c=g(x_c)+r_c$, где g строит вектор по свойствам, а r_c — индивидуальная поправка. Для нового ID можно положить поправку равной нулю и использовать свойства, если они доступны к моменту прогноза.

### Unknown row нужно чему-то научить

При скрытии категорий (category dropout) во время обучения часть известных ID заменяют на UNK. Строка UNK учится на распределении скрытых примеров, а не получает автоматически смысл всех будущих объектов. Если выбор равномерен по строкам, в сигнале преобладают частые ID; если по категориям, задача меняется. Долю скрытия и схему сравнивают на проверке с отдельными срезами известных, редких и новых значений.

Для новой категории с доступными свойствами можно построить резервное представление по этим свойствам. Для произвольного ID без свойств индивидуальную информацию получить неоткуда. Создание случайной строки на каждом запросе не даёт осмысленной персонализации. При расширении словаря фиксируют версию, правило инициализации и при продолжении обучения расширяют состояние оптимизатора; перестановка старых строк нарушает соответствие.

## Extraction и transfer

Векторы можно заморозить и передать другой модели, в том числе бустингу. Но если их предварительно обучили на метках всего набора до перекрёстной проверки, полученные признаки уже содержат информацию внешней проверки. Кодировщик должен обучаться внутри разрешённой обучающей части либо быть независимо предобучен в рамках объявленного протокола.

Для переноса между задачами нужны стабильные ID, совместимые словари, доступные источники и проверка отрицательного переноса. Исходная задача могла закрепить смещение старого периода, а дообучение — забыть полезную структуру. Замороженную и обновляемую таблицы сравнивают на одном разбиении с отдельной оценкой редких и новых объектов.

### Почему обучение embeddings на train допустимо

Таблица векторов — обычный обучаемый параметр модели. Её обучение по разрешённым обучающим меткам не требует автоматически исключать каждую строку из собственного градиента: иначе пришлось бы запретить и обычное обучение с учителем. Обобщение проверяют на внешних данных, чьи метки не участвовали в обучении таблицы, головы или подборе параметров.

Если представление используют как признак для второй модели, кодировщик становится ещё одним этапом обучения по меткам. Можно обучить его на всей разрешённой внешней обучающей части и передать полученные представления второй модели, но она увидит признаки тех же объектов, на которых обучался кодировщик: это допускает запоминание и отличие от новых данных. Для вневыборочного поведения нужно перекрёстное вычисление с учётом согласования координат ниже. Использование внешних проверочных или тестовых меток при обучении кодировщика до оценки второй модели является утечкой.

### Почему нельзя просто склеить OOF embedding coordinates

Оси независимо обученных кодировщиков в разных folds могут поворачиваться, менять масштаб и переставляться. Например, категория A может получить (1,0) в одном fold и (0,1) в другом при согласованных головах и одинаковых прогнозах. Склеивание таких координат в одну OOF-матрицу создаёт несогласованное пространство для второй модели. Это отличается от OOF-вероятности фиксированного положительного класса, смысл которой одинаков на всех folds.

Возможные решения: общий заранее замороженный независимый кодировщик; выходы модели с фиксированным смыслом вместо скрытых координат; отдельная последующая модель для каждого кодировщика с объединением прогнозов; согласование по опорным объектам из разрешённых данных. Ни один вариант не следует автоматически из самого перекрёстного вычисления. Например, выравнивание Прокруста исправляет ортогональные повороты при подходящих опорных объектах, но не гарантирует согласования произвольных нелинейных представлений и не разрешает использовать проверочные метки.

### Frozen против fine-tuned transfer

Для переноса фиксируют определение объекта в исходной задаче, словарь, временную границу и цель обучения. Один числовой ID в разных системах может означать разные объекты; совпадение формы таблиц не гарантирует совместимости. Исходные метки из будущего относительно оценки новой задачи могут нарушать временной протокол, даже если набор называется независимым.

Замороженная таблица сохраняет исходное представление, но новая голова ограничена доступной в нём информацией. Дообучение адаптирует известные строки, но может ухудшить исходную геометрию или забыть старую структуру. Сравнение со случайной инициализацией и моделью только по свойствам объекта помогает отделить полезный перенос от дополнительной ёмкости. Качество на известных ID не доказывает качество для новых объектов.

В [работе об entity embeddings](https://arxiv.org/abs/1604.06737) предложено обучать representations категориальных variables и применять их дальше в моделях. Это источник метода, а не гарантия выигрыша на конкретном пользовательском dataset. Для implementation lookup/gradient rules сверяют с [API Embedding](https://docs.pytorch.org/docs/stable/generated/torch.nn.Embedding.html) установленной версии; числовые примеры этой главы определены формулами, без предположения о library defaults.

**Расширенная практика:** воспроизведите batch scatter-add и simultaneous step; проверьте gradient finite differences; посчитайте training memory; сравните distances до и после invertible transform при неизменных predictions. Для transfer опишите разрешённые source data, axes/mapping contract и known/new evaluation. Факт наличия этого задания не означает, что обучение или benchmark уже выполнены.

## Представления текста и изображений

Идея векторного представления применима не только к ID: кодировщик $f_\theta$ преобразует объект $x$ в вектор $z=f_\theta(x)\in\mathbb R^d$. Текстовый кодировщик может объединять состояния токенов, а кодировщик изображения — пространственную карту признаков. Геометрия зависит от цели предобучения, объединения, нормировки и области данных; одинаковая размерность разных моделей не делает их оси одинаковыми.

Замороженный кодировщик преобразует обучающие, проверочные и новые объекты одной фиксированной функцией. Это удобный базовый вариант, если его состояние независимо от проверочных меток, но различие областей данных может ограничить качество. Дообучение меняет параметры под новую задачу и может забыть исходную структуру. Кодировщик и обучаемые нормализацию или PCA располагают внутри разрешённой обучающей части либо используют независимо предобученные компоненты по объявленному протоколу.

Пример: $z_1=(1,1)$ и $z_2=(2,0)$ имеют cosine $1/\sqrt2\approx0.707$, но Euclidean distance $\sqrt2$. После L2-normalization Euclidean distance становится $\sqrt{2(1-0.707)}\approx0.765$. Значит, выбор cosine/Euclidean и normalization — часть feature contract. Проверяйте neighbors по известным labels/slices и downstream task; близость сама по себе не доказывает семантическое объяснение.

Для применения к новым объектам сохраняют версию модели, предварительную обработку, способ объединения, размерность, нормировку и правила некорректного или отсутствующего входа. Если после кодировщика используют PCA или другую обучаемую проекцию, её параметры тоже сохраняют и не пересчитывают по новым объектам.

**Схема курса:** raw object → saved preprocessing → frozen или fine-tuned encoder → pooling/normalization → versioned vector → nearest-neighbor или downstream estimator.

**Практика:** на одном split сравните frozen encoder + linear head, fine-tuning и simple feature baseline. Для каждого зафиксируйте training boundary; проверьте neighbor examples, unseen slice и transform parity на новых объектах. Отдельно укажите, какой вывод подтверждает validation metric и чего он не говорит о внутреннем смысле coordinates.

## Контроль и практика

1. Почему lookup не требует dense one-hot? **Ответ:** он сразу выбирает row, хотя математически эквивалентен соответствующему умножению.
2. Является ли embedding distance объективной semantic truth? **Ответ:** нет; она зависит от objective, parametrization и training data.
3. Можно ли сначала обучить embeddings на всех labels, затем CV бустинга? **Ответ:** это утечка; encoder является частью supervised pipeline.

**Практика:** повторите gradient step, затем обновите и embedding, и head одновременно, используя исходные gradients. Посчитайте weights плюс optimizer states для нескольких dimensions. Составьте transfer protocol с независимым source dataset и stable ID mapping.
