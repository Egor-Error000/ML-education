# Типы признаков: смысл, допустимые операции и контракт

**Уровень:** общее ядро.

**Предпосылки:** [Постановка задачи и паспорт данных](<../01-reliability/df-task.md>), [Split, cross-validation и утечки](<../01-reliability/df-split.md>).

**Учебный вопрос:** Почему одинаковый числовой тип может обозначать измерение, порядок или название?

## Что модель должна узнать из поля

**Признак** — представленная модели информация об объекте на момент предсказания. Тип данных в файле отвечает за хранение; смысл признака определяет допустимые операции. Число 3 может обозначать количество покупок, место в очереди или код страны. Разность количеств имеет смысл; место в очереди задаёт порядок, но не одинаковую разницу полезности; код страны позволяет проверить равенство, но не измерить расстояние между странами.

Выделяют числовые измерения и счётчики, **порядковые** категории с осмысленным отношением «раньше/позже» и **номинальные** категории, для которых осмысленно равенство. Это свойство задачи: оценки «низкий, средний, высокий» имеют порядок, но расстояние от низкого до среднего не обязано равняться расстоянию до высокого. Дата, координата, список значений, текст и изображение имеют дополнительные правила представления.

![Одно сохранённое число и три разных смысла поля](<../../оформление/course/feat-types.svg>)

На схеме три поля одинакового числового типа идут по разным ветвям: для количества рассматривают масштабы, для порядка — упорядоченные признаки, для города — словарь категорий. Разделение происходит по смыслу, а не по названию столбца или dtype.

## Ложный порядок на трёх городах

Пусть A, B, C закодированы числами 1, 2, 3 и линейная модель использует $f(c)=b+wc$. Её ответы на три города — $b+w$, $b+2w$, $b+3w$: разница A→B всегда равна разнице B→C. Если назначить те же коды в другом порядке, это ограничение будет связывать другие города. Географического смысла в такой зависимости нет.

Вместо числа можно создать три индикатора присутствия категории: A→(1,0,0), B→(0,1,0), C→(0,0,1). Линейная модель может назначить отдельный эффект каждому городу. Совместно с общим свободным перехватом коэффициенты не обязательно единственны; отождествление модели и её коэффициентов разбирается в [главе о категориях](<feat-categorical.md>).

Если же 3 — количество товаров, 4−3=1 действительно обозначает один дополнительный товар. Температуры в градусах связаны преобразованием $F=1.8C+32$, а при изменении кода страны аналогичная арифметика не описывает физическое изменение. Число с порядком не обещает линейной зависимости результата: её тоже нужно проверять.

## Контракт поля и преобразования

Для каждого поля запишите смысл, единицу, допустимый диапазон и тип отсутствия, источник, время появления и правило обработки неизвестного значения. Например, `age_years` — возраст в годах на дату решения, `country_code` — номинальный код, `event_time` — момент события с часовым поясом, `tags` — набор или последовательность в зависимости от задачи. Идентификатор пользователя может быть необходим для группового разбиения, даже если его не подают модели как число.

Преобразование также имеет состояние: словарь, обученную среднюю, порядок выходных столбцов и версию. Фиксированный перевод единиц не учится на данных; масштабирование по среднему сначала оценивают на обучающей части и затем повторяют с теми же параметрами. Для векторов из модели сохраняют версию модели, предобработку, способ получения общего вектора и нормировку: одинаковая размерность не делает два пространства совместимыми.

## Практика и проверка

Поменяйте коды городов местами. Проверка равенства сохранится при согласованном словаре; числовые разности изменятся. Для четырёх полей выше укажите доступное время, пропуски и допустимые операции. Сравните простую линейную модель с кодами города и индикаторами: какой класс зависимостей разрешён в каждом случае? Далее — [пропуски и неизвестные значения](<feat-missing.md>) и [кодировки категорий](<feat-categorical.md>).
