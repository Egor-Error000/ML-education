**Учебный вопрос:** Почему одинаковый dtype требует разных преобразований?

## От поля к признаку

**Признак** — информация, представленная модели для одного предсказания. Поле исходной таблицы ещё не определяет представление: число `3` может быть количеством покупок, кодом страны или номером месяца. Тип признака задаётся смыслом допустимых операций. Для количества осмысленны сумма и разность; для номинальной категории — равенство; для порядка — сравнение, но не обязательно одинаковое расстояние между соседями.

Различайте непрерывные измерения (continuous), счётчики (count), порядковые (ordinal) и номинальные (nominal) признаки. Дата, географическая координата, множество, текст и изображение требуют своих правил геометрии или агрегирования. `user_id` может быть ключом группировки для split (разбиение данных), но это не делает его полезным числовым входом. Удаление ID из inputs не устраняет зависимость записей одного пользователя.

## Вычисляемый пример ложного порядка

Пусть города закодированы как A=1, B=2, C=3. Линейная модель $f(x)=wx+b$ принудительно задаёт одинаковую разницу $w$ между A/B и B/C. Перестановка словаря C=1, A=2, B=3 меняет класс допустимых зависимостей между названиями. One-hot позволяет независимые коэффициенты городов; ordinal coding допустим, когда порядок действительно следует из задачи. Числовой dtype сам этого не доказывает.

Для температуры изменение единиц $F=1.8C+32$ имеет физический смысл. Для кода города операция «умножить ID на 1.8» такого смысла не имеет. Это различие определяет, какие преобразования стоит передавать scaler, а какие — словарю категорий.

## Контракт представления

Для поля сохраняют смысл, единицы, диапазон, допустимые пропуски, правило неизвестного значения, источник и момент доступности. После преобразования сохраняют порядок выходных столбцов, параметры fit и версию. Для embedding (векторное представление) дополнительно нужны checkpoint (сохранённое состояние модели), preprocessing, pooling (агрегирование состояний) и normalization (нормировка по выбранному правилу). Одинаковая размерность двух векторов не доказывает совместимость пространств.

Составьте контракт для `age_years`, `country_code`, `event_time`, `tags`: укажите значение missing, разрешённые операции, время доступности и представление. Ошибка — масштабировать коды стран совместно с возрастом только потому, что оба столбца имеют integer dtype.

## Проверка понимания

Объясните, какие операции останутся корректными после перестановки кодов категории. **Ответ:** сравнение на равенство сохранится при согласованном словаре; расстояния между числовыми кодами могут измениться. **Практика:** выпишите два представления каждого поля и выберите baseline (базовый вариант сравнения) по предполагаемому классу модели.
